# Part A — Complete lesson summary

## 1. What JSON is and why it matters

JSON means **JavaScript Object Notation**. Despite its name, it is language-independent. Python, Java, JavaScript, Go, Java, and almost every modern programming language can read and write it.

JSON is a lightweight, human-readable **data-interchange format**. Different applications use it to exchange structured data. Common uses include:

- Web API request and response bodies.
- Application configuration files.
- Service messages, logs, and message queues.
- Dataset and machine-learning experiment metadata.
- Model inference requests and responses.
- AI agent state and tool arguments.
- Structured output generated by an LLM.

CSV represents flat rows and columns. JSON can represent nested structures: an object can contain another object, an array, or any combination of JSON values.

Example:

```json
{
  "name": "Alice",
  "age": 30,
  "active": true
}
```

An **object** is a collection of key-value pairs. Keys are strings. An **array** is an ordered collection of values. A **field/value** may be a string, number, Boolean, null, object, or array.

## 2. JSON's six value types

| JSON type | Example | Python type after decoding |
|---|---|---|
| Object | `{"name": "Alice"}` | `dict` |
| Array | `["Python", "SQL"]` | `list` |
| String | `"Alice"` | `str` |
| Number | `42` or `3.14` | `int` or `float` |
| Boolean | `true`, `false` | `True`, `False` |
| Null | `null` | `None` |

Objects and arrays can nest to arbitrary depth:

```json
{
  "customer": {
    "id": 1001,
    "orders": [
      {"id": 5001, "amount": 100.5},
      {"id": 5002, "amount": 42.0}
    ]
  }
}
```

After decoding, normal Python indexing applies:

```python
city = data["customer"]["profile"]["address"]["city"]
amount = data["customer"]["orders"][0]["amount"]
```

The first example requires those keys to exist. Missing keys raise `KeyError`; an unexpected type at an intermediate level may raise `AttributeError` or `TypeError`.

## 3. JSON syntax is not Python syntax

Standard JSON rules:

1. Strings and object keys use double quotes only.
2. A colon separates a key and value.
3. Commas separate object pairs or array elements.
4. No trailing comma is allowed.
5. Boolean and null tokens are lowercase: `true`, `false`, `null`.
6. Numbers are unquoted; no leading zeros (except `0`), leading `+`, `.5`, or `1.`.
7. Valid escapes include `\"`, `\\`, `\/`, `\b`, `\f`, `\n`, `\r`, `\t`, and `\uXXXX`.
8. Objects use `{}`; arrays use `[]`.
9. JSON has no comments.

Invalid JSON:

```json
{'name': 'Alice'}
```

It uses single quotes. Another invalid example:

```json
{"active": True, "items": ["a", "b",]}
```

It has Python's `True` and a trailing comma. The valid version is `{"active": true, "items": ["a", "b"]}`.

Compare Python and JSON:

| Python | JSON |
|---|---|
| `True` / `False` | `true` / `false` |
| `None` | `null` |
| Single or double quoted strings | Double-quoted strings only |
| Trailing commas allowed in literals | Trailing commas forbidden |
| Comments supported in Python source | No comments in JSON |

A Python dictionary is **not** JSON. A dictionary is an in-memory Python object; JSON is text. Converting between them is an explicit operation.

## 4. Serialization and deserialization

**Serialization** converts a Python object into JSON text, suitable for storage or transfer. **Deserialization** parses JSON text into Python objects.

```python
import json

data = {"name": "Alice", "age": 30}
text = json.dumps(data)
print(text)
print(type(text))       # str

recovered = json.loads(text)
print(recovered)
print(type(recovered))  # dict
```

The direction is important:

```text
Python object --json.dumps()--> JSON string
JSON string   --json.loads()--> Python object
```

Serialization is used in APIs, caches, configuration, databases, distributed services, queues, and ML/AI metadata.

## 5. The four essential JSON functions

| Function | Input | Result |
|---|---|---|
| `json.dumps(obj)` | Python object | JSON string (`str`) |
| `json.loads(text)` | JSON string | Python object |
| `json.dump(obj, file)` | Python object + open file | Writes JSON; returns `None` |
| `json.load(file)` | Open file object | Python object |

The trailing `s` means **string**. `loads` reads from a string; `dumps` creates a string. The versions without `s` work with an already-open file object.

```python
with open("config.json", "w", encoding="utf-8") as f:
    json.dump({"name": "Alice", "age": 30}, f, indent=2)

with open("config.json", "r", encoding="utf-8") as f:
    config = json.load(f)
```

Use explicit `encoding="utf-8"`. Unlike CSV, JSON file handling does not require `newline=""`. `json.dump()` expects an open writable file object; `json.load()` expects an open readable file object. `json.loads()` accepts `str`, `bytes`, or `bytearray`, but explicitly decoding bytes with a known encoding is clearer.

## 6. Important `dumps`/`dump` options

- `skipkeys=False`: unsupported dictionary key types raise `TypeError`. `True` silently drops those key-value pairs, which can cause data loss.
- `ensure_ascii=True`: non-ASCII characters are emitted as `\uXXXX`. Set `False` to display characters directly, such as Bengali text; write the file using UTF-8.
- `check_circular=True`: detects containers that refer to themselves and raises `ValueError`. Disabling it risks runaway recursion.
- `allow_nan=True`: Python's encoder permits `NaN`, `Infinity`, and `-Infinity`, although these are not standard JSON. Use `allow_nan=False` for strict output; it raises `ValueError`.
- `cls`: supplies a custom `JSONEncoder` subclass.
- `indent`: `None` produces compact one-line output; `2` or `4` produces readable indentation.
- `separators`: controls item and key separators. `(",", ":")` removes optional whitespace for compact output.
- `default`: a function to convert otherwise unsupported Python objects.
- `sort_keys=True`: sorts object keys, making output stable for diffs and tests.

Default separators are `(", ", ": ")` for compact output and `(",", ": ")` when `indent` is set.

`sort_keys=True` improves determinism, but is not full canonical JSON: values such as `1` and `1.0` still serialize differently, and floating-point representations may differ.

## 7. `loads`/`load` options and decoder hooks

The main `json.loads()` parameters are:

- `cls`: custom decoder class.
- `object_hook`: called for every decoded object, innermost first; receives a dictionary and returns the replacement value.
- `object_pairs_hook`: receives ordered key-value pairs before dictionary construction. It can detect duplicate keys. If both hooks are supplied, `object_pairs_hook` takes precedence.
- `parse_int`: converts integer-looking JSON tokens; receives the original digit text.
- `parse_float`: converts decimal/exponent JSON tokens; commonly set to `Decimal`.
- `parse_constant`: controls non-standard `NaN`, `Infinity`, and `-Infinity` tokens.

Example:

```python
text = '{"count": 3, "ratio": 0.5}'
data = json.loads(text, parse_int=str, parse_float=str)
# {'count': '3', 'ratio': '0.5'}
```

Duplicate-key detection:

```python
def reject_duplicate_keys(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"Duplicate key: {key}")
        result[key] = value
    return result

data = json.loads('{"id": 1, "id": 2}',
                  object_pairs_hook=reject_duplicate_keys)
```

Without this hook, Python normally keeps the last duplicate key.

## 8. JSON and Python type mapping

- JSON object ↔ Python `dict`.
- JSON array ↔ Python `list`.
- JSON string ↔ Python `str`.
- JSON integer token ↔ Python `int`.
- JSON decimal/exponent token ↔ Python `float` by default.
- JSON Boolean ↔ Python `bool`.
- JSON null ↔ Python `None`.

A Python tuple serializes as a JSON array and decodes as a list; the original tuple identity is lost. A set is not serializable by default. Arbitrary class instances are not serializable by default. Python dictionary keys may be converted: `int`, `float`, `bool`, and `None` keys become strings; unsupported key types raise unless `skipkeys=True`.

Types without a direct default mapping include `set`, `bytes`, `datetime`, `date`, `time`, `Decimal`, `Path`, `UUID`, ordinary `Enum`, and custom class instances.

## 9. Custom serialization

A direct attempt to serialize `datetime`, `Decimal`, `Path`, or a custom object raises `TypeError`. Use a deliberate conversion rule.

```python
from datetime import datetime

def serialize_value(value):
    if isinstance(value, datetime):
        return value.isoformat()
    raise TypeError(f"Cannot serialize {type(value).__name__}")

text = json.dumps({"created_at": datetime.now()},
                  default=serialize_value)
```

`default=str` is a convenient shortcut, useful for debugging/logging, but it may produce lossy or non-reconstructable text. For persistent data, define explicit rules and matching decode logic.

For repeated rules, subclass `json.JSONEncoder`:

```python
from datetime import datetime
from decimal import Decimal
from uuid import UUID

class CustomEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, datetime):
            return obj.isoformat()
        if isinstance(obj, Decimal):
            return str(obj)
        if isinstance(obj, UUID):
            return str(obj)
        return super().default(obj)

text = json.dumps(data, cls=CustomEncoder)
```

Override `default()` and call `super().default(obj)` for unsupported types. `encode()` returns a complete string; `iterencode()` yields string chunks and is used by `json.dump()`.

## 10. Decoder classes and hooks

`json.JSONDecoder` is used internally by `json.loads()`. Direct use is uncommon; keyword hooks usually suffice. `.decode(text)` requires exactly one complete JSON value with no trailing non-whitespace content. `.raw_decode(text, idx=0)` parses one value starting at an index and returns `(object, end_index)`, allowing trailing content to be handled separately.

`object_hook` can convert a decoded object into a class instance:

```python
def customer_hook(obj):
    if "id" in obj and "name" in obj:
        return Customer(obj["id"], obj["name"])
    return obj

customer = json.loads(text, object_hook=customer_hook)
```

It runs for every object, innermost first. Therefore the hook must handle unrelated object shapes safely.

`parse_int=str` replaces normal integer conversion. `parse_float=Decimal` preserves exact decimal digits when parsing JSON number tokens. It does not affect quoted numeric strings. `parse_constant` can reject non-standard tokens:

```python
def reject_constant(token):
    raise ValueError(f"Non-standard JSON constant: {token}")

json.loads('{"x": NaN}', parse_constant=reject_constant)
```

## 11. Decimal, datetime, Path, Enum, and dataclasses

**Decimal:** `Decimal` is not directly JSON-serializable. For exact financial values, serialize as a string and reconstruct with `Decimal(text)`. Never convert through `float()`. `parse_float=Decimal` applies only when the JSON contains a number token such as `19.99`, not a quoted string such as `"19.99"`.

**Datetime:** serialize with `.isoformat()` and reconstruct with `datetime.fromisoformat()`. ISO 8601 text can preserve timezone offsets when the datetime is timezone-aware.

**Path:** serialize using `str(path)`. Decide whether the contract stores an absolute path, relative path, URI, or logical identifier. Absolute paths often fail on another machine; relative paths need a known base.

**Enum:** ordinary Enum members are not directly serializable. Choose `.value` or `.name` deliberately and reconstruct using the matching form, e.g. `Status("active")`.

**Dataclasses:** `dataclasses.asdict()` converts fields to a dictionary and recursively handles nested dataclasses:

```python
from dataclasses import dataclass, asdict

@dataclass
class User:
    id: int
    name: str

text = json.dumps(asdict(User(1, "Alice")))
```

`asdict()` does not convert nested `datetime`, `Decimal`, `Path`, Enum, or arbitrary non-dataclass objects. Combine it with `default=` or a custom encoder. Reconstruct a domain object with a validating factory function or a carefully designed `object_hook`.

## 12. Numeric and Unicode edge cases

Python's default encoder accepts `NaN` and infinities, even though strict JSON does not. Use `allow_nan=False` when interoperability matters. On decoding, use `parse_constant` to reject those tokens.

With `ensure_ascii=True`, Bengali or other non-ASCII characters are represented using Unicode escapes but retain their meaning. With `ensure_ascii=False`, actual characters appear in output; use UTF-8 when writing.

## 13. Errors and validation

`json.JSONDecodeError` is a subclass of `ValueError`. Useful attributes are `.msg`, `.doc`, `.pos`, `.lineno`, and `.colno`. Catch it specifically and preserve its context.

**Syntax validation is not schema validation.** `json.loads('{"age": "hello"}')` succeeds because the text is valid JSON. The value may still be wrong for the application.

A schema is your program's explicit contract describing required/optional fields, types, constraints, nested shapes, and version. Validate immediately after parsing and before business logic. Remember that `bool` is a subclass of `int`; reject booleans explicitly when a field must be an integer.

```python
def validate_config(data):
    if not isinstance(data, dict):
        raise ValueError("Config must be an object")
    if "version" not in data:
        raise ValueError("Missing version")
    value = data["version"]
    if isinstance(value, bool) or not isinstance(value, int):
        raise ValueError("version must be an integer")
```

Safe access: `data["name"]` raises `KeyError` when absent; `data.get("name")` returns `None`; `data.get("name", "N/A")` returns a default. For nested structures, use defensive `.get()` calls or a helper that checks each level is a dictionary.

## 14. Configuration, API payloads, and AI/ML

A config loader should: read UTF-8 text, parse JSON, catch syntax errors, validate structure and types, apply defaults to optional fields, check schema version, and return a clean internal representation. A shallow dictionary merge does not recursively merge nested configuration objects.

An API request body is parsed, validated, and then passed to application logic. A response is built as Python objects and serialized before sending. This lesson teaches the JSON part, not a complete HTTP server/client.

JSON appears in model metadata, inference payloads, dataset metadata, experiment configurations, evaluation results, agent state, tool arguments, and structured LLM output.

Asking an LLM for JSON gives predictable fields rather than prose, but **valid JSON is not necessarily correct JSON**. It may contain wrong values, missing fields, wrong types, or unsafe instructions. Always parse, validate schema and business rules, and only then act.

## 15. Security and resource limits

Never use `eval()` to parse JSON. `eval()` executes arbitrary Python code; `json.loads()` parses a restricted data format and does not execute arbitrary input code (unless you deliberately add custom hooks that perform unsafe actions).

Untrusted JSON can contain:
- Excessively deep nesting.
- Huge strings or arrays.
- Extremely long numbers.
- Objects with enormous numbers of keys.
- Unexpected shapes.

Set sensible payload-size and nesting limits at application boundaries. Parsing success does not make content safe.

## 16. Large JSON vs. JSON Lines

A single JSON document is one complete nested value. `json.load()`/`loads()` must parse the complete structure, so the full parsed structure is held in memory. For moderate config/API/metadata documents, this is appropriate.

For large record collections, **JSON Lines / NDJSON** stores one independent JSON value per line:

```text
{"id": 1, "name": "Alice"}
{"id": 2, "name": "Bob"}
```

The whole file is not one JSON document. Each line is parsed separately, enabling streaming:

```python
def read_json_lines(path):
    with path.open("r", encoding="utf-8") as f:
        for line in f:
            line = line.strip()
            if line:
                yield json.loads(line)

def write_json_lines(path, records):
    with path.open("w", encoding="utf-8") as f:
        for record in records:
            f.write(json.dumps(record))
            f.write("\n")
```

Memory depends on the current record and retained state, not the total number of records. Catch `JSONDecodeError` at each line boundary if malformed records should be quarantined while processing continues. JSON Lines is useful for logs and large pipelines.

## 17. Safe atomic updates and schema versioning

Overwriting an important JSON file directly risks leaving a truncated, invalid file if the process stops mid-write. A basic write-then-replace pattern is:

```python
def save_json_safely(path, data):
    temporary_path = path.with_name(path.name + ".tmp")
    temporary_path.write_text(json.dumps(data, indent=2), encoding="utf-8")
    temporary_path.replace(path)
```

The temporary file is fully written before replacing the target. Replacement is typically atomic on the same filesystem, but this is not an unconditional power-loss durability guarantee. Concurrent writers need unique temporary names and coordination.

Schemas evolve. Store `schema_version`, reject unsupported versions, and explicitly migrate older supported versions to the current shape. Never silently interpret an unknown schema.

## 18. Performance, reusable utilities, and testing

Serialization/deserialization cost grows with data size. Decoded JSON creates Python objects with memory overhead. Indentation increases output size; sorting adds work. Avoid repeated conversions; measure before optimizing. Use JSON Lines only when size justifies it.

Reusable functions separate pure conversion from filesystem I/O:

```python
def load_json(path):
    return json.loads(path.read_text(encoding="utf-8"))

def save_json(path, data, indent=2):
    path.write_text(
        json.dumps(data, indent=indent, ensure_ascii=False, sort_keys=True),
        encoding="utf-8"
    )

def serialize_config(config):
    return json.dumps(config, indent=2, sort_keys=True)
```

The serialization function does not touch disk and is independently testable. Low-level utilities generally let errors propagate so callers can decide how to recover.

Use pytest's `tmp_path` for isolated file tests. Test valid/invalid JSON, empty object/array, missing keys, null, wrong types, Unicode, special characters, deterministic output, custom-type round trips, JSON Lines, and unsupported schema versions. A round-trip test must compare logically reconstructed objects using matching decode rules: tuples become lists; custom types need explicit reconstruction; Decimal strings need `Decimal(text)`.

## 19. Debugging workflow and common mistakes

Debug in this order:
1. Inspect raw JSON text.
2. Use `repr()` to reveal invisible characters.
3. Check double quotes.
4. Check missing, extra, or trailing commas.
5. Match braces and brackets.
6. Check encoding.
7. Inspect `JSONDecodeError` line, column, and position.
8. Reproduce the smallest failing example.
9. Print `type(data)` and dictionary keys.
10. Verify the exact code path with a standalone script or test.

Common mistakes: confusing JSON text with a dict; using Python `True`/`None`; single quotes; trailing commas; indexing a string before parsing; passing a dict to `loads`; passing a string to `.get()`; confusing load/loads and dump/dumps; omitting UTF-8; catching broad `Exception` and returning `{}`; assuming parse success means schema correctness; using `eval`; blindly using `default=str`; loading huge documents unnecessarily; ignoring versioning; trusting LLM JSON without validation.

## 20. End-to-end examples and advanced API reference

**Configuration loader:** read JSON, catch `JSONDecodeError`, validate root/app/name/version/features, reject bool for integer version, apply defaults, and return a flattened internal configuration. Use an application-specific exception such as `ConfigError`.

**Experiment metadata manager:** a dataclass may contain `UUID`, `datetime`, `Path`, model name, and schema version. `asdict()` handles dataclass fields; a custom encoder converts UUID to string, datetime to ISO format, and Path to string. Save deterministic JSON to a temporary file and replace the target. On load, validate schema version and reconstruct each type using `UUID(...)`, `datetime.fromisoformat(...)`, and `Path(...)`. A version check alone is not full payload validation.

Advanced public API reference:
- Functions: `dumps`, `loads`, `dump`, `load`, `detect_encoding`.
- Classes: `JSONEncoder` (`default`, `encode`, `iterencode`), `JSONDecoder` (`decode`, `raw_decode`), `JSONDecodeError` (`msg`, `doc`, `pos`, `lineno`, `colno`).
- Hooks: `object_hook`, `object_pairs_hook`, `parse_int`, `parse_float`, `parse_constant`, `default`, `cls`.
- Options: `skipkeys`, `ensure_ascii`, `check_circular`, `allow_nan`, `indent`, `separators`, `sort_keys`.

The internal mental model is: encoder walks Python values and produces JSON text; decoder parses JSON tokens and produces Python values. **Parsing produces data; validation earns trust.**

## 21. Four mini-project specifications

1. **JSON Inspector:** load an unfamiliar file; report top-level type, object keys, nesting depth, and precise syntax errors. Must support top-level object, array, string, or number; test empty structures and malformed files. Extension: report key value types without printing huge nested values.

## Level 1 — Foundation

### 1. Convert a dictionary to JSON text

```python
data = {"name": "Alice", "age": 30}
text = json.dumps(data)
print(text)
```

`data` is a Python dictionary. `dumps()` serializes it into a string. `print()` displays the JSON text.

### 2. Convert JSON text to a dictionary

```python
text = '{"name": "Alice", "age": 30}'
data = json.loads(text)
print(data["name"])
```

The variable `text` contains JSON syntax. `loads()` parses it into a dictionary. The final line accesses the `name` value.

### 3. Write a dictionary to a JSON file

```python
data = {"name": "Alice", "active": True}
with open("user.json", "w", encoding="utf-8") as f:
    json.dump(data, f, indent=2)
```

Open/create the file in write mode with UTF-8. The context manager closes it. `dump()` writes the dictionary as readable JSON.

### 4. Read the JSON file back

```python
with open("user.json", "r", encoding="utf-8") as f:
    data = json.load(f)
print(data)
```

Open the file for reading. `load()` parses the file object into Python values. Print the resulting dictionary.

### 5. Access a nested value

```python
text = '{"customer": {"profile": {"city": "Kolkata"}}}'
data = json.loads(text)
city = data["customer"]["profile"]["city"]
print(city)
```

Parse the JSON first. Each bracket accesses one nested dictionary. The final value is `"Kolkata"`.

## Level 2 — Practical

### 6. Validate two required keys

```python
def validate_user(data):
    if not isinstance(data, dict):
        raise ValueError("User data must be an object")
    required = {"id", "name"}
    missing = required - data.keys()
    if missing:
        raise ValueError(f"Missing fields: {sorted(missing)}")
```

Reject non-dictionaries. Define required keys. Set subtraction finds missing keys. Raise a useful error only when the set is non-empty.

### 7. Safely read a missing key

```python
status = data.get("status", "unknown")
```

`.get()` returns the field if present; otherwise it returns `"unknown"` without raising `KeyError`.

### 8. Re-raise JSON syntax errors with application context

```python
class PayloadError(Exception):
    pass

def parse_payload(text, source_name):
    try:
        return json.loads(text)
    except json.JSONDecodeError as error:
        raise PayloadError(
            f"{source_name}: invalid JSON at line {error.lineno}, "
            f"column {error.colno}: {error.msg}"
        ) from error
```

## Level 3 — Engineering

### 12. Serialize and reconstruct `datetime`

```python
from datetime import datetime

def encode_datetime(value):
    if isinstance(value, datetime):
        return value.isoformat()
    raise TypeError(f"Unsupported type: {type(value).__name__}")

def decode_datetime(text):
    return datetime.fromisoformat(text)

original = datetime(2026, 9, 21, 14, 0)
text = json.dumps({"created_at": original}, default=encode_datetime)
loaded = json.loads(text)
recovered = decode_datetime(loaded["created_at"])
assert recovered == original
```

The encoder converts datetime to ISO text and rejects unknown types. JSON stores a string. The decoder reconstructs datetime. The assertion checks logical equality.

## Level 4 — Advanced

### 18. Custom encoder for three types

```python
from pathlib import Path
from uuid import UUID
from datetime import datetime

class AppEncoder(json.JSONEncoder):
    def default(self, obj):
        if isinstance(obj, datetime):
            return obj.isoformat()
        if isinstance(obj, Path):
            return str(obj)
        if isinstance(obj, UUID):
            return str(obj)
        return super().default(obj)

text = json.dumps(data, cls=AppEncoder)
```

The encoder handles three non-native types. The final `super()` call preserves normal `TypeError` behavior for unsupported objects.

### 19. Convert matching objects with `object_hook`

```python
class User:
    def __init__(self, user_id, name):
        self.user_id = user_id
        self.name = name

def user_hook(obj):
    if "user_id" in obj and "name" in obj:
        return User(obj["user_id"], obj["name"])
    return obj

result = json.loads(text, object_hook=user_hook)
```

The hook receives every object. Matching objects become `User` instances; unrelated dictionaries remain dictionaries. Inner objects are processed before outer objects.

### 20. Reject duplicate JSON keys

```python
def unique_object(pairs):
    result = {}
    for key, value in pairs:
        if key in result:
            raise ValueError(f"Duplicate key: {key}")
        result[key] = value
    return result

data = json.loads(text, object_pairs_hook=unique_object)
```

Pairs retain duplicates before dictionary construction. Check each key before insertion. Raise instead of silently accepting the last value.

### 21. Demonstrate all three parse hooks

```python
from decimal import Decimal

def parse_special(token):
    raise ValueError(f"Forbidden constant: {token}")

data = json.loads(
    text,
    parse_int=str,
    parse_float=Decimal,

```

### 22. Stream JSON Lines and transform records

```python
def transform_jsonl(source, target):
    with source.open("r", encoding="utf-8") as src, \
         target.open("w", encoding="utf-8") as dst:
        for line_number, line in enumerate(src, start=1):
            if not line.strip():
                continue
            try:
                record = json.loads(line)
                if not isinstance(record, dict):
                    raise ValueError("record must be an object")
                record["processed"] = True
                dst.write(json.dumps(record) + "\n")
            except (json.JSONDecodeError, ValueError) as error:
                # In a full pipeline, write this line and reason to a reject file.
                print(f"Line {line_number}: {error}")
```

Read one line at a time. Skip blank lines. Parse each line independently and require an object. Transform and write immediately. Report errors with line numbers; production code should quarantine rejected records in a separate file.

### 23. Safe atomic JSON update and failure test

```python
def save_json_safely(path, data, writer=None):
    temporary = path.with_name(path.name + ".tmp")
    write = writer or (lambda p, value: p.write_text(
        json.dumps(value, indent=2), encoding="utf-8"
    ))
    write(temporary, data)
    temporary.replace(path)
```

Write the temporary file first. Replace the target only after the writer completes. If writing raises, replacement is never reached and the original remains.

```python
def test_failed_write_preserves_original(tmp_path):
    target = tmp_path / "config.json"
    target.write_text('{"old": true}', encoding="utf-8")

    def failing_writer(path, data):
        path.write_text("{partial", encoding="utf-8")
        raise OSError("simulated failure")

    with pytest.raises(OSError):
        save_json_safely(target, {"new": True}, writer=failing_writer)

    assert target.read_text(encoding="utf-8") == '{"old": true}'
```

The test creates an original file, simulates a partial temporary write followed by failure, and confirms the target content is unchanged.

# Part D — All 14 debugging exercises

1. **Single quotes:** JSON requires double quotes. Replace `"{'name': 'Alice'}"` with `'{"name": "Alice"}'`.
2. **Python `True`:** JSON Boolean is lowercase `true`; change `True` to `true`.
3. **Trailing comma:** remove the comma after the final array item.
4. **`load` vs `loads`:** a string requires `json.loads(text)`. `json.load()` expects an open file object.
5. **`dump` vs `dumps`:** to write to an open file use `json.dump(data, f)`. `dumps()` returns a string and does not take the file as its second positional argument.
6. **File encoding:** specify `encoding="utf-8"` in `open()`.
7. **Unicode output:** escaped Bengali is still correct JSON. Use `ensure_ascii=False` only if direct characters are desired; write UTF-8.
8. **UUID unsupported:** convert with `str(uuid_value)` or supply a deliberate `default=`/encoder rule.
9. **Circular reference:** JSON is a finite tree and cannot represent an object pointing back to itself. Store an identifier/reference instead of the cyclic object.
10. **Custom encoder missing fallback:** without `return super().default(obj)`, the method returns `None` for an unrecognized object, which may silently serialize it as `null`. Add the fallback.
11. **Unsafe `object_hook`:** the innermost `{"x": 1}` lacks `"name"` and causes `KeyError`. Check required keys; return unmatched dictionaries unchanged.
12. **Decimal through float:** converting `Decimal` to float may lose precision. Serialize the exact `str(decimal)` and reconstruct with `Decimal(text)`.
13. **Wrong datetime format:** `"%Y-%m-%d"` cannot parse the full ISO timestamp. Use `datetime.fromisoformat(text)`.
14. **Broad exception swallowed:** `except Exception: return {}` hides malformed JSON, file errors, and programming bugs, and skips schema validation. Catch `JSONDecodeError` specifically, then validate parsed data separately.

# Part E — All 12 knowledge-check answers

1. Parsing checks syntax; correctness and safety require schema, type, and business-rule validation.
2. JSON has no tuple type. Tuples serialize as arrays and every array decodes as a list.
3. First output preserves insertion order: `{"b": 1, "a": 2}`. Second sorts keys: `{"a": 2, "b": 1}`.
4. `x` becomes `int` (`1`); `y` becomes `float` (`1.0`).
5. Use `json.loads()` for JSON text already in memory.
6. Use `object_pairs_hook` to inspect all key occurrences before dictionary construction.
7. Likely a missing comma between items or a trailing/extra comma.
8. Decimal has no built-in JSON mapping. A convenient but potentially lossy approach is `default=str`; the deliberate approach is an explicit Decimal-to-string rule and `Decimal(text)` reconstruction. Do not use float.
9. `{"age": "hello"}` is syntactically valid JSON. It violates an application expectation that age be numeric.
10. `eval()` executes arbitrary Python code. `json.loads()` parses a data format without evaluating arbitrary expressions.
11. One JSON document is a single nested value whose complete structure must be parsed. JSON Lines makes each line an independent JSON value.
12. A malformed line may be an isolated bad record. Quarantining it preserves valid records and reports exactly which line failed.

# Part F — Interview revision

1. **JSON:** language-independent, human-readable structured data interchange format.
2. **JSON vs dict:** JSON is text; a dict is a Python in-memory object.
3. **Serialization/deserialization:** Python object to JSON text, and JSON text to Python object.
4. **`dump` vs `dumps`:** write to file object vs return a JSON string.
5. **`load` vs `loads`:** parse file object vs parse string.
6. **Lowercase tokens:** JSON syntax is language-independent and uses `true`, `false`, `null`.
7. **`JSONDecodeError`:** malformed JSON error with message, document, position, line, and column.
8. **`ensure_ascii`:** controls escaping of non-ASCII characters.
9. **`sort_keys`:** sorts keys for stable diffs and tests.
10. **`default=`:** converts unsupported Python types; `default=str` may lose reconstructable type information.
11. **`JSONEncoder`:** serializer class; subclass when custom rules are reused.
12. **`JSONDecoder`:** parser class; direct use is uncommon except advanced decoding such as `raw_decode`.
13. **`object_hook`:** transforms each decoded dictionary, innermost first.
14. **`object_pairs_hook`:** receives ordered pairs before dict creation and can detect duplicate keys.
15. **`parse_float`:** controls decimal-token conversion; `Decimal` preserves exact decimal digits.
16. **Decimal vs float:** Decimal avoids binary floating-point representation error for money.
17. **`check_circular`:** detects cyclic Python containers that JSON cannot represent.
18. **`allow_nan`:** controls non-standard NaN/infinity output.
19. **Schema validation:** checks required fields, types, constraints, and nested shape after parsing.
20. **Datetime:** encode with `.isoformat()` and decode with `datetime.fromisoformat()`.
21. **Dataclass with custom fields:** use `asdict()` plus `default=` or a custom encoder for non-native fields.
22. **Huge JSON:** use JSON Lines for independently parseable records; use incremental third-party parsing only when a single huge JSON document must be handled.
23. **NDJSON:** one independent JSON value per line; enables streaming.
24. **Production ingestion:** parse, validate, convert, apply rules, route valid/rejected records, report metrics, and test.
25. **AI-generated JSON:** parse, validate schema and business rules, and treat it as untrusted before taking action.
26. **Old config KeyError:** schema changed; add explicit schema versioning and migrations.
27. **Key-order test mismatch:** serialize with `sort_keys=True`, or compare parsed objects for logical equality.
28. **Numbers sometimes strings:** external JSON is not guaranteed to follow your assumptions; validate types and explicitly convert only if the data contract allows it.
