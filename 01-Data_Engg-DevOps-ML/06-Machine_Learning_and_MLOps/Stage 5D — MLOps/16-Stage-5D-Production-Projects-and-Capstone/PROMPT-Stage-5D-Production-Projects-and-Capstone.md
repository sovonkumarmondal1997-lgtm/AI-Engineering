- **The evidence-label convention (reused from `../09-…`, restated once).** Every statement about a system's behaviour carries exactly one label: **`MEASURED`**, **`SIMULATED`**, **`DOCUMENTED`**, or **`NOT ASSESSED`** (definitions as in `../09-…` Unit 0). **A claim, figure, or verdict without a label is a defect. Planted-estate results are `SIMULATED` or `MEASURED (synthetic estate, this machine)` — never statements about real systems.**
- **The evidence-pack convention (EPC; defined once; a course convention).** **Every capstone ships an *evidence pack*: a folder `evidence/` with an `index.json` listing, for every claim the dossier and rubric self-assessment make, an *evidence id*, the *claim text*, the *artifact path(s)* and their *SHA-256*, the *command that regenerates it*, the *evidence label*, the *seed(s)*, the *environment fingerprint* (Python and library versions, OS family, CPU count — no hostnames), the *determinism level* at which regeneration reproduces it (`../06-…`), the *logical time* of production, and *the rubric criterion ids it supports*. `prodcap evidence --verify` re-runs the regeneration commands in a scratch directory and compares hashes at the stated level; a claim with no evidence id, a missing artifact, or a hash that does not reproduce is a defect. Screenshots are never primary evidence.**
- **The clean-clone convention (CCC; defined once).** **A capstone must build and verify from a *clean clone* in a fresh virtual environment with only pinned dependencies and no network: `git clone` → `python -m venv` → `pip install -r requirements.lock` (offline editable-install note of `../02-…`) → `prodcap verify --quick` (passes within a stated time budget `[ASSUMPTION]`, within the disk cap, with no optional lane) → `prodcap verify --full` (the complete campaign, documented duration) → `prodcap evidence --verify`. No hidden state, no files outside the repository and a declared scratch directory, no reliance on the learner's home directory, no wall-clock or network dependence.**
- **The integration-contract convention (ICC; defined once; a course convention).** **Every interface *between* modules' artifacts is a *contract* with a *schema* (strict, versioned), a *producer test* (the producer emits conforming artifacts), a *consumer test* (the consumer rejects non-conforming input safely and handles conforming input), and a *compatibility test* (a planted older/newer version is classified by the contract-compatibility checker of `../02-…`/`../09-…`). The module names ten contracts the capstones exercise: **C1** model package manifest ↔ serving loader (verification before load, signature/schema compatibility); **C2** prediction log ↔ label join (keys, clocks, completeness); **C3** monitoring-signal record ↔ retraining policy (signal schema, evidence ids, reference hash); **C4** evidence bundle ↔ gate engine (hash binding, verdict); **C5** run record ↔ lineage and registry (parent, cut, config, seed); **C6** router configuration ↔ cache keys and propensity log (arm isolation); **C7** degradation rung ↔ SLI accounting and response disclosure; **C8** ADR assumption ↔ assumption monitor (break-even signal); **C9** card claim ↔ evidence hash (staleness binding); **C10** audit event ↔ decision reconstruction (decision id → model, features, threshold, approvals). The *contract coverage* of a capstone is the fraction of its inter-module interfaces with all three tests.**
- **The game-day convention (GDC; defined once; a course convention).** **A *game day* is a scripted fault-injection campaign run on the capstone's system on the virtual clock: each scenario states the *injected fault* (and when), the *expected detection* (which signal, by when), the *expected response* (which runbook step, which automation, which degradation rung), the *expected recovery* (the state and time to reach it), the *safety limits* (what must never happen — for example, a wrong model promoted, data lost, a secret leaked), and the *measured outcome*; the pass criteria are written before the run; results are `SIMULATED`/`MEASURED (synthetic estate)` with intervals where stochastic; a game day that was not executed is not evidence.**
- **The honest-scope convention (HSC; defined once).** **Every capstone ends with a *`NOT ASSESSED` register*: everything a real production deployment would require that this capstone did not exercise (real traffic and scale, real cloud, real data and privacy obligations, real legal and compliance review, real adversaries, accessibility of real user interfaces, organisational processes) — listed explicitly, never counted as passed. The dossier's headline claims are phrased "on this synthetic estate, on this machine, for these scenarios".**
- **The no-leak convention (restated from the module projects).** **Detectors, policies, evaluators, and reviewers-in-code never read the planted-truth manifest or the simulators' hidden ground truth except through the same observable channels a real system has; a guard test proves it.**

8. **Inter-rater agreement.** The weighted Cohen's kappa for ordinal level scores, `κ_w = 1 − Σ w_ij p_ij / Σ w_ij p_i· p_·j` with quadratic disagreement weights `w_ij = (i − j)²/(k − 1)²` — **derived and verified on small examples by enumeration and against a SciPy/scikit-learn computation**; the **kappa thresholds in the literature are conventions, not standards (`JUDGEMENT`)**; the **small-`n` caution** (with ~40 criteria the interval on `κ_w` is wide — report it by bootstrap); the **calibration exercise**: both raters score the *flawed reference* capstone and compare; disagreements are discussed and the rubric descriptors clarified (a *rubric defect list*); reviewer-recall on the planted flaws as a reviewer-calibration measure (counts with Wilson intervals, caution at small `n`).
