- **The run-record convention (defined once; used identically everywhere; a course convention).** A **run** is one execution of a training or evaluation procedure and has: **identity** (`experiment`, `run_id`, optional `parent_run_id`, human name); **status** (`running`, `finished`, `failed`, `killed` — **a run that is `running` beyond a stated heartbeat timeout is reported as *stale*, never silently left**); **timing** (start and end from an injected clock); **parameters** (the *inputs that define the run*: **immutable once logged — re-logging a different value is an error, re-logging the same value is a no-op**); **metrics** (named numeric series `(name, step, timestamp, value)` — **append-only; the final value is a convention stated per metric, not the last write by accident**); **tags** (mutable labels, never used for facts that define the run); **artifacts** (files stored by **content hash**, with sizes and media types); and the **captured provenance fields of the run tuple**: `code` (commit id, **a dirty-tree flag and a hash of the uncommitted diff**), `data` (snapshot/manifest ids and logical dataset hashes from Module 03), `config` (the canonical config hash from Module 02), `environment` (a fingerprint from `env_check` plus the resolved dependency list), `seeds` (the root seed and named spawn keys), and the `data_interval` and orchestrator `run_id` when launched by a workflow. **A run record is *complete* iff every captured field is present or explicitly recorded as `unavailable` with a reason.** **Every run is recorded — failed and killed runs included — and every experiment report states the total run count `k`.**
- **The model-package convention (defined once; a course convention).** A **model package** is a directory containing: the **serialised model** in a stated format; a **package manifest** (package format version; flavour(s); **input signature** — column names, order, dtypes, nullability, allowed ranges/categories; **output signature**; library names and versions used to build; Python version; the producing `run_id` and the lineage ids; **content hashes of every file**; creation time from an injected clock); an **input example**; and a **behavioural fingerprint** (predictions on a fixed probe set, hashed). **A loader must verify file hashes and signature compatibility *before* deserialising any model file, and must refuse a package whose manifest or hashes do not verify.** **"Loadable" is not "safe": deserialising a model file can execute code (`CITED [VERIFY]`), so the course loads only packages whose integrity it has verified and whose provenance it trusts, and teaches the residual risk honestly.**
- **The registry vocabulary (defined once; mapped to the illustrated tool's names with `[VERIFY]`).** A **registered model** is a named collection of **versions**; a **version** is an **immutable** record pointing to a model package (by hash) and a run (and its lineage), numbered monotonically and **never reused or edited**; an **alias** (e.g., `candidate`, `champion`) is a **named, movable pointer** to exactly one version at a time; a **tag** is a mutable annotation; **stages** (the older fixed-lifecycle labels) are treated as **a legacy modelling choice whose status in the illustrated tool for the stated family is `[VERSION-SENSITIVE] [VERIFY]` — the course models promotion with aliases and an explicit state machine and shows the mapping to stages only where verified**. **Every registry mutation is an event in an append-only, hash-chained audit log; registry state is the replay of its events.**
- **Reproducibility convention.** The 5A run tuple and levels R0–R4 apply; **a result without a stated level is not a result; "reproduce a registered version" is defined as *rebuild from its lineage and compare behavioural fingerprints/metrics at a stated level*, never as "the file still exists"**. Randomness only via recorded root seeds and named spawn keys; time via injected clocks; no hidden global state.
- **Numerical-assertion convention.** Every floating-point comparison states its tolerance, its semantics, and why; no `==` on floats unless guaranteed and tested; **a hash match is evidence of equality of bytes, never of equality of behaviour across environments; behavioural fingerprints compare predictions at a stated tolerance or exact class labels**; percentile definition and estimator stated wherever used.
- **Original-content policy.** All problems, data, runs, packages, registries, lineage graphs, incidents, and approvals are original or synthetic. Named results, books, standards, and tools are referred to **by name and own-words statement only**, never by reproducing documentation, tutorials, or example code.
