- **Correctness policy.** Every worked example and key is verified **two independent ways**: (1) a hand/explicit derivation or a read-through of the tool's documented semantics in the text, and (2) an independent computation or check (exact `Fraction`/enumeration where possible; a spec-literal brute-force reference; a different tool; never importing the function under test). Measurements and simulations carry **`n`, seeds, and an interval or spread**; one run is an anecdote.
- **The Production-Readiness Card (PRC), the units convention, and the test-level vocabulary** are those of the Stage 5D overview, `../01-…`, and `../02-…` (link; restate the twelve PRC item names once: (1) decision, consumers, serving mode; (2) data contract and quality gates; (3) point-in-time correctness and training-serving parity; (4) reproducible build; (5) tracked runs, registry, lineage; (6) tests at four levels; (7) release gate and rehearsed rollback; (8) serving contract and budget; (9) monitoring and runbook; (10) retraining policy; (11) security, privacy, retention, model card; (12) ADR and failure-mode review). The PRC is a **course convention (`JUDGEMENT`)**, not an industry standard. **This module implements and verifies items (2), (3), and the data half of (4).** The **ADR** template (context, options, decision, consequences, status) is used in every unit.
- **The two-clock convention (defined once; used identically everywhere).** Every record that enters an ML dataset has **`event_time`** (when the thing happened in the world), **`available_time`** (the earliest time the pipeline could know it — ingestion/commit time; **never assumed equal to `event_time`**), and every training row has a **`prediction_time`** (`t`, the moment the model would have been called) and, for supervised tasks, a **`label_time`** (when the label became known) with a stated **label horizon and maturity window**. **A feature value is *admissible* for row `(entity, t)` iff its `available_time ≤ t`; a label is *mature* at `t` iff `label_time ≤ t_cutoff`.** All timestamps are timezone-aware UTC in storage; naive timestamps are rejected by the contract. **The unit of independence and the as-of rule are stated for every dataset.**
- **Idempotence, atomicity, and determinism vocabulary (defined once).** A step `f` is **idempotent** if running it twice on the same input and state leaves the same state as running it once; **atomic** if a reader sees either the old complete output or the new complete output, never a partial one; **deterministic** if the same `(code, data snapshot, config, environment, seeds)` yields the same output at a stated reproducibility level (R0–R4 of 5A-11). **"Exactly-once" is treated as "at-least-once delivery plus idempotent effects"; the phrase is never used as a mechanism.**
- **Data-handling convention.** `X: (n_samples, n_features)`, `y: (n_samples,)`; keys and the unit of independence stated; the target is never an input; fit-on-training-only; **sensitive values never appear in logs, rejects, manifests, or reports — identifiers are hashed with a keyed hash or replaced by row positions in all diagnostic outputs.**
- **Numerical-assertion convention.** Every floating-point comparison states its tolerance, its semantics (absolute vs relative; symmetric vs asymmetric), and why; no `==` on floats; **bit-exact equality is claimed only where the algorithm guarantees it and is tested, otherwise a stated tolerance is used**; reductions over floats are order-sensitive and the order is stated.
- **Randomness and time policy.** Every randomized component takes an explicit `Generator`/seed derived from a recorded root seed with named spawn keys; tools never read the system clock inside logic (**inject a clock**); wall-clock timing appears only at the CLI edge and is reported with spread; simulated time is data.
- **Original-content policy.** All problems, data, schemas, contracts, defects, and incidents are original or synthetic. Named results, books, and tools are referred to **by name and own-words statement only**, never by reproducing documentation, tutorials, or example configs.
- **Data and security policy.** All data local, human-readable (CSV/JSON/JSONL/TOML/YAML/`.py`), validated, written atomically (`os.replace` after a flush and fsync where the lesson says so — **state exactly what `os.replace` guarantees and what it does not, `[VERIFY]` against the Python and OS documentation**); no PII, no telemetry, no network; never `pickle`/`marshal`/`eval`/`exec` on untrusted input (**CSV/JSON inputs are parsed, never executed; formulas in cells are not evaluated**); path traversal rejected in manifests; **planted PII-like and secret-like values in test corpora are obviously fake**.
- **Integrity and ethics policy.** Work is the learner's own; AI assistance is allowed for explanation and review, **must be disclosed in the evidence log**, and AI-generated schemas, contracts, SQL, and pipeline code are **untrusted hypotheses verified against a check**. Honest self-representation; accessibility (text alternatives for diagrams); anxiety about data engineering acknowledged as a real experience (awareness only, `[JUDGEMENT]`, no clinical claims); **responsible-use note: data about people flows through these pipelines; minimisation, retention, access, and consent are named; fairness-relevant data defects (missing-not-at-random, representation gaps) are flagged here and owned by `../14-…/05-…`; no legal claims**.
- **Result status vocabulary:** `PROVED`, `CITED`, `EVIDENCE ONLY`, `HEURISTIC`, `JUDGEMENT` (markers: `[ASSUMPTION]`, `[ILLUSTRATIVE]`, `[VERSION-SENSITIVE]`, `[VERIFY]`). **Exhaustive or seeded testing, passing gates, and matching hashes never upgrade a status to `PROVED`.**
- **Stage gate convention (inherits the repository's):** ≥ 80% proceed; 60–79% remediate named lessons and retake; < 60% repeat prerequisites. Thresholds are `HEURISTIC`/`JUDGEMENT`; **no certificate or credential is implied.**
