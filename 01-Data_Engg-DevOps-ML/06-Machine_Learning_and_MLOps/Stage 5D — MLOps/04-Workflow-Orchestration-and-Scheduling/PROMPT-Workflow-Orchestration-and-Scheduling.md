Every tool gets a Tool card, tests (including exhaustive small-domain tests), and deterministic behaviour (seeds, injected clocks).** **The module never re-teaches a Stage 1–4 lesson, a Stage 2 lesson, a Stage 5A/5B lesson, a Module 01–03 lesson, a later Module (05–16) lesson, or an S3-14/S3-20 tool: it names and links.**

## Conventions stated once, used everywhere

- **Claims policy.** Every claim about learning efficacy, study method, hiring, role requirements, orchestrator/executor popularity, "industry standard" status, tool maintenance, timeout/retry/alert targets, or superiority is exactly one of: (a) cited from a T1/T2 source tagged `[VERIFY]` with its limits; (b) practitioner opinion tagged `[JUDGEMENT]`; (c) a verifiable statement about code, a derivation, a measurement, or the repository tree; or (d) omitted. **No success rates, no outcome guarantees, no statements about what any named company does, no invented quotes or anecdotes, no rankings, no real prices.** All durations are `[ASSUMPTION]` templates; **all task durations, failure rates, costs, and prices in examples are `[ILLUSTRATIVE]` parameters**.
- **Correctness policy.** Every worked example and key is verified **two independent ways**: (1) a hand/explicit derivation or a read-through of the tool's documented semantics in the text, and (2) an independent computation or check (exact `Fraction`/enumeration where possible; a spec-literal brute-force reference; a different tool; never importing the function under test). Measurements and simulations carry **`n`, seeds, and an interval or spread**; one run is an anecdote.
- **The Production-Readiness Card (PRC), the units convention, the test-level vocabulary, and the two-clock convention** are those of the Stage 5D overview and `../01-…`/`../02-…`/`../03-…` (link; restate the twelve PRC item names once: (1) decision, consumers, serving mode; (2) data contract and quality gates; (3) point-in-time correctness and training-serving parity; (4) reproducible build; (5) tracked runs, registry, lineage; (6) tests at four levels; (7) release gate and rehearsed rollback; (8) serving contract and budget; (9) monitoring and runbook; (10) retraining policy; (11) security, privacy, retention, model card; (12) ADR and failure-mode review). The PRC is a **course convention (`JUDGEMENT`)**, not an industry standard. The **ADR** template (context, options, decision, consequences, status) is used in every unit.
- **The scheduling-time convention (defined once; used identically everywhere).** Every scheduled run has: a **`data_interval`** `[interval_start, interval_end)` it is responsible for (half-open); a **`logical_date`** (a stated function of the interval — the course names it explicitly and **never uses the bare word "date"**); a **`trigger_time`** (when the scheduler actually starts it — **for interval schedules, at or after `interval_end`**, because the data for the interval is only complete then); and a **`run_id`**. **Tasks derive every partition key, window, and filename from the `data_interval` and never from `now()`; a rerun, a retry, a catch-up run, and a backfill for the same interval must produce the same output (idempotent, from Module 03).** All schedules are defined **in UTC unless a requirement explicitly needs local civil time, and every local-time schedule is accompanied by a stated DST policy** (`[JUDGEMENT]`; the default is UTC). **Whether the orchestrator's own naming of these concepts matches the course's names is stated per version family, `[VERIFY]`.**
- **The run-state vocabulary (defined once; a course convention mapped to the orchestrator's names with `[VERIFY]`).** Task states: `none/scheduled`, `queued`, `running`, `success`, `failed`, `up_for_retry`, `skipped`, `upstream_failed`, `timed_out`, `cancelled`; run states: `queued`, `running`, `success`, `failed`. **Trigger rules** define when a task may start as a function of its upstream states (`all_success`, `all_failed`, `all_done`, `one_success`, `one_failed`, `none_failed`, and their semantics are specified by a table in the lesson, `[VERIFY]` against the orchestrator's documentation). **The propagation of `upstream_failed` and `skipped` is specified as a pure function and verified exhaustively.**
- **Reproducibility convention.** The 5A run tuple `(code, data, config, environment, seeds)` and levels R0–R4 apply; **every workflow run records its run tuple, its parameters, its `data_interval`, and the snapshot/manifest ids of its inputs and outputs (Module 03 identifiers); a result without a stated level is not a result.** Randomness only via recorded root seeds and named spawn keys; **time via injected clocks — the virtual clock of Unit 5 drives every test**; no hidden global state.
- **Numerical-assertion convention.** Every floating-point comparison states its tolerance, its semantics, and why; no `==` on floats unless guaranteed and tested; durations and rates state units (seconds, runs/hour); **duration percentiles are never averaged or added** (recall `../01-…`); percentile definition and estimator stated.
- **Original-content policy.** All problems, data, DAGs, schedules, parameters, failures, and incidents are original or synthetic. Named results, books, and tools are referred to **by name and own-words statement only**, never by reproducing documentation, tutorials, or example DAGs.
- **Randomness and time policy.** Every randomized component takes an explicit `Generator`/seed derived from a recorded root seed with named spawn keys (**durations, failures, arrivals, and shuffles use distinct named keys**); tools never read the system clock inside logic (inject a clock and a sleeper); **no test sleeps or waits for real time**; wall-clock timing appears only at the CLI edge and is reported with spread; simulated time is data.
- **Data and security policy.** All data local, human-readable (CSV/JSON/TOML/YAML/`.py`), validated, written atomically (reuse Module 03's commit protocol); no PII, no telemetry, no network at run time; **DAG files and pipeline specs are analysed with `ast.parse` and never executed by the learner's linters; the optional Airflow lab executes only the learner's own DAG files**; **secrets never in DAG code, parameters, templates, run configs, logs, or alerts** (connections and credentials are injected from the environment or a secret backend; a static check flags secret-shaped literals; planted secret-like strings are obviously fake); **templates are never rendered from untrusted input** (server-side template injection is a code-execution risk, `CITED [VERIFY]`; the course renderer is an allow-list substituter, not a general template engine); never `pickle`/`marshal`/`eval`/`exec` on untrusted input; XCom-style inter-task payloads carry **references (paths, ids, hashes), never data or sensitive values**; alert and log payloads carry no sensitive values.
- **Integrity and ethics policy.** Work is the learner's own; AI assistance is allowed for explanation and review, **must be disclosed in the evidence log**, and AI-generated DAGs, schedules, and retry/timeout values are **untrusted hypotheses verified against a check** (a generated DAG is parsed, linted, simulated on a virtual clock, and fault-injected before it is believed). Honest self-representation; accessibility (text alternatives for DAG diagrams — an adjacency list or table accompanies every graph picture); anxiety about infrastructure acknowledged as a real experience (awareness only, `[JUDGEMENT]`, no clinical claims); **responsible-use note: scheduled jobs act on data about people without a human present; failure handling, alerts, and rollbacks must account for that; no legal claims**.
- **Result status vocabulary:** `PROVED`, `CITED`, `EVIDENCE ONLY`, `HEURISTIC`, `JUDGEMENT` (markers: `[ASSUMPTION]`, `[ILLUSTRATIVE]`, `[VERSION-SENSITIVE]`, `[VERIFY]`). **Exhaustive or seeded testing, simulation, and a green DAG run never upgrade a status to `PROVED`.**
- **Stage gate convention (inherits the repository's):** ≥ 80% proceed; 60–79% remediate named lessons and retake; < 60% repeat prerequisites. Thresholds are `HEURISTIC`/`JUDGEMENT`; **no certificate or credential is implied.**
