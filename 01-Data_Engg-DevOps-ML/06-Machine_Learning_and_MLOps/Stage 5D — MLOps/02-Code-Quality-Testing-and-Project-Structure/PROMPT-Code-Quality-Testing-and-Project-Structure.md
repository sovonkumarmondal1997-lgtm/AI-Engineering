- **The test-level vocabulary (defined once, used identically everywhere; a course convention):** **unit test** (one function/class, no I/O, no model fit beyond a trivial one), **property test** (an invariant over generated inputs), **golden test** (output pinned to a stored, reviewed value), **integration test** (several real components together, tiny seeded data, local only), **contract test** (a producer/consumer interface or schema, independent of either implementation), **data test** (an assertion about data), **model-behaviour test** (an assertion about a trained model's behaviour: minimum performance versus a baseline, invariance, directional expectation, slice minimums, stability), **end-to-end test** (the CLI on tiny data). **The four PRC test levels (item 6) map to: unit (incl. property/golden), integration/contract, data, model-behaviour.**
- **Reproducibility convention.** The 5A run tuple `(code, data, config, environment, seeds)` and levels R0–R4 apply; **a result without a stated level is not a result.** Randomness only via recorded root seeds and named spawn keys; time via injected clocks; no hidden global state; **no test depends on test order, wall-clock time, the current directory, the network, or an unseeded generator.**
- **Data-handling convention.** `X: (n_samples, n_features)`, `y: (n_samples,)`; the **unit of independence**, **event time vs processing time**, and the **fit-on-training-only** rule are stated; the target is never an input; the test set is never an input to any fit.
- **Numerical-assertion convention.** Every floating-point comparison states its **tolerance, the tolerance semantics (absolute vs relative; asymmetric vs symmetric), and why**; **no `==` on floats**; `numpy.testing.assert_allclose`, `pytest.approx`, and `math.isclose` semantics **differ and are `[VERIFY]` against the documentation — teach the learner to test the semantics with a two-line experiment**.
- **Stochastic-test convention.** A test of a stochastic component asserts a bound derived from the sampling distribution with a **declared false-failure probability** (the *flake budget*, derived in Unit 3), uses a **fixed seed recorded in the test**, and states **what the seed does not guarantee**; "re-run until green" is a defect.
