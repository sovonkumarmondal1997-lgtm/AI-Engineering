## Conventions stated once, used everywhere (state them in Unit 0, apply in all units)

- **Text, bytes, and token conventions (a table, stated once; mixing is a defect).** A **string** is a sequence of Unicode **code points**; its **UTF-8 encoding** is a sequence of **bytes** (values `0..255`); a **grapheme cluster** is what a reader perceives as one character — **three different units, never conflated**. **Byte-level tokenizers operate on bytes**; **base tokens are the 256 byte values with ids `0..255`**; merged tokens have ids `256 + merge_index`; **special tokens have reserved ids placed after the merged tokens** (or at a stated, documented location) and **are never produced by encoding ordinary text unless explicitly allowed**. **A token is a byte string**; a token's *display form* is a lossless escaped rendering (never used for logic). **Decoding a token sequence yields bytes; converting bytes to text is a separate, explicit step with a stated error policy** (`strict`, `replace`, or `surrogateescape`; **an individual token may be an invalid UTF-8 fragment** — a multi-byte character split across tokens — and this is a feature to be handled, not hidden).
- **Determinism convention.** Tokenizer **training is a pure function of `(corpus, configuration)`**: **tie-breaks are explicit and total** (for equal pair counts, the lexicographically smallest `(left_id, right_id)` pair, stated), **iteration order never depends on hash seeds or dictionary insertion order unless that order is itself defined** (`PYTHONHASHSEED` effects are named and tested), and the same inputs give byte-identical artifacts. **Encoding is a pure function of `(artifact, text, allowed_special)`.**
- **Round-trip convention.** For a byte-level tokenizer **`decode(encode(s)) == s` for every byte string `s`** (lossless; proved and tested); for any text normalisation applied before tokenisation, the module states **exactly what is lost** (a normaliser breaks the round trip by design) and tests the stated property (idempotence of the normaliser; `decode(encode(normalise(s))) == normalise(s)`). **Concatenation is not preserved in general: `encode(a + b) ≠ encode(a) + encode(b)` at boundaries — a documented property with a counterexample, and the reason prompt boundaries matter (Unit 4).**
- **Special-token convention.** Special tokens (`BOS`, `EOS`, `PAD`, and others as configured) have a **declared policy** for each of: *production by the encoder from literal text* (**off by default**: the string `"<|eos|>"` in user text is encoded as ordinary bytes unless the caller passes an explicit `allowed_special`), *insertion by the caller*, *treatment in the loss and attention masks* (the padding token is masked; **Module 07's mask convention applies**), and *decoding* (skipped or rendered). **A test that user text containing a special-token string is not interpreted as a control token is mandatory.**
- **Tokenizer-independent metric convention (the signature habit of this module).** Language-model quality across different tokenizers is compared **only in bits per byte (BPB) `= (total negative log-likelihood in nats) / (ln 2 · number of bytes of the original text)`** (or bits per character for single-byte text). **Per-token cross-entropy and perplexity are reported only as within-tokenizer diagnostics, never as cross-tokenizer comparisons**, and **at least one worked example shows two tokenizers with identical total NLL and different per-token perplexity** (derived and verified). **Comparisons at a stated budget fix the *bytes seen* and the *non-embedding parameter count* (and report the embedding/softmax parameters separately) rather than the tokens seen.** The **canonical-tokenisation caveat** is stated: a token-level model assigns probability to token sequences, **and the probability of a text is the sum over all token sequences that decode to it; evaluating only the canonical sequence gives a lower bound on the text's likelihood** (an upper bound on its NLL) — derived on a tiny example by exhaustive enumeration (`CITED [VERIFY]`).
- **Evaluation-unit convention.** Metrics computed over documents (compression ratio, fertility, BPB) have the **document** as the unit of independence; **intervals are computed by a bootstrap over documents (`B` stated), never over tokens**; **tokenizer training and tokenizer evaluation use disjoint documents**; **model training and evaluation use disjoint documents**; a tokenizer is **trained on the training split only**.
- **Planted-truth convention.** Every generator ships a **manifest** of the planted truth (the Zipf exponent; the roots, prefixes, suffixes and the true morpheme boundary of every word; the multi-word phrases; the script ranges and their byte lengths; the canaries and rare strings; for the Markov source the exact entropy rate), **computed two independent ways where possible** (closed form and a large-sample empirical estimate with an interval). **A measured quantity better than the planted optimum (e.g., an LM below the entropy floor) means a bug or a leak.**
- **Fair-comparison and stability protocol (inherited from Module 05).** Comparisons (vocabulary sizes, tokenizer families, normalisation choices) use **equal bytes seen, equal non-embedding parameters (embedding/softmax parameters reported separately), equal optimiser-step budgets where stated, ≥ 5 paired seeds (`--quick` ≥ 3), disjoint tuning and reporting seeds, effect sizes with bootstrap intervals, and the number of configurations reported; no tokenizer ranking is ever stated** (link `../05-Sequence-Models-and-Tabular-Deep-Learning/README.md`, whose content is not yet authored — mark `OPEN` until reconciled).

## Unit 3 — Byte-pair encoding — **core unit**

- **L1:** **the idea** (start with the smallest units; repeatedly merge the most frequent adjacent pair into a new unit; stop at the desired vocabulary size; the **merge list** *is* the tokenizer); **a complete hand-worked training run** on a tiny word-frequency table (e.g., five words with counts) **over bytes** — the initial pair counts, the first three merges with their new token ids, the updated word representations — **verified by code**; **encoding a new word with the learned merges** (apply merges **in the order they were learned**: the earliest merge first; a hand-worked example); **decoding** (concatenate token byte strings; then UTF-8 decode); **why starting from bytes means there are no unknown tokens** (all 256 bytes are in the base vocabulary); **why pre-tokenisation first** (so merges stay inside words); **the vocabulary size** `= 256 + (number of merges) + (number of special tokens)` (derive; a worked check); **the history in two sentences** (a data-compression origin and its adoption for neural machine translation — `CITED [VERIFY]` (Gage; Sennrich, Haddow & Birch), no further history claims).

It builds **`tokenlab`'s BPE core and its evaluation harness**: **a deterministic, serialisable, fully tested byte-level BPE tokenizer (trainer, encoder, decoder, special-token policy) with a brute-force reference, an optimised trainer and encoder verified against it, and a tokenizer-independent evaluation harness that compares tokenizers by bits per byte on planted-truth corpora, with every claim bounded to those corpora.**

**Goal:** an honest, reproducible tokenizer whose **round trip is proved and exhaustively tested, whose training is deterministic and byte-identical across processes, whose optimised implementations provably match the naive references, and whose consequences (cost, fairness, glitch tokens, leakage, injection) are measured against planted truth — and that never ranks tokenisation schemes or states an optimal vocabulary size.** It is the learner's CP3 for the spine project.

**`tokgen` — the planted-truth corpus generator (specify once; used by Units 1–4 labs and this project).** A **seeded, capped (≤ 16 MB, generated on the fly or stored as UTF-8 text with a manifest and content hash)** generator with: **(a) a Zipfian lexicon** with a known exponent `s`; **(b) planted morphology** — words are `prefix? + root + suffix*` from small inventories, with **every word's true morpheme boundaries recorded**; **(c) planted multi-word phrases** with known frequencies; **(d) numbers** (digit strings of controlled lengths) and **arithmetic strings** (`a + b = c`); **(e) code-like identifiers** (camelCase and snake_case built from the lexicon); **(f) punctuation and whitespace patterns** (including indentation runs); **(g) a multi-script mode** — `K` synthetic scripts built from distinct Unicode ranges chosen so that characters occupy 1, 2, 3, and 4 UTF-8 bytes, with **equal planted information content per word across scripts** (the same underlying word sequence rendered in each script by a fixed bijection); **(h) planted canaries and rare strings** (a canary appears in exactly one document; rare strings appear a controlled number of times); **(i) planted confusables** (visually similar code point pairs and canonically equivalent NFC/NFD variants); **(j) an order-`k` Markov character source** with an **exact entropy rate** (stationary-distribution formula verified by long-run simulation) for the language-model experiments. **Manifests record every planted quantity; floors and ground truths are computed two independent ways.** A "bring your own text" mode (≤ 1 MB, no PII, provenance note) supports qualitative exploration only.

**Required components:**
1. **Bytes/Unicode layer:** a from-scratch UTF-8 encoder/decoder **verified against Python's codec over the full code-point range and over all short invalid byte sequences**; normalisation helpers; grapheme/code-point/byte counters.
2. **Pre-tokeniser:** the stdlib-compatible splitter with configurable leading-space attachment, digit rule, and case/normalisation hooks; **a proof-and-test that no merge crosses a pre-token boundary**.
3. **BPE trainer (three implementations):** **(i) a spec-literal naive trainer (the oracle)**, **(ii) an incremental trainer with a pair-to-words inverted index and a lazy-deletion max-heap**, and **(iii) a configurable minimum-count / minimum-document-frequency safeguard**; **explicit total tie-break; the overlapping-pair rule stated and tested; agreement of (i) and (ii) merge-for-merge on random small corpora (property test) and on an exhaustively enumerated tiny-corpus family**; **byte-identical output across shuffled document order and `PYTHONHASHSEED` values**.
4. **Encoder/decoder:** **(i) the simple rank-based encoder (the oracle)**, **(ii) the linked-list-plus-heap encoder**, **(iii) a trie-greedy encoder (the contrasting non-BPE algorithm)**, a pre-token cache, and the decoder with an explicit UTF-8 error policy; **`decode(encode(s)) == s` proved and exhaustively tested over all byte strings up to a stated length over a small alphabet, plus random byte strings, plus all single code points**; equality of (i) and (ii) over all small strings; documented disagreements of (iii).
5. **Special tokens and security:** the `allowed_special` policy; **the injection test**; PAD masking test hooks for the LM testbed; **homoglyph and normalisation tests**; **strict-schema, versioned, hashed JSON serialisation with a rejecting loader** (unknown fields, duplicate merges, undefined ids, hash mismatch, oversized files); **no `pickle`**.
6. **Other tokenizer families (compact):** a WordPiece-style trainer and a Unigram-LM trainer with Viterbi and EM, each verified against exhaustive segmentation enumeration on tiny inputs; used for the Unit 2 comparisons.
7. **The tokenizer-independent evaluation harness:** compression (bytes per token), fertility, OOV (word-level), **boundary precision/recall/F1 against planted morphemes**, rare-token fraction, **BPB for the LM testbed**, **per-token perplexity as the counter-example**, **document-level bootstrap intervals (`B` stated)**, the **canonical-tokenisation bound** on tiny strings by exhaustive enumeration, and the **Rényi-efficiency descriptive statistic**; **the BPB identity tested against a direct byte-level likelihood calculation on the planted Markov source (where the true NLL in bits per byte is known)**.
8. **Language-model testbed:** the Module 07 `xformer` decoder-only model trained on the planted corpora tokenised by (a) bytes, (b) BPE at several vocabulary sizes, (c) a word-level tokenizer, **at equal bytes seen and equal non-embedding parameters (embedding/softmax parameters reported separately), ≥ 5 paired seeds, BPB with intervals, sanity gates (initial loss `ln V`; overfit one batch; round trip on the training set; determinism), and the planted floor never beaten**.
9. **Required experiments (each ends with an experiment card; ≥ 5 seeds for LM runs (`--quick` ≥ 3); paired; equal budgets; tuning and reporting seeds disjoint; trials reported; tokenizer and model trained on training documents only):** (a) **correctness and exhaustive suite**; (b) **vocabulary-size sweep** (compression, fertility, boundary F1, rare-token fraction, held-out compression gap) with intervals; (c) **merge-frequency curve and the monotonicity property**; (d) **LM study in BPB across vocabulary sizes and tokenizer families** (evidence only; per-token perplexity shown as the non-comparable counter-example); (e) **Zipf/Heaps fits with intervals against the planted exponent**; (f) **cross-script cost inequity and mitigations**; (g) **number tokenisation and the planted addition task**; (h) **prompt-boundary KL and token healing**; (i) **tokenizer–model mismatch**; (j) **normalisation (NFC/NFD) and homoglyph studies**; (k) **special-token injection demonstration and the policy**; (l) **glitch tokens: planted mismatch between tokenizer and LM corpora, the detector, and its error rates**; (m) **canary leakage and the minimum-count safeguards**; (n) **training/encoding cost curves** (naive versus incremental; measured at the edge with spread, `[ILLUSTRATIVE]`); (o) **cost ledger** (artifact size; embedding/softmax parameters and FLOPs by formula; the per-byte cost identity evaluated for each vocabulary).
