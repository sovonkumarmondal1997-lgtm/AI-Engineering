## Conventions stated once, used everywhere (state them in Unit 0, apply in all units)

- **Notation, shape, and layout conventions (a table, stated once; mixing is a defect).** `B` batch, `T` sequence length (`Tq` query length, `Tk` key/value length), `d = d_model`, `h` heads, `d_k = d_v = d/h`, `V` vocabulary. Activations are **`(B, T, d)`**; per-head tensors are **`(B, h, T, d_k)`**; attention scores and weights are **`(B, h, Tq, Tk)`**, **softmax over the last axis (the key axis)**. The head split is **`(B, T, d) → (B, T, h, d_k) → (B, h, T, d_k)` via `reshape` then `transpose(1, 2)`**; the merge is the exact inverse followed by `reshape` (a **round-trip test** is mandatory; a `view` on a non-contiguous tensor or a split in the wrong order silently mixes heads). **Projection matrices are stored `(in, out)` in the from-scratch code, as in Module 01; `torch.nn.Linear` stores `(out, in)`; every port states and tests the transpose.** **Positions are zero-indexed.** **FLOPs are counted as `2 × multiply–accumulates` and the convention is stated every time.** **Parameter counts are stated with and without biases.**
- **The mask convention (the module's most important convention).** **The module's own mask is a boolean `allow` tensor, broadcastable to `(B, h, Tq, Tk)`, with `True` meaning "this query may attend to this key".** Library APIs differ — **`F.scaled_dot_product_attention`'s boolean `attn_mask`, `nn.MultiheadAttention`'s `attn_mask` and `key_padding_mask`, and `nn.TransformerEncoderLayer`'s masks use different polarities and shapes, and float masks are additive `[VERSION-SENSITIVE]`, `[VERIFY]` against the documentation for the installed version** — so the module supplies **explicit, exhaustively tested converters** (an `allow → library mask` function for each API; **a test over every boolean mask on small `(Tq, Tk)` that the converted call equals the from-scratch result**; the two polarity traps reproduced and fixed). **Fully-masked rows** (a query with no allowed key) have a **documented policy (output zeros) and a `NaN` guard**; **additive masks use `−inf` only where the fully-masked-row policy is handled**. **Causal masks are `Tk × Tq`-aware: with a cache, a query at absolute position `p` may attend to keys `0..p` — the offset convention is stated now and used by Module 12.**
- **The causality convention.** A decoder block is **causal** iff the output at position `t` depends only on inputs at positions `≤ t`. It is **proved for the architecture (masked attention, position-wise MLP, per-position norms) and tested by perturbation** (change the input at `t + j`, `j ≥ 1`; outputs at `≤ t` must be unchanged to the stated tolerance) **exhaustively over all small `T` and all `(t, j)`**.
- **Position convention.** The position scheme (learned, sinusoidal, rotary, ALiBi, none) is a **named configuration**; **rotary embeddings declare their pairing convention (interleaved pairs `(2i, 2i + 1)` versus the "rotate-half" split) and base frequency**, and the converter between the two conventions is tested; **positions enter only where the scheme says (input embedding; or queries and keys only; or the score bias)**.
- **Loss, masking, and normalisation (inherited from Module 03, applied).** Token-weighted, masked cross-entropy; **targets are inputs shifted by one for a causal language model**; padding never contributes to the loss or the metric (Module 05's padding-invariance test is reused).
- **Equivalence-test convention (inherited and extended).** Two attention/block implementations are "equivalent" only with a **stated tolerance and reason** in **float64** (and a looser, justified float32 tolerance), on **random inputs from named seeds**, over an **exhaustive small grid of shapes, mask patterns, and head counts**, and the test **fails on a planted broken variant**. **Library cross-checks (`F.scaled_dot_product_attention`, `nn.MultiheadAttention`, `nn.TransformerEncoderLayer`) are oracles for equivalence only after the from-scratch code has been checked against a brute-force loop that does not use the library.**
- **Planted-task convention (the signature habit of this module).** Every task generator (`attngen`) ships a **manifest** of the planted truth — the mechanism required, the optimal accuracy or the loss floor (**computed two independent ways**: closed form/exact enumeration and a large-sample Monte Carlo with an interval), the dependency distances, and the vocabulary — and **a held-out loss or error better than the floor means a bug or a leak**. **A model is said to have "learned the mechanism" only if it reaches the planted optimum on held-out data, including at the stated generalisation lengths, with a seed spread.**
- **Attention-diagnostics convention.** Attention weights are **diagnostics, never explanations** (`CITED [VERIFY]` the literature on attention as explanation); every diagnostic (entropy; maximum weight; **mass on the planted-correct key**) is accompanied by **a sanity check against a randomised-weights model** and a statement of what it cannot show; plots have text alternatives and numeric summaries.
