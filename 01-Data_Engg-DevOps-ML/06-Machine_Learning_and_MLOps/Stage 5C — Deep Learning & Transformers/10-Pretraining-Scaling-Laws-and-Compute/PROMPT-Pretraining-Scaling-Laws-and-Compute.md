## Conventions stated once, used everywhere (state them in Unit 0, apply in all units)

- **Counting conventions (the module's most important convention; a table, stated once; mixing is a defect).** **`N_total`** = all trainable parameters (embeddings, unembedding, norms included; tied weights counted once); **`N_ne`** = non-embedding parameters (the blocks and final norm); **`N_emb`** = token plus position embedding parameters; **`D`** = **training tokens seen** (optimiser steps × global batch × sequence length) — **and, for cross-tokenizer work, the corresponding bytes**; **`C`** = training compute in FLOPs, **`C ≈ 6·N·D` with the `N` used stated every time and the approximation compared with exact FLOPs**; **`Ψ`** = the parameter count used in memory formulas. **Every scaling fit states which of `N_total`/`N_ne` it uses and which loss unit (per-token or bits per byte).** **FLOPs are `2 × multiply–accumulates`.** **`p`** = world size (number of ranks); **`B_global = p × B_micro × accum`**.
- **The loss-unit convention.** **Scaling and comparison results are reported in bits per byte (BPB)** (`5C-08`'s identity) **or, within a fixed tokenizer, per-token cross-entropy in nats with the tokenizer named; irreducible-loss terms are compared with the planted floor in the same unit.**
- **The fitting convention (signature habit).** Every fitted law is accompanied by: the **functional form and its justification**; the **number of data points and of free parameters**; the **fitting procedure (objective, robust loss if any, multiple initialisations, optimiser, convergence check)**; **parameter uncertainty by bootstrap (case bootstrap over ladder points *and* parametric bootstrap from the fit), `B` stated, with the coverage of the procedure checked on data simulated from a known law**; **residual diagnostics (residuals versus `N`, `D`, and `C`; a structured residual is a model-misspecification finding, not noise)**; **the measured range of `N`, `D`, `C`, and an explicit refusal to extrapolate beyond it, followed by a *tested* extrapolation (hold out the largest points, predict, report the error versus extrapolation distance)**; and **the fits' sensitivity to the counting and loss-unit conventions**. **Exponents are never quoted to more digits than their intervals support.**
- **The experimental-design convention.** Ladders and sweeps are **pre-registered** (Stage 5A-11/5B format: the grid, seeds, learning-rate protocol, schedule rule, fit forms, extrapolation holdout, and decision rules are written before any result; a **deviation checker** compares the executed analysis with the plan); **the learning rate is tuned per model size with an equal, budgeted, disjoint-seed protocol** (`5C-03` Unit 7); **the schedule length is matched to the token budget of each run (a fully decayed schedule — an unfinished schedule is a confound, measured)**; **tuning and reporting seeds are disjoint; ≥ 3 seeds per ladder point (`--quick` ≥ 2); the number of runs, failed runs, and discarded runs is reported; the ladder harness is Module 09's, reused**.
- **The distributed-simulation convention.** A **simulated rank** holds its own copy or shard of the state; **collectives are functions with explicit semantics** (`all_reduce` sums by default and **the module states, tests, and uses the division by `p` separately**; `reduce_scatter`; `all_gather`; `broadcast`) **and message/volume counters**; **every simulation is verified against the single-device computation** (float64 where the result is exact up to floating-point associativity, with the tolerance justified from the number of summed terms); **memory per rank is computed by formula and by counting the simulated shards**; **communication volume is computed by formula and by the simulation's counters**; **a simulation never claims a speed-up**.
- **The cost-model convention.** Time/cost/energy models are **symbolic in their hardware parameters** (peak FLOP/s `F`, memory bandwidth `W`, link bandwidth `β`, latency `α`, device power `P`, power-usage effectiveness `PUE`, price per device-hour `c`); **worked examples use named, obviously-hypothetical symbols or round placeholders labelled `[HYPOTHETICAL]`, never values attributed to real hardware**; **the only measured hardware quantity is the learner's own CPU (dense-matmul throughput and the achieved training throughput), measured at the edge with spread and labelled `[ILLUSTRATIVE]`**; **MFU on the CPU is defined relative to the CPU's own measured dense-matmul ceiling and is labelled as such.**
