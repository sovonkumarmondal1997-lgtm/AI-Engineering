**Design decisions to state in Unit 0 and Unit 8 (deliberate, `JUDGEMENT`):**

1. **Build in testable increments, against floors.** The module is organised as **bigram → one head → several heads → block → stack → trained model**, and **every increment is tested against an oracle and a floor before the next is added**. Because natural text has no known floor, **correctness is established on planted-truth corpora** (the Module 07 `attngen` tasks — Markov source with an exact entropy rate, induction, lookup — and the spine project's `toycorpus` generators, `../00-Stage-Overview/Projects/01-train-a-small-gpt-and-write-the-report.md`; **the spine's `toycorpus` specification is not yet authored — use the Module 07 `attngen` generators and give the minimal schema if `toycorpus` is absent; record `OPEN`**), **and the end-to-end experience is then repeated on a custom corpus the learner supplies**.
2. **The custom corpus is the learner's own, local, and handled responsibly.** The repository forbids downloaded corpora. **"Custom corpus" therefore means text the learner already owns and may use — their own writing, notes, or code — held locally, ≤ a few megabytes, with a written provenance and licence note, no personal data about other people, a secret/PII scan before training, document-level splits, and deduplication.** Results on it are **never graded on quality** (there is no floor); they are graded on **process** (splits, leakage and memorisation checks, reproducibility, a compute ledger, honest reporting). **No real-world corpus is downloaded or assumed.**
3. **Relationship to the spine project and to Modules 07, 08, 10, 12.** This module is where the learner **builds their own GPT from the verified parts** — it is the stage's **open-box moment** (the spine's reference `tinygpt` becomes the learner's own; checkpoints **CP2 (own attention, block, model) and CP3 (own tokenizer)** are completed here, and **CP1 (own training loop)** is exercised). **State the mapping table in Unit 0 and Unit 8; do not duplicate the spine project's report-writing content.** **Scaling *laws* and compute-optimal theory belong to Module 10; here "scaling it up" means the engineering of larger runs — configuration, memory/time planning, batch and context choices, mixed precision, resumability — plus a small practical scaling ladder.** **Decoding and sampling are Module 12; here `generate` is the minimal autoregressive loop with temperature**, and **KV-cached generation is Module 12**.

## Conventions stated once, used everywhere (state them in Unit 0, apply in all units)

- **Notation, shape, and model-configuration conventions (a table, stated once; mixing is a defect).** Token batches are **`(B, T)` `int64`**; activations `(B, T, C)` with **`C = n_embd`**; logits `(B, T, V)`; the **context window is `block_size`** and **every forward pass requires `T ≤ block_size`** (a precondition check, never a silent clamp); `n_head` divides `n_embd`; `head_size = n_embd / n_head`; `n_layer` blocks. The configuration is a **frozen, validated dataclass** (`block_size, vocab_size, n_layer, n_head, n_embd, dropout, bias`, plus the weight-tying flag) **hashed into every checkpoint and every log**. **Parameter counts are reported in three numbers: total, non-embedding, and embedding (token + position), with the weight-tying convention stated** (under tying the token table is counted once). **FLOPs are counted as `2 × multiply–accumulates`.** All conventions of Module 07 (mask polarity `allow = True`, `(in, out)` weights in from-scratch code versus `(out, in)` in `nn.Linear`, zero-indexed positions, token-weighted masked loss) **apply unchanged.**
- **Language-modelling, shift, and batching conventions.** **A language model is trained to predict token `t + 1` from tokens `≤ t`; the input and target windows are `x = tokens[i : i + T]` and `y = tokens[i + 1 : i + T + 1]`** — **the shift-by-one is stated, implemented once, and tested** (a test that `y[:, :-1] == x[:, 1:]` and that the loss on a copy task without the shift is near zero while with it is not). **Valid window offsets are `0 … N − T − 1` for a token stream of length `N`; no window crosses a document or split boundary** (a document boundary is either an explicit `EOS` token with the model trained across it, or windows are drawn within documents — **the choice is stated and tested**). **The budget of a run is stated in tokens seen and optimiser steps (never "epochs" alone).**
- **Data-file and split conventions.** Corpora are stored as **memory-mapped token files (`uint16` when `V ≤ 65535`, else `uint32`; the dtype recorded) with a JSON metadata file** (tokenizer artifact hash, vocabulary size, dtype, document boundaries, split boundaries, normalisation, deduplication report, secret/PII-scan report, provenance and licence note, content hash); **splits are by document (or by contiguous block with a gap of at least `block_size` tokens when only one long document exists), made before tokenisation statistics are computed, and the tokenizer is trained on the training split only**; **the test split is evaluated once**. **No random-window split of a single stream is ever used.**
- **Evaluation conventions (the module's habit).** Loss is reported as **bits per byte (BPB) on the evaluation split** (`= NLL_nats / (ln 2 · bytes)`; **bytes counted from the decoded text, not tokens**; Module 08's identity) **alongside per-token loss only as a within-model diagnostic**; **comparisons across tokenizers use BPB only**; evaluation uses **fixed evaluation batches** (drawn once from a named seed), `model.eval()`, `torch.no_grad()`, and reports **the standard error across evaluation batches and the spread across training seeds**. **Every language-model result is accompanied by the baselines it must beat** — **the unigram model, the bigram model, and an interpolated n-gram model, each fitted on the training split with hyperparameters chosen on validation data** — **and by the planted floor where one exists**; **a held-out loss below the floor means a bug or a leak**.
- **Sampling and qualitative-evaluation conventions.** `generate(model, prompt_ids, max_new_tokens, temperature, top_k, seed)` **crops the context to the last `block_size` tokens at every step, uses an explicit `torch.Generator`, and is deterministic given its seed**; **qualitative samples are produced from fixed prompts, fixed seeds, and a stated set of temperatures, and all of them (not a selection) are reported**; **sample quality is never claimed without a stated measurement** (distinct-n-gram rates, the fraction of generated `n`-grams copied verbatim from the training split, held-out loss).
- **Memorisation, privacy, and provenance conventions.** Before any training on text the learner supplies: **(1)** a **provenance and licence note** is written; **(2)** a **secret/PII scan** (patterns for key-like strings, email-like strings, phone-like strings, and other stated patterns; **its false-negative limits stated: a scan reduces risk, it does not eliminate it**) is run and its report stored; **(3)** **exact and near-duplicate detection** (rolling-hash `n`-gram overlap and shingling/MinHash — Stage 3) is run **within** the training split and **between** splits; **(4)** after training, a **memorisation probe** (the fraction of sampled `n`-grams present verbatim in the training split; a planted-canary exposure test on planted corpora) is reported. **A model trained on text containing other people's personal data is out of scope.**

## Unit 1 — The bigram language model

- **L1:** **the task** (given the tokens so far, assign a probability to the next token; chain them to get a probability for a whole text); **the simplest model — counting** (a bigram model predicts the next token from the previous one: **`p̂(b | a) = count(a, b) / count(a, ·)`**; a hand-worked table for a 12-character toy string and a 4-symbol vocabulary; **sampling** from it by hand); **the same model as a table of learnable logits** (a `V × V` array; row `a` is the logit vector for "what follows `a`"; **the embedding table of Module 06 is exactly this table when it outputs logits directly** — `../06-Embeddings-and-Representation-Learning/01-one-hot-vs-dense-embeddings.md`); **cross-entropy loss** of the neural bigram on the toy string computed by hand and verified; **the loss at initialisation** (`≈ ln V` for near-uniform logits — hand-derived); **bits per character** (loss `/ ln 2`; recall Module 05/08); **what the model cannot do** (it sees one token; a hand-built example where the next token depends on two previous ones); **a first generation** (sample 40 characters; compare with the true text — and note the output is gibberish that has the right local statistics, which is exactly what the model was asked to learn).
- **L2:** **implement from scratch**: **(a) the counting unigram, bigram, and interpolated-trigram baselines** (`p = λ₁ p̂₁ + λ₂ p̂₂ + λ₃ p̂₃` with the `λ` chosen on **validation** data by grid search or EM — Jelinek–Mercer-style interpolation `CITED [VERIFY]`; **add-`k` smoothing**; unseen-context handling); **(b) the neural bigram** (`nn.Embedding(V, V)`; `forward(idx, targets)` returning logits and the mean loss with `F.cross_entropy` on the flattened `(B·T, V)` logits — **cross-entropy takes logits, never probabilities; tested**); **(c) the data pipeline**: a token stream, **`get_batch(split, B, T, generator)`** (random offsets, `x`/`y` windows with the shift, **the shift-by-one test, the no-cross-boundary test, the determinism-given-seed test**); **(d) the training loop** (the Module 03 `Trainer`: sanity gates — initial loss `≈ ln V`, overfit one batch; **fixed evaluation batches**; a small AdamW run with a constant then a decayed learning rate); **(e) `generate`** (the autoregressive loop: crop context, take the last position's logits, **divide by temperature, softmax, sample with an explicit generator**, append; **the equivalence of generating one token at a time to teacher-forced next-token probabilities — an exhaustive small-`T` test**; `temperature → 0` limit and its numerical hazard); **(f) the equivalence experiment**: **train the neural bigram by gradient descent and show its softmax rows converge to the counting estimate on every context seen in training** (a table of the maximum absolute difference versus step, ≥ 3 seeds; **the rows for contexts never seen remain at initialisation**); **(g) evaluation against floors**: on the planted **order-1 Markov source** the bigram model must reach the **exact entropy rate** (never below it on held-out data); on the **order-2 source** the bigram's held-out loss converges to the **exact conditional entropy `H(X_t | X_{t−1})`**, strictly above the entropy rate — **the gap is the information a longer context would give, computed exactly (two ways) and measured**; on **`induction`/`lookup` the bigram stays at chance**; **BPB** for a character-level and a Module 08 BPE tokenisation of the same text (**equal bytes**, evidence only); the **training-run card**.
- **L3:** **mathematics, in full:** (a) **maximum-likelihood for a categorical conditional**: maximising `Σ log p(b | a)` over a table gives `p̂(b | a) = c(a, b)/c(a, ·)` — **derive with a Lagrange multiplier; verify against the counts**; (b) **the neural-bigram stationary point**: the gradient of the mean cross-entropy with respect to row `a` of the logit table is `(1/N) Σ_{t : x_t = a} (softmax(W[a, :]) − onehot(x_{t+1}))`, **zero iff the softmax row equals the empirical conditional — prove; the learned table equals the counting MLE at the optimum (up to a per-row additive constant in the logits, which the softmax removes) — verify numerically; contexts never observed receive zero gradient**; (c) **why the unsmoothed MLE has infinite held-out loss** (a zero-probability bigram in the evaluation text) **and what smoothing does**: add-`k` smoothing `p(b | a) = (c(a, b) + k)/(c(a, ·) + kV)` **is the posterior mean under a symmetric Dirichlet(`k`) prior — derive (link `4C-05 06-bayesian-inference-posteriors-and-conjugate-priors.md`); the MAP estimate is a different expression — state both**; (d) **Gibbs' inequality and the loss decomposition**: `CE(p, q) = H(p) + KL(p ‖ q) ≥ H(p)` with equality iff `q = p` — **prove**; **hence a language model's expected loss cannot fall below the source's entropy rate, and the learner's bug detector ("loss below the floor ⇒ bug") is a theorem**; (e) **the information chain** `H(X₁) ≥ H(X₂ | X₁) ≥ H(X₃ | X₂, X₁) ≥ … ≥ H_∞` (unigram entropy ≥ bigram conditional entropy ≥ … ≥ entropy rate) **— prove (conditioning cannot increase entropy), compute each term exactly for the planted order-`k` sources by enumeration and verify with large-sample empirical estimates with intervals**; (f) **interpolation as a mixture model** (the interpolated estimate is a convex mixture of conditionals; its log-likelihood is concave in the weights; **EM for the weights — derive the update; verify against a grid search**); (g) **perplexity** `= exp(loss)` and its relation to the effective branching factor (derive; a worked example); **BPB and the tokenizer-independence identity (recall `5C-08`)**; (h) **parameter and compute accounting** (`V²` parameters; the cost of the logit table versus a low-rank factorisation `V × d` and `d × V` — the **motivation for embeddings and an unembedding: with `d ≪ V`, `2Vd ≪ V²`**; the rank constraint it imposes on the logit table — derive); (i) **the data pipeline's mathematics** (the number of valid windows `N − T`; the probability that a random window falls in a given document; **the correlation between overlapping windows and the effective number of independent training examples**; why random offsets with replacement are a stochastic estimate of the epoch loss — derive the unbiasedness; **the evaluation-batch count needed for a stated standard error — derive and verify by simulation**); ## Unit 2 — The self-attention head

- **L1:** **the problem the bigram leaves** (the next token may depend on many earlier tokens); **the simplest way to use the past — average it**: the output at position `t` is the **mean of the vectors at positions `0 … t`** (a hand-worked `T = 4` example by a Python loop); **the same average as one matrix multiplication** (a lower-triangular matrix of ones, row-normalised, times the input — hand-verified); **the same again via a masked softmax** (start from a zero score matrix, set the future entries to `−∞`, take a softmax over each row — the rows become uniform over the allowed positions — hand-verified) — **three forms, one result**; **making the weights depend on the data** (queries and keys decide *how much* of each past position to take; values decide *what* to take — recall `5C-07 02-queries-keys-values-and-scaled-dot-product-attention.md`, one line); **why the scores are scaled** (one line; recall Module 07); **the head in code in six lines** (shapes written at every line) **and the causal mask as a registered non-trainable buffer sliced to `[:T, :T]`**; **token and position embeddings feeding one head, then a linear map to the vocabulary** (the **first attention language model**); **hand-checked shapes** `(B, T) → (B, T, C) → (B, T, head_size) → (B, T, V)`.
