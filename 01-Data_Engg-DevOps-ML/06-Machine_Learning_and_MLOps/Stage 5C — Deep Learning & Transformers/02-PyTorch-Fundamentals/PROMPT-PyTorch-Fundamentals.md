## Conventions stated once, used everywhere (state them in Unit 0, apply in all units)

- **The tensor card** (one per non-trivial tensor in an example; a one-line comment is enough in code): **shape, dtype, device, contiguity, whether it requires grad, whether it shares storage with another tensor**. Every function states these for inputs and outputs, and **runtime-checks the shape and dtype it depends on** (a helper `check(t, shape=..., dtype=..., device=...)` in `ptlab`).
- **Shape and layout convention (inherited from Module 01 and extended).** Samples are rows: `X: (B, d)`; sequences (used in later modules and in collate examples) are `(B, T, d)`; images are `(B, C, H, W)`; labels for classification are `int64` class indices `(B,)`. **Losses are mean-reduced unless stated.** **`nn.Linear.weight` is `(out, in)`; Module 01's `nnlab` `W` is `(in, out)`; every port states the transpose explicitly and tests it.**
- **The PyTorch behaviour rule.** Every statement of the form "PyTorch does X" is exactly one of: (a) **verified by a test the learner can run** (preferred); (b) cited to the official documentation and tagged `[VERSION-SENSITIVE]` and `[VERIFY]`; (c) omitted. **Never teach internals (the dispatcher, kernel selection, allocator details, storage implementation) as guarantees.** Record `torch.__version__`, device, dtype, and thread count in every experiment.
- **The gradient-check convention (inherited from Module 01, restated in the PyTorch setting).** `torch.autograd.gradcheck` / `gradgradcheck` in **float64**, with the tolerances stated and justified (the Module 01 error analysis applies); **a gradient check must be shown to fail on a planted bug** before it is trusted.
- **Equivalence-test convention.** Two implementations are "equivalent" only with a **stated tolerance and reason** (float64 comparisons: relative/absolute tolerance justified from the operation count; float32 comparisons: looser and justified), tested on **random inputs from named seeds**, and the test **fails on a deliberately broken variant**.
- **Reproducibility convention (extends the 5A run tuple and levels R0–R4).** Seeds via `torch.manual_seed` **and** an explicit `torch.Generator` for data order; NumPy via `SeedSequence`/`default_rng`; worker seeding stated; `torch.use_deterministic_algorithms` used deliberately and its effect tested `[VERSION-SENSITIVE]`; thread count pinned (`torch.set_num_threads`); **the achievable level is stated (R2: same machine, same torch version, same thread count, stated tolerance); bitwise reproducibility across machines, versions, devices, or thread counts is never promised**.
- **Measurement convention (for any speed or memory number).** Warm-up iterations discarded; **multiple repeats with spread**; **device synchronisation before stopping the clock on any asynchronous device**; the clock is injected in tests and used only at the edge; wall-clock numbers are **never asserted exactly in tests**; memory figures state what was measured (bytes of tensors by formula, process RSS, allocator counters). **You cannot execute code: every timing or memory figure is `[ILLUSTRATIVE]` and accompanied by the command that produces the real number; byte counts by formula (`numel × element_size`) are exact and may be stated.**

- **Claims policy.** Every claim is exactly one of: (a) cited `[VERIFY]` with conditions and limits; (b) practitioner opinion `[JUDGEMENT]`; (c) a verifiable statement about code, mathematics, or the repository tree; or (d) omitted. **No framework or library ranking; no outcome or hiring claims; no claims about how real systems use PyTorch; no GPU speed-up or memory figure unless it is derived or labelled `[ILLUSTRATIVE]` with its command.**
- **Evaluation hygiene (inherited):** split before fitting; evaluate on unseen data; report baselines and the planted floor; ≥ 5 seeds with spread (`--quick` ≥ 3) for the MLP experiments; a loss or error better than the planted floor on held-out data means a bug or a leak.
