## Unit 2 — Gini, entropy, information gain, and variance reduction

- **L1:** **an impurity measure scores how mixed a node is; a good split makes the children purer than the parent**; **for class proportions `p = (p_1, …, p_K)`: Gini impurity `G(p) = 1 − Σp_k²` (the probability that two independent draws from the node have different classes; also the expected misclassification rate of labelling a row by a random draw from the node's distribution); entropy `H(p) = −Σp_k ln p_k` (recall 4B-13 lesson `02-entropy.md`; nats here; the library's log base for `criterion="entropy"` is a documented convention `[VERSION-SENSITIVE]`, `[VERIFY]`: tested; the base only rescales gains); misclassification error `E(p) = 1 − max_kp_k`; for binary nodes with positive share `p`: `G = 2p(1 − p)`, `H = −p ln p − (1 − p)ln(1 − p)`, `E = min(p, 1 − p)`; all are `0` for a pure node and largest at the uniform distribution**; **the gain of a split: `Gain = I(parent) − (n_L/n)I(left) − (n_R/n)I(right)` (weighted by child sizes)**; **a first worked example by hand: the 8-row table: parent Gini, the weighted child Gini and the gain for each of three candidate splits; the same with entropy; the same via the library's `tree_.impurity` (weighted)**; **regression: the impurity of a node is its variance (mean squared error around the node mean); variance reduction = the parent's SSE minus the children's total SSE; the criterion `squared_error` (and `friedman_mse`, `absolute_error`, `poisson` named: `[VERSION-SENSITIVE]`)**; **why not misclassification error (a split can improve purity without changing the majority class, so `E` shows zero gain: a computed example: parent `(6, 4)` → children `(4, 0)` and `(2, 4)`-type splits that leave both majority classes unchanged under a particular design: construct and verify)**; ≥ 3 worked examples.
- **L2:** **properties and relationships (each derived in L3)**: **Gini and entropy are strictly concave in `p`, so the weighted child impurity never exceeds the parent's: `Gain ≥ 0` for every split, with equality iff the child class distributions equal the parent's (a split that does not change the class mix is worthless); `G ≤ H` (in nats) and both are maximised at the uniform distribution (`G_max = 1 − 1/K`, `H_max = ln K`); in practice Gini and entropy often pick the same split (a measured agreement rate on seeded generators with an interval; `JUDGEMENT`: no claim that either is better; where they disagree, the difference is typically small in held-out score: measured)**; **information gain as mutual information: for a split indicator `S ∈ {L, R}` and class `Y`, `H(Y) − H(Y | S) = I(Y; S)` (recall 4B-13 and 4C-06 lesson `02-mutual-information.md`): the entropy gain of a split is the information the split carries about the label (in nats), so it is bounded by `H(S) ≤ ln 2` and by `H(Y)`**; **variance reduction (regression): `SSE_parent − (SSE_L + SSE_R) = (n_Ln_R/n)(ȳ_L − ȳ_R)²` (proved in L3): a split is valuable when the child means differ and both children are reasonably large (the factor `n_Ln_R/n` is largest for balanced splits)**; **gain and weights (sample weights and class weights enter the class counts/sums; `min_impurity_decrease` in scikit-learn is applied to the *weighted* gain `(N_t/N)·(…)`: the exact formula is a documented convention `[VERSION-SENSITIVE]`, tested)**; **bias of the split search toward many candidate splits (the maximum of many noisy gains is larger: a feature with `u` distinct values offers `u − 1` thresholds, so a pure-noise continuous feature typically wins the root over a weak informative binary feature; an ID-like feature separates every row and achieves the maximum possible gain (a leaf per row) — derived in L3 and demonstrated: the expected maximum gain of pure-noise features vs the number of distinct values, with intervals; remedies: gain ratio (C4.5, `CITED [VERIFY]` Quinlan), minimum leaf size, bagging, and held-out evaluation; the same bias appears in impurity-based importance (Unit 12))**; **criteria in ensembles and boosting (boosted trees use gradient/Hessian-based gain: Unit 8; random forests use the same impurity criteria)**; **the cost of computing gains (counts via cumulative sweeps: Unit 1; the cost of entropy's logarithms vs Gini's squares: counted)**; **Poisson and absolute-error criteria (named; when the target is a count or a median is desired: the leaf value is the leaf mean (Poisson) or median (absolute error); cost: the median needs a heap/sorted structure: `[VERIFY]`; link 5A-04 Unit 8)**; **class imbalance and impurity (a rare class contributes little to Gini unless it is concentrated: `class_weight` rescales; the split search still favours the majority class; link 5A-05 Unit 4)**; **choosing the criterion (a convention: the default is usually fine; compare on held-out data with a paired interval; the module claims nothing general)**.
- **L3:** **proofs, written in full:** (a) **concavity: `G(p) = 1 − Σp_k²` is strictly concave on the simplex (Hessian `−2I`); `H(p) = −Σp_k ln p_k` is strictly concave (Hessian `−diag(1/p_k)`); `E(p) = 1 − max_kp_k` is concave but not strictly (piecewise linear)** — complete; (b) **gain non-negativity: for a concave impurity `I`, Jensen gives `I(p) = I((n_L/n)p_L + (n_R/n)p_R) ≥ (n_L/n)I(p_L) + (n_R/n)I(p_R)`, so `Gain ≥ 0`; for strictly concave `I`, equality holds iff `p_L = p_R` (= `p`)** — complete; (c) **`G ≤ H`: since `−ln p_k ≥ 1 − p_k`, `H = Σp_k(−ln p_k) ≥ Σp_k(1 − p_k) = 1 − Σp_k² = G`; equality iff each `p_k ∈ {0, 1}` (pure node)** — complete; (d) **information gain is mutual information: `H(Y) − Σ_{s}P(s)H(Y | S = s) = I(Y; S)` (the definition of mutual information in terms of conditional entropy: 4C-06 Unit 2), hence `0 ≤ IG ≤ min(H(Y), H(S))`** — complete (recalled definition; bound by non-negativity of conditional entropy); (e) **variance reduction identity: with `n = n_L + n_R`, `SSE(S) = Σ_{i∈S}(y_i − ȳ_S)²`, then `SSE(S) − SSE(S_L) − SSE(S_R) = (n_Ln_R/n)(ȳ_L − ȳ_R)² ≥ 0` (the between-group sum of squares)** — complete (add and subtract group means; check numerically with `Fraction`); (f) **misclassification error can show zero gain although Gini gain is positive: a worked family where both children keep the parent's majority class (`E` is linear on each side of `p = ½`) — constructed and verified** — complete; (g) **ID-feature gain: if each row has a unique feature value, the best split of a node of size `n` can isolate any single row, and a full tree has `n` pure leaves; the total impurity decrease of a fully grown tree on a dataset with no duplicate feature vectors equals the root impurity (leaves are pure): telescoping** — complete; (h) **selection bias of the split search: for `u` independent noise thresholds each with gain `Γ_j ≥ 0`, `E[max_jΓ_j]` is non-decreasing in `u` (a maximum over a larger set is no smaller): a nested-candidates argument; for a continuous noise feature the number of candidates grows with the node size** — complete for monotonicity; the magnitude is measured by simulation (`EVIDENCE ONLY`); **counterexamples**: **a zero misclassification-error gain with positive Gini gain (computed)**; **a noise feature beating a weak informative feature at the root (seeded; intervals)**; **a unique-ID feature winning every split (computed)**; **Gini and entropy selecting different roots on a constructed table, with equal held-out scores within the interval (seeded)**; **numerical analysis**: **spec-literal gains vs `tree_.impurity` and `DecisionTreeClassifier(criterion=…)` on random tables; the `entropy` base; weighted-gain conventions of `min_impurity_decrease`; cancellation in variance computations (the naive `Σy²/n − ȳ²` form vs the stable running mean/variance: recall 5A-01 Unit 5)**; **tool card** for `treelab.impurity` (Gini/entropy/misclassification/variance impurities and gains with explicit weights and log base; running-statistics sweeps (counts; sum and sum of squares with a Welford-style update); - **L4:** **impurity and criteria in production (an MLOps lens)**: **numerical stability of gains (floating-point cancellation in `Σy²/n − ȳ²`; use running means; ties at the `1e-12` level and tie-breaking determinism; ## Unit 3 — Tree depth, pruning, and leaf constraints

## Unit 4 — Random forests and bagging

- **L1:** **bagging (bootstrap aggregating, `CITED [VERIFY]` Breiman 1996)**: **draw `B` bootstrap samples (each of `n` rows drawn *with replacement* from the training rows), fit one deep tree on each, and combine: average the predictions (regression) or average the class-probability estimates / vote (classification)**; **why it helps (recall 5A-07 Unit 2): a deep tree has low bias and high variance; averaging `B` trees whose predictions have variance `v` and pairwise correlation `ρ` has variance `ρv + (1 − ρ)v/B`, the bias is unchanged, and the variance falls toward `ρv` as `B` grows; bagging helps when trees are unstable (they are) and less when `ρ` is close to 1**; **random forests (`CITED [VERIFY]` Breiman 2001)**: **bagging plus *random feature subsetting at every split* (only `m_try` randomly chosen features are considered at each node), which decorrelates the trees (lower `ρ`) at the price of slightly weaker individual trees; the conventional defaults `m_try ≈ √p` (classification) and `≈ p/3` (regression) are conventions; library defaults differ by estimator and version `[VERSION-SENSITIVE]`, `[VERIFY]`: tested**; **a first worked example: a 10-row dataset; three bootstrap samples drawn with a stated seed by hand (indices with repeats), the three trees' predictions for one query, and the averaged/voted result; the same with a 3-tree `RandomForestClassifier` (`n_estimators=3`, `bootstrap=True`, `random_state`)**; **out-of-bag (OOB) estimation (derived in L3): each tree's bootstrap sample leaves out about 36.8% of the rows; predicting each row only with the trees that did not see it gives an honest-looking error estimate without a separate validation set; `oob_score`, `oob_decision_function_`, `oob_prediction_` (`[VERSION-SENSITIVE]`)**; **hyperparameters (each defined): `n_estimators`, `max_features`, `max_depth`/`min_samples_leaf`, `bootstrap`, `max_samples`, `class_weight` (including `balanced_subsample`), `n_jobs`, `random_state`**; ≥ 3 worked examples.

## Unit 5 — Extra-trees and ensemble diversity

- **L1:** **extremely randomised trees (extra-trees, `CITED [VERIFY]` Geurts, Ernst & Wehenkel 2006)**: **like a random forest, but the split threshold for each candidate feature is drawn *at random* (uniformly between the feature's minimum and maximum in the node) instead of searched, and the best of these random candidate splits is chosen by the usual gain; by default the whole training set (no bootstrap) is used for each tree (library default `bootstrap=False`: `[VERSION-SENSITIVE]`, `[VERIFY]`)**; **why: cheaper (no sorting for thresholds) and more randomised, so the trees are less correlated and the decision boundary smoother, at the price of higher bias per tree**; **a first worked example by hand: the 8-row table; for each of two features a random threshold is drawn (seeded); the gains of the two random candidates; the chosen split; contrast with the exhaustive best split; the same with `ExtraTreesClassifier` (`n_estimators=1`)**; **ensemble diversity (the idea): an ensemble helps only if its members make *different* errors; an ensemble of identical models adds nothing (`ρ = 1`); a good ensemble has individually decent members that disagree in useful ways**; **sources of diversity (each defined): different training samples (bagging), different feature subsets (random subspace/forests), random split thresholds (extra-trees), different algorithms (stacking/voting: Unit 6), different hyperparameters, different seeds/initialisations**; **measuring diversity (each defined and computed by hand on a 6-row example): pairwise disagreement `P(h_a(x) ≠ h_b(x))`, the correlation of errors (or of residuals for regression), the double-fault measure `P(both wrong)`, and the Kohavi–Wolpert variance (named: `CITED [VERIFY]`)**; ≥ 3 worked examples.
- **L2:** **extra-trees vs forests vs bagging (measured, not ranked)**: **seeded comparisons on generators with different structures (smooth additive; interactions; many irrelevant features; noisy labels): held-out scores with paired intervals, the measured tree-prediction correlation `ρ`, the per-tree bias/variance proxy (the mean per-tree held-out error), and the ensemble's variance reduction — evidence about these generators; **smoothness (averaging many random-threshold trees yields a smoother function than a forest: a seeded 1-D plot as a table)**; **the ambiguity decomposition (derived in L3): for squared error and a weighted average ensemble, `(f̄ − y)² = Σw_k(f_k − y)² − Σw_k(f_k − f̄)²`: the ensemble error equals the average member error minus the ambiguity (the spread of the members around the ensemble); ## Unit 7 — Boosting versus bagging

- **L1:** **two ways to combine trees**: **bagging/forests build many *independent* deep, low-bias, high-variance trees in parallel and average them (variance reduction); boosting builds *shallow*, high-bias, low-variance trees *sequentially*, each one focusing on what the current ensemble gets wrong, and adds them (bias reduction)**; **a first worked example (a decision table plus numbers): the same 600-row problem with (a) one depth-1 stump, (b) 100 bagged stumps, (c) 100 boosted stumps, (d) one deep tree, (e) a 100-tree forest: training and held-out scores with intervals: bagged stumps stay as biased as a stump; boosted stumps fit the structure; the forest averages away the deep tree's variance**; **AdaBoost (adaptive boosting, `CITED [VERIFY]` Freund & Schapire 1997) for binary labels `y ∈ {−1, +1}`**: **start with equal row weights `w_i = 1/n`; for `m = 1…M`: fit a weak learner `h_m` (e.g., a stump) to the *weighted* data; compute its weighted error `ε_m`; give it a vote weight `α_m = ½ ln((1 − ε_m)/ε_m)` (positive when `ε_m < ½`); increase the weights of misclassified rows by `e^{α_m}` and decrease the others by `e^{−α_m}`; renormalise; the final classifier is `sign(Σα_mh_m(x))`**; **a first worked example by hand: a 6-row dataset; three rounds of AdaBoost with stumps: the weights after each round, the `α_m`, and the final combined predictions; the same via `AdaBoostClassifier` (`algorithm` options and the status of the older "SAMME.R" variant: `[VERSION-SENSITIVE]`, `[VERIFY]`)**; **boosting's cautions (sequential and not parallel across rounds; sensitive to label noise (mislabelled rows get ever-larger weights); needs a learning rate/shrinkage and a stopping rule)**; ≥ 3 worked examples.
- **L2:** **bagging vs boosting in depth (derived/measured)**: **(1) what each reduces: bagging reduces variance and leaves bias; boosting reduces bias (the training error falls as rounds are added) and can increase variance if run too long (a seeded rounds sweep: training error monotone down; robust losses and shrinkage in gradient boosting mitigate: Unit 8); (5) tuning: forests are comparatively insensitive to hyperparameters; boosting requires tuning rounds, learning rate, depth, and regularisation together (Unit 11); (6) probabilities: AdaBoost's scores are margin-like and poorly calibrated (`CITED [VERIFY]` Niculescu-Mizil & Caruana 2005; measure; 5B `04`); gradient boosting with log loss trains probabilistic outputs directly: Unit 8**; **AdaBoost as stagewise additive modelling (derived in L3): minimising the exponential loss `Σexp(−y_iF(x_i))` greedily over an additive model `F = Σα_mh_m` gives exactly the AdaBoost weight updates and `α_m = ½ln((1 − ε_m)/ε_m)` (`CITED [VERIFY]` Friedman, Hastie & Tibshirani 2000); this view generalises to other losses: gradient boosting (Unit 8)**; **margins and training error (the training-error bound: `(1/n)Σ1{H(x_i) ≠ y_i} ≤ ∏_m 2√(ε_m(1 − ε_m)) ≤ exp(−2Σγ_m²)` with `γ_m = ½ − ε_m`: derived in L3: training error falls exponentially fast whenever each weak learner is better than chance; it says nothing about held-out error, which can keep improving after training error reaches 0 (a margin story: named `CITED [VERIFY]`; no claim) or deteriorate with noise)**; **the key identity (derived in L3): after reweighting, the *previous* weak learner has weighted error exactly `½` under the new weights — so the next learner must find something different**; **learning rate/shrinkage in AdaBoost (`learning_rate` scales `α_m`; smaller values need more rounds)**; **multiclass AdaBoost (SAMME, named; `CITED [VERIFY]`)**; **AdaBoost regression (named: `AdaBoostRegressor`; not the module's focus)**; **decision table: when to use bagging/forests vs boosting (data size, noise level, tuning budget, latency, need for probabilities, interpretability: `JUDGEMENT`; no ranking; - **L3:** **proofs, written in full:** (a) **AdaBoost's optimal vote weight: at round `m` with weights `w_i` (sum 1) and a weak learner with weighted error `ε`, the weighted exponential loss `Σw_ie^{−αy_ih(x_i)} = (1 − ε)e^{−α} + εe^{α}` is minimised at `α = ½ln((1 − ε)/ε)` with minimum value `2√(ε(1 − ε))`** — complete (calculus); ## Unit 8 — Gradient boosting fundamentals

- **L1:** **boosting as gradient descent in function space (`CITED [VERIFY]` Friedman 2001)**: **we want a function `F(x)` minimising the total loss `Σℓ(y_i, F(x_i))`; start from a constant; at each round compute, for every training row, the *negative gradient of the loss with respect to the current prediction* (the "pseudo-residual" `r_i = −∂ℓ(y_i, F)/∂F` at `F = F_{m−1}(x_i)`), fit a small regression tree `h_m` to these pseudo-residuals, and add it with a small step: `F_m = F_{m−1} + νh_m` (`ν` = learning rate/shrinkage)**; **for squared error `ℓ = ½(y − F)²`, `r_i = y_i − F(x_i)`: the plain residual — each tree fits what is still unexplained**; **a first worked example by hand: an 8-row regression table; `F_0 = ȳ`; residuals; a depth-1 tree fitted to them (the best split by variance reduction); `ν = 0.5`; `F_1`; the new residuals; the second tree; the training loss after each round; the same with `GradientBoostingRegressor` (`n_estimators=2`, `learning_rate=0.5`, `max_depth=1`) and your reference**; **classification: the model `F(x)` is a log-odds; `p = σ(F)`; the log loss's negative gradient is `r_i = y_i − p_i`; the initial constant is the prior log-odds `ln(π/(1 − π))`; leaf values use a Newton step (below); multiclass: `K` trees per round and a softmax**; **the algorithm (pseudo-code in the syllabus): initialise; for `m = 1…M`: compute `r_i`; fit a tree to `r` (structure by squared-error gain on `r`); compute each leaf's value by a one-dimensional line search/Newton step on the true loss; update `F`; optional row subsampling (stochastic gradient boosting) and feature subsampling**; **the hyperparameters (each defined): `n_estimators`, `learning_rate`, `max_depth`/`max_leaf_nodes`, `min_samples_leaf`, `subsample`, `max_features`, `loss`, `n_iter_no_change` and `validation_fraction` (early stopping: Unit 11), `init`; `HistGradientBoostingClassifier/Regressor` (binning, native NaN, `max_iter`, `max_leaf_nodes`, `l2_regularization`, `categorical_features`, `monotonic_cst`, `early_stopping` defaults: `[VERSION-SENSITIVE]`, `[VERIFY]`)**; - **L2:** **gradient boosting in depth (derived in L3; implemented as the references)**: **loss functions and their pseudo-residuals (a table, each derived): squared error → `y − F`; absolute error → `sign(y − F)` (robust; leaf values are medians of residuals); Huber → clipped residual; quantile (pinball) → `τ` or `τ − 1` by side (a quantile model: 5A-04 Unit 10); binomial deviance (log loss) → `y − p`; exponential loss → AdaBoost's weights (Unit 7); Poisson/Gamma deviance → `y − μ`-type with a log link (counts: 5A-04 Unit 8)**; **leaf values and second-order boosting (the Newton view used by XGBoost/LightGBM/HistGradientBoosting; `CITED [VERIFY]` Chen & Guestrin 2016): approximate the loss by a second-order Taylor expansion in the new tree's output: `Σ[g_if(x_i) + ½H_if(x_i)²] + Ω(f)`; for a fixed tree structure with leaf sets `I_j`, the optimal leaf value is `w_j* = −G_j/(H_j + λ)` with `G_j = Σ_{i∈I_j}g_i`, `H_j = Σ_{i∈I_j}H_i`, `λ` an L2 penalty on leaf values, and the structure score is `−½Σ_jG_j²/(H_j + λ) + γT`; the gain of a split is `½[G_L²/(H_L + λ) + G_R²/(H_R + λ) − (G_L + G_R)²/(H_L + H_R + λ)] − γ` (derived in L3). For squared error `g_i = F_i − y_i`, `H_i = 1`: the leaf value is the (shrunken) mean residual and the gain reduces to the variance-reduction criterion; for log loss `g_i = p_i − y_i`, `H_i = p_i(1 − p_i)`: leaves are `Σ(y − p)/(Σp(1 − p) + λ)`**; **shrinkage and rounds (derived in L3): with learning rate `ν`, fitting a constant learner to the residual `r` shrinks it by `(1 − ν)` each round; reaching a residual fraction `ε` takes `m = ln ε/ln(1 − ν) ≈ ln(1/ε)/ν` rounds — so halving `ν` roughly doubles the rounds needed (the first-order learning-rate/rounds trade-off: `HEURISTIC` for trees but exact for this constant-learner toy; a seeded check on trees)**; **regularisation levers (each with its bias/variance role): shrinkage `ν`, number of rounds, tree depth/leaves, minimum leaf size/child weight, row subsampling, column subsampling, `λ`/`γ`; their interactions (lower `ν` needs more rounds; stronger subsampling adds variance reduction like bagging: stochastic gradient boosting)**; **training and validation loss by round (`staged_predict`/`staged_predict_proba`; the training loss decreases monotonically for a small enough step; the validation loss is U-shaped: the round count is a hyperparameter selected on a validation split inside the training fold: Unit 11)**; **bias–variance (boosting reduces bias round by round; the variance enters through depth, noise, and rounds: the module's seeded decomposition on a known generator with intervals)**; **what boosted trees represent (additive combinations of piecewise-constant functions: depth 1 = an additive model; depth `d` = interactions up to order `d`: Unit 7; extrapolation is constant beyond the data: Unit 4's limitation)**; **probabilities (log-loss boosting yields probability estimates with reasonable-but-unguaranteed calibration; ## Unit 12 — Feature importance: an introduction

- **L1:** **what importance answers (and what it does not)**: **a feature-importance score says how much a *fitted model* relies on a feature — it is a property of the model, not a causal effect and not necessarily a property of the world (association ≠ causation: recall 5A-04 Unit 3, 5A-02 Unit 3)**; **three families (introduced; each defined and computed by hand on a tiny example)**: **(1) impurity-based importance (mean decrease in impurity, MDI): the total impurity decrease contributed by splits on the feature, weighted by the number of rows reaching each split, summed over the trees and normalised (`feature_importances_` in scikit-learn tree models: `[VERSION-SENSITIVE]`); computed from the training data; (2) permutation importance: shuffle one feature's values in a held-out set and measure the drop in the model's score (a metric card from 5A-06); the bigger the drop, the more the model uses the feature; repeated shuffles give an interval; (3) Shapley-value attributions (SHAP): a game-theoretic way to split a prediction among the features; introduced here with an exact computation on a three-feature toy**; **a first worked example: a 3-feature synthetic dataset where feature 1 drives the target, feature 2 is a correlated copy of feature 1, and feature 3 is noise: MDI, permutation importance, and the true structure side by side; the importance of the copies splitting between them**; **sanity checks (the module's habit): add a **random noise column** and see where it ranks; if the noise column outranks a real feature, the importance method is unreliable for that model/data**; **partial dependence and ICE (named; introduced in L2)**; ≥ 3 worked examples.
- **L2:** **the methods in depth (derived/measured)**: **(1) MDI: the importance of feature `j` is `Σ_{trees}Σ_{nodes t splitting on j}(n_t/N)·Gain_t` (normalised); properties (derived in L3): non-negative; sums over features to the total impurity decrease; **biases (measured on seeded generators): it favours features with many distinct values (more candidate splits: Unit 2's selection bias), is computed on *training* data (an overfit model assigns importance to noise features), and splits importance among correlated features arbitrarily; a continuous noise feature can outrank a binary informative one**; (2) permutation importance on held-out data (algorithm: for each feature and each of `R` repeats, shuffle the feature column in the evaluation set, recompute the metric, record `score_baseline − score_shuffled`; report the mean and spread; `sklearn.inspection.permutation_importance` `[VERSION-SENSITIVE]`; the evaluation set must be held-out (training-set permutation importance reflects what the model *memorised*: a seeded demonstration); the metric must be the one in the plan (5A-06); the interval: spread over repeats plus bootstrap over evaluation rows; **caveats (measured)**: correlated features (shuffling one creates unrealistic combinations and the importance is shared among copies: two identical features each show about half the drop; grouped permutation (shuffling a block of correlated features together) named), and models that cannot use a feature show exactly 0 drop); (3) drop-column (refit without the feature: expensive and answers a different question: the value of the feature *given a model class that can substitute others*); (4) Shapley values (derived/computed): for a prediction `f(x)` and a feature set `N`, the Shapley value of feature `j` is the weighted average of its marginal contribution `v(S ∪ {j}) − v(S)` over all subsets `S` (weights `|S|!(|N| − |S| − 1)!/|N|!`), where `v(S)` is the model's expected prediction when only the features in `S` are known (the definition of `v` — marginal/interventional vs conditional expectation — matters and depends on a *background dataset*: a seeded demonstration that different `v` give different attributions); **efficiency: `Σ_jφ_j = f(x) − E[f]`**; exact computation costs `2^{|N|}` evaluations; TreeSHAP computes exact values for tree ensembles in polynomial time (`CITED [VERIFY]` Lundberg et al. 2020; the library is optional: the module computes exact Shapley values by enumeration for ≤ 8 features and uses them as the oracle); local (per-prediction) vs global (mean absolute Shapley value) importance; caveats (attributions depend on the background data and on `v`; they describe the model, not causes; correlated features share credit; SHAP values are not feature *removal* effects); (5) partial dependence (PD: the average prediction as a feature is varied over a grid with the others kept at their observed values: `PD_j(x) = (1/n)Σ_if(x, x_{i,−j})`) and ICE (one curve per row): derived structure; caveats (unrealistic combinations under correlation; heterogeneity hidden by averaging: ICE shows it); accumulated local effects (ALE: named `CITED [VERIFY]`; no development)**; **stability and uncertainty (importance rankings vary across seeds, bootstrap resamples, and correlated-feature configurations: measure rank correlation across bootstrap refits with intervals; report importances with intervals; never present a ranking without one)**; **importance for feature selection (only inside the training fold; the selection-before-CV leak: 5A-03 Unit 12; 5A-07 Unit 7)**; **importance as a leakage detector (a single feature dominating importance is a leak hypothesis: 5A-03 Unit 12; run the shuffled-label control and a structure-aware split)**; **interactions (a pair that matters only jointly (XOR) has near-zero univariate association but high permutation importance in a model that captured the interaction: a seeded demonstration; Friedman's H-statistic named `CITED [VERIFY]`)**; **importance and the model class (a different model gives different importances for the same data; importance is relative to a model and a metric)**; **fairness and proxies (importance of a feature correlated with a sensitive attribute: awareness only; the check is per-group performance, not importance)**; **reporting standard (importance table: method, data (held-out), metric card, repeats, interval, null-feature baseline, correlated-group handling; a "what this does not show" paragraph)**.
- **L3:** **proofs, written in full:** (a) **MDI properties: with weighted impurity decreases `Δ_t = (n_t/N)Gain_t ≥ 0` (Unit 2), the importance of feature `j` in a tree is `Σ_{t: split on j}Δ_t ≥ 0`;
