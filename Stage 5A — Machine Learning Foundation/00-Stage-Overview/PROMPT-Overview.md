# 6. UNIT-SPECIFIC CONTENT REQUIREMENTS

These topics are the **minimum**; add depth, never remove. **Every lesson-sized topic contains at least two fully worked original examples (at least three in Unit 3), each verified two independent ways.** **Every tool gets a Tool card, tests (including exhaustive small-domain tests), and deterministic behaviour (seeds, injected clocks).** **The module never re-teaches a Stage 1–4 lesson, a Module 01–13 lesson, or an S3-14/S3-20 tool: it names and links.**

## Conventions stated once, used everywhere

- **Claims policy.** Every claim about learning efficacy, study method, hiring, interviews, role requirements, or what "a data scientist needs" is exactly one of: (a) cited research tagged `[VERIFY]` with its limits; (b) practitioner opinion tagged `[JUDGEMENT]`; (c) a verifiable statement about code, statistics, or the repository tree; or (d) omitted. **No success rates, no outcome guarantees, no statements about what any named company asks or requires, no invented quotes or anecdotes, no "N% of ML work is data cleaning".** All durations are `[ASSUMPTION]` templates the learner replaces with measured values.
- **Correctness policy.** Every worked example and key is verified **two independent ways**: (1) a hand/explicit derivation in the text, and (2) an independent computation in Python (exact `Fraction`/enumeration where possible; otherwise NumPy/SciPy/scikit-learn with a **stated tolerance and reason**; never float `==`). Statistical statements from experiments carry **`n`, seeds, and an interval or standard error**; agreement on examples is evidence, not proof.
- **Evaluation-protocol convention (the signature habit of this stage; taught in Unit 1, enforced everywhere).** **(i) Define the question and the unit of prediction; (ii) choose and record the baseline; (iii) split first (and respect groups and time) before any fitting or inspection of the target; (iv) fit every learned transformation on training data only, inside a pipeline; (v) select models on validation or cross-validation, never on the test set; (vi) touch the test set once; (vii) report the metric with an interval and the seeds; (viii) record versions, data snapshot, and config.** The **protocol card** records these eight items.
- **Reproducibility convention.** A run is reproducible if, given the recorded code version, config, data snapshot hash, library versions, and seeds, it yields the same result to a stated tolerance; **a result that cannot be reproduced is not a result**. Randomness only via explicit `np.random.default_rng(seed)`/`random_state` arguments; `n_jobs` and BLAS thread effects acknowledged; no hidden global state.
- **Data-handling convention.** Rows are samples, columns are features; `X: (n_samples, n_features)`, `y: (n_samples,)`; the **unit of independence** (row, customer, session, time) is stated; train/validation/test are named consistently (`X_train`, `X_val`, `X_test`); **the target is never an input; the test set is never an input to any fit**.
- **Original-content policy.** All problems, data, and scenarios are original or synthetic. Named results are referred to **by name and own-words statement only**, never by reproducing a textbook's wording, examples, figures, or exercise sets. No downloaded or scraped content.
- **Randomness and time policy.** Every randomized component takes an explicit `Generator` or seed; tools never read the system clock inside logic (inject a clock); every Monte Carlo or resampling statement carries its sample size and an error estimate.
- **Data and security policy.** All data local, human-readable (CSV/JSON/`.py`/`.ipynb`-with-outputs-stripped), validated, written atomically (`os.replace`); no PII, no telemetry, no network; never `pickle`/`marshal`/`eval`/`exec` on untrusted input (serialised models are a code-execution risk: state this and show a safe alternative for the smoke test, `[VERIFY]`); secrets never in notebooks or Git; notebooks executed only from the learner's own project directory with the stated warning that opening a notebook runs code.
- **Integrity and ethics policy.** Work is the learner's own; AI assistance is allowed for explanation and review, **must be disclosed in the evidence log**, and AI-produced code or claims are **untrusted hypotheses verified against a check**. Honest self-representation; accessibility (text fallbacks for plots); maths anxiety acknowledged as a real experience (awareness only, `[JUDGEMENT]`, no clinical claims); responsible-use note on data about people (privacy, fairness) as awareness only.
- **Result status vocabulary:** `PROVED`, `CITED`, `EVIDENCE ONLY`, `HEURISTIC`, `JUDGEMENT` (markers: `[ASSUMPTION]`, `[ILLUSTRATIVE]`, `[VERSION-SENSITIVE]`, `[VERIFY]`). **Exhaustive or seeded testing never upgrades a status to `PROVED`.**
- **Stage gate convention (inherits the repository's):** ≥ 80% proceed; 60–79% remediate named modules and retake; < 60% repeat prerequisites. Thresholds and weights are `HEURISTIC`/`JUDGEMENT`; **no certificate or credential is implied.**
