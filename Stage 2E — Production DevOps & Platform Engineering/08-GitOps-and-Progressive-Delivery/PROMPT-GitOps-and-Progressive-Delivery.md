2. AI self-audit is not independent. Run every manifest, rollout, query and migration on a real kind cluster, and close every `[VERIFY]` item against current official docs. The status and output in the syllabus will be representative, not captured from real runs.
3. Highest fabrication risk, check first:
   - Argo CD `Application`, `ApplicationSet` and `AppProject` fields.
   - Sync options and `ignoreDifferences` forms.
   - Flux CRD API versions and fields, `flux bootstrap git` flags and image-automation maturity.
   - Argo Rollouts step and analysis-provider fields, and which traffic-router plugins are currently supported (this changes).
   - Flagger's current maintenance status and supported routers.
   - PromQL label names used for canary versus stable.
   - OpenFeature and flagd provider names.
   - PostgreSQL DDL locking behavior by major version.
   - OpenAPI diff tool flags.
   - Controller event and history behavior.
4. Scope decisions I made, which you can change:
   - The tooling map lists Flux, Argo Rollouts and Flagger as Awareness, but this folder has dedicated modules for them. The prompt teaches Flux and Rollouts at working depth. Flagger gets a concept, architecture and comparison treatment, with an optional lab.
   - A local Git server (such as Gitea) replaces any hosted Git, so no external account is needed. Using GitHub or GitLab on a private test repo is optional.
   - The memory budget is the hard constraint. The prompt forces Argo CD and Flux never to run in the same cluster at once, and metrics for rollout analysis come from a minimal source (a tiny Prometheus or a stub), not a full observability stack (that is M11).
   - One secret-reference tool is hands-on. M09 owns the depth.
5. Handoffs are explicit. CI's responsibility ends at writing desired state to Git. SLO gates are M10, admission-time signature enforcement is M12, DR is M13, and multi-cluster is M14. If you change those folders, adjust the handoffs.
6. Several labs deliberately break things: a bad canary, a locking migration, a leaked secret, a controller outage and a force-push. The prompt requires a safety plan, a context assertion and throwaway resources for each. Keep the lab cluster and repo separate from anything real.
7. Statistical claims are limited on purpose. A laptop lab can't give real traffic volumes. The prompt forbids quoting thresholds or sample sizes as standards and makes the LLM state that low-traffic services can't be canaried on error rate alone.
