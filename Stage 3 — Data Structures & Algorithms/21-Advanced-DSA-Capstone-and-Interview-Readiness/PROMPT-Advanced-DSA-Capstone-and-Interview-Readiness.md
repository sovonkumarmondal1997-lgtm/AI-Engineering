## Unit 3 — Benchmarking and complexity validation
*This unit **recalls** the S3-01 benchmarking pitfalls and the S3-14 estimator in one page and teaches **designing, running, analyzing, and reporting benchmark experiments for a whole library**.*

- **L2:** **the benchmark suite**: **`BenchSuite`** (**a declarative spec: algorithm, input family generators, sizes, repetitions, seeds, measure (counted work and optionally time/memory); a runner that executes with `gc` control, warm-up, and per-run seeds; candidate-model comparison (linear, `n log n`, quadratic, cubic, exponential via `log T` vs `n`) with residuals; the `fit_growth` tool built on the S3-14 estimator**), **claim validation** (**`validate_claim(algorithm, claimed_class, families, sizes, tolerance)` returns `SUPPORTED`/`CONTRADICTED`/`INCONCLUSIVE` with the evidence; rules: at least 5 sizes spanning ≥ 2 orders of magnitude where feasible; fitted exponent within a stated tolerance of the claimed class; worst-case claims are checked on adversarial families; amortized claims by total work over operation sequences divided by the number of operations; expected-case claims over many seeds with an interval; space claims by peak counted cells**), **amortized validation example** (**dynamic array append: total copies over `n` appends ≤ `2n`; union-find operations; monotonic deque — counted**), **expected-case validation example** (**randomized quickselect: mean comparisons over seeds with a bootstrap interval vs the `≤ ~3.4n`-type bound `CITED [VERIFY]`**), **regression guards** (**deterministic thresholds on counted work stored in a baseline file; reusing mutated inputs; too few sizes; single runs; warm-vs-cold effects; garbage collection; WSL2 noise; Python-level constants hiding asymptotics; comparing C built-ins with pure Python**), **noise management** (**repetitions; pinning nothing (no privileges); reporting variability**).
- **L3:** **statistics and rigor**: **(a) log-log regression derivation: if `T(n) = c·n^a`, then `log T = log c + a·log n`; the least-squares slope estimates `a` — derivation of the estimator and its standard error under the usual assumptions (`CITED [VERIFY]` for the standard-error formula; the learner verifies on synthetic data with known `a`)**; **(b) identification limits: `n log n` vs `n^{1.1}` over a finite range — a computed example showing the local slope of `n log₂ n` between `n` and `2n` is `1 + 1/ln n`-like and drifts toward 1 slowly (derivation: `d log(n log n)/d log n = 1 + 1/ln n`); hence with few sizes the classes are not separable — the tool reports `INCONCLUSIVE` when residual differences are below a stated threshold**; **(c) bootstrap confidence intervals: resample runs (or seeds) with an injected RNG; percentile interval; why it is an approximation; exact coverage checks on small synthetic cases (enumerating all bootstrap resamples for tiny samples) — `EVIDENCE ONLY`**; **(d) counted work as an exact quantity: for deterministic algorithms the count on a given input is exact and reproducible; worst-case claims can be validated exactly on small domains by exhaustive search for the maximizing input (e.g., maximum comparisons of insertion sort over all permutations of `n ≤ 8`) — derived vs measured**; **(e) amortized analysis validation: potential-function claims checked as an invariant at every step (`Φ ≥ 0`, amortized cost = actual + ΔΦ) on random operation sequences — written for two structures**; **(f) expected-case analysis validation with exact enumeration where possible (e.g., randomized quicksort's expected comparisons for `n ≤ 8` over all permutations vs the recurrence) — S3-16/S3-14 recall**; **(g) experimental design: choosing sizes (geometric spacing), number of repetitions from variance estimates (a sample-size calculation with Chebyshev, proved; or with the normal approximation, `CITED [VERIFY]`), randomization of run order, blocking by input family**; **(h) the limits of benchmarks: they cannot prove asymptotics; worst-case behavior may be missed; hardware and interpreter effects; a "claim ledger" listing for each claim its evidence level (proof / exhaustive-domain / counted-work fit / timing observation)**; **(i) multiple comparisons across many algorithms: the chance that at least one fit looks `CONTRADICTED` by noise (the counted-work path has no noise, so only randomized/timed claims are affected) — stated**.
- **L4:** **expert practice**: **diagnosing a surprising benchmark result (hypotheses: wrong input family; hidden quadratic behavior like list slicing; cache effects (named); GC; accidental sorting in the generator) with a checklist and counted-work cross-checks**, **benchmarking at scale within resource caps (stopping rules; time budgets per benchmark; skipping oversized configurations with a recorded reason)**, **comparing across Python versions/interpreters (documented differences; PyPy JIT warm-up caveat `[VERSION-SENSITIVE]`)**, **reviewing others' benchmark reports (a review checklist: environment, seeds, sizes, repetitions, intervals, baselines, claims vs evidence)**, **publishing benchmark results responsibly (no cherry-picking; include negative results; raw data files)**, **hostile inputs** (non-deterministic algorithms without seeds → rejected; absurd sizes → capped; timeouts → partial results recorded), **explanations** (`explain(report)` states which claims are supported and why), **testing**: **`fit_growth` recovers known exponents/classes from synthetic exact counters (exact for noise-free ladders; ambiguity flagged for narrow ranges); `validate_claim` decisions tested on constructed true/false claims; amortized/expected validators tested against exact enumerations; regression guard tested for pass/fail/update paths; JSON/CSV report round-trips; environment capture contains no PII (tested)**; stress harness with shrinking; **mutation lab** (using wall time instead of counted work in an assertion; off-by-one in the doubling ratio; sizes not sorted; fit ignoring residual; baseline update without reason accepted; generator timed inside the loop) with no surviving mutants; **regression guard**; documentation; coaching approach ("a benchmark can contradict a claim but never prove it; say which evidence level you have").
