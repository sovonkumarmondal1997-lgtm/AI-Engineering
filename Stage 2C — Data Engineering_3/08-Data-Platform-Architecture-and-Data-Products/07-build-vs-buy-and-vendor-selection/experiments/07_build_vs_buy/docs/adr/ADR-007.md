# ADR-007: Managed-first SaaS ingestion with custom-source escape hatch

- **Status:** Proposed, pending POC, security review, and written commercial quote
- **Owner:** Data Platform Lead
- **Stakeholders:** Data Engineering, Platform/SRE, Finance, Security, Legal/Privacy, Analytics
- **Decision date:** 2026-10-19
- **Review date:** 2027-01-19 or earlier on a trigger

## Context
Ingest 40 SaaS sources into an existing warehouse. Team capacity is three data engineers and one shared platform/SRE resource; 24×7 connector operations are undesirable. Ingestion is assumed commodity; source semantics and data products are likely differentiators. The named shortlist is Fivetran managed ingestion, Airbyte Core self-managed, and custom dlt-based ingestion. The cost model uses generic archetypes rather than named-vendor pricing; scores are illustrative hypotheses and all hard gates remain NOT_ASSESSED. Current cost inputs and scores are illustrative assumptions only.

## Decision
Shortlist Fivetran managed ingestion and Airbyte Core self-managed, with custom dlt-based ingestion as a targeted alternative. Prefer managed ingestion only if it passes POC correctness, security, source-coverage, recovery, and operations gates and negotiated three-year TCO fits the approved budget. No score is decision-eligible until hard gates are evidenced. Use custom dlt-style code for unsupported sources or requirements the managed service cannot satisfy safely. Do not sign before security/legal review and exit terms.

## Alternatives
1. Fivetran managed ingestion: expected to reduce routine connector operations; verify exact coverage, billing definitions, security, quote, and exit.
2. Airbyte Core self-managed: greater deployment control; team owns operations and incident response; verify exact Core version, connectors, licence, and current deployment requirements.
3. Custom dlt-based ingestion: flexible and inspectable; team owns connector code and production operations.
4. Hybrid: managed for commodity sources, custom/dlt-based connectors for exceptions; two paths require clear ownership.

## Consequences
- Verify exact connector/object coverage and update/delete semantics.
- Keep source inventory, mappings, contracts, and runbooks in version control.
- Replace model assumptions with POC measurements and written quotes.
- Treat export/deletion/termination terms as procurement gates.
- Hybrid operation requires consistent ownership, alerting, and lifecycle standards.

## Risks and mitigations
- Hidden usage cost: reconcile vendor billing units, test a usage estimator, negotiate caps/alerts and overage terms.
- Connector gaps: POC critical sources and use custom escape hatch.
- Outage: document recovery/replay and destination-side validation.
- Lock-in: test data/config export and one-source migration annually.
- Security/privacy: threat, DPA, subprocessor, residency, access, and audit review.
- Operational underestimation: record engineer/on-call time during POC and first quarter.

## Reversal conditions
Reopen if:
- POC fails correctness, security, or critical source coverage.
- Quoted 3-year TCO exceeds approved budget by >20% after assumptions are reconciled.
- Actual operations/on-call hours exceed model by >30% for two consecutive months.
- Material support/SLA failure or adverse pricing/licence/region change occurs.
- A residency, data-processing, or customer requirement cannot be met.
- An alternative demonstrates lower comparable TCO with acceptable documented residual risk and opportunity cost.

## Evidence and review
Review by 2027-01-19. Store source inventory, criteria/weights, dated scores, POC logs, security/legal outcomes, written quote, reference notes, final TCO, and exit test under `docs/vendor-eval/`. Finance approves spend; Security and Legal approve their gates; the Data Platform Lead owns operational fit and review.
