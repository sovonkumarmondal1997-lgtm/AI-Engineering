# 6. UNIT-SPECIFIC CONTENT REQUIREMENTS

These topics are the **minimum**; add depth, never remove. **Every lesson-sized topic contains at least two fully worked original examples (at least three at L1 and L2 combined per unit), each verified two independent ways.**

## Conventions stated once, used everywhere

- **Claims policy.** Every claim about learning efficacy, hiring, the "best" selection or explanation method, a number of features to keep, a VIF or importance cutoff, or what an explanation "shows" is exactly one of: (a) cited research/documentation tagged `[VERIFY]` with limits; (b) practitioner opinion/rule of thumb tagged `[JUDGEMENT]` or `HEURISTIC`; (c) a verifiable statement about mathematics, code, or the tree; or (d) omitted. **No general ranking of selection or explanation methods; no explanation is presented as causal; no legal or regulatory sufficiency is claimed; every empirical comparison is stated as evidence about its generator only.** Durations `[ASSUMPTION]`; sizes `[ILLUSTRATIVE]`.
- **Correctness policy.** Every worked example and key is verified **two independent ways**: (1) a hand derivation in the text, and (2) an independent computation — **exact (`Fraction`/`sympy`/enumeration/quadrature) on the tiny tables and on models with closed-form attributions wherever possible**, otherwise `numpy`/`scipy`/scikit-learn with a **stated tolerance and reason**, or simulation with stated `n`, seed, replicates, interval. **Every selector, importance, attribution, and counterfactual search in the module is implemented as a short spec-literal reference and cross-checked against scikit-learn/SciPy on tiny and random inputs, including constant features, duplicate features, ties in scores, `p > n`, and categorical encodings.** A library function is never the sole oracle for a claim about that function.
- **Proof policy.** Where Section 6 says "proof", write it in full: statement, hypotheses, every step justified, closing "where each hypothesis was used". **Heuristics are labelled `HEURISTIC` with their measured behaviour on a stated generator.** Where a result is `CITED [VERIFY]`, say which and give a numerical sanity check.
- **What-is-being-explained convention (stated once; applied everywhere).** **Every explanation is a statement about a *specific fitted model* `f̂` evaluated on a *specific data distribution* (the background/reference distribution), for a *specific question* (global importance, local attribution, marginal effect, what-would-change-the-decision). It is not a statement about the data-generating process, about causes, or about a different model. Every explanation reports (i) the model and its version, (ii) the data and background distribution, (iii) the output space (probability, log-odds, regression units), (iv) the question answered, and (v) stability across refits. Local and global explanations are never mixed without saying so.**
- **Planted-truth convention.** Every selector, importance, attribution, and counterfactual method is evaluated on generators for which **the truth is known**: the relevant-feature support; the true additive effects and interactions; **the exact Shapley values and partial-dependence curves of the generating function (or of an additive/linear model that matches it)**; the true causal graph and interventional effects; the true proxy strength; so that **support-recovery precision/recall and false-discovery proportion, attribution error against the exact values, rank agreement with the true effects, stability across refits, and counterfactual validity are measured against truth over ≥ 30 independent generator seeds with intervals**, never inferred from the data the method saw. **The no-signal null generator is part of every study (any "selected" or "important" feature there is a false discovery).**

## Unit 1 — Feature selection: filter, wrapper, and embedded methods

- **L1:** **feature selection means choosing a subset of the input columns to use; reasons: speed, simpler and cheaper models, less overfitting when there are many columns and few rows, and sometimes interpretability; non-reasons: it does not reveal which features *cause* the outcome**; **three families, in plain words: *filters* score each feature on its own (correlation with the label, a statistical test, mutual information) and keep the best; *wrappers* try subsets by fitting the actual model repeatedly (forward selection, backward elimination); *embedded* methods select as part of fitting (the lasso zeroes coefficients; trees skip features)**; **the central danger in one sentence: **selection uses the labels, so it must be inside the cross-validation loop — selecting features on all the data and then cross-validating gives optimistic scores, sometimes wildly so**; **a first worked example by hand: the six-row, three-feature table: filter scores by correlation; a forward selection run with a stated criterion; and a 12-row "random label, 30 random features" table where picking the top 3 features by correlation on all rows gives a spurious perfect-looking fit**; ≥ 3 worked examples.
- **L2:** **selection in depth (derived/measured)**: **(1) the three families compared** (cost: a filter is `O(p)` scores; forward/backward wrappers fit `O(p²)` models (derived in L3); the exhaustive search over `2^p − 1` subsets is infeasible beyond `p ≈ 25`: counted; the multiplicity problem; why univariate screening plus a model refit looks excellent in-sample); **(4) evaluating a selector against planted truth** (support recovery: precision, recall, and F1 of the selected set against the true relevant set; ## Unit 2 — Variance, correlation, and mutual information

- **L1:** **three simple filters: *variance* (drop columns that barely vary), *correlation* (keep columns that move with the label), *mutual information* (keep columns that share information with the label, including non-linear sharing)**; **what each can and cannot see: low variance can still matter (a rare "fraud-flag" column that is almost always 0); high variance need not matter; correlation sees only straight-line relationships; mutual information sees any relationship but is harder to estimate; **all three look at one feature at a time, so a pair of features that matter only together (XOR) can be invisible**; **a first worked example by hand: the eight-row XOR table: each feature's correlation and mutual information with the label (both zero, computed exactly); the pair's joint mutual information (1 bit); then `y = x²` with `x ∈ {−1, 0, 1}`: correlation `0`, mutual information `0.918` bits**; **scaling matters for variance (a feature in dollars has more variance than the same feature in thousands)**; ≥ 3 worked examples.
- **L2:** **filters in depth (derived/measured)**: **(1) variance filters** (`VarianceThreshold`; scale dependence; normalised variants (coefficient of variation, binary-feature rarity); the rare-but-decisive counterexample; use only to drop constants and near-constants *as a data-quality step* (5A-02 Unit 4), not as a relevance judgement); **(2) correlation and test statistics** (Pearson `r` (linear), Spearman (monotone), point-biserial; ANOVA `F` and the regression `F` (`f_classif`, `f_regression`) with the exact relation `F = r²(n − 2)/(1 − r²)` for a single feature (derived in L3); `chi2` for non-negative count features and its requirements `[VERSION-SENSITIVE]`; **(3) mutual information** (`I(X; Y)` in nats or bits (4B-13/4C-06 recalled); **plug-in estimates for discrete variables and their positive bias**: `E[Î] ≈ (a − 1)(b − 1)/(2N)` nats under independence for `a × b` categories and `N` rows (derived in L3: the G-test relation) and the Miller–Madow correction named; **continuous variables**: binning (bin-count dependence), kernel/`k`-nearest-neighbour estimators (Kraskov-type: named `CITED [VERIFY]`); `mutual_info_classif`/`mutual_info_regression` (`discrete_features`, `n_neighbors`, added noise, `random_state`) `[VERSION-SENSITIVE]`: **estimates are noisy and slightly random; selection by top-`k` MI inherits that noise: a measured stability study with intervals**); **(4) what univariate filters miss** (interactions: XOR and products (computed and seeded); conditional relevance (a feature relevant only given another); a simple greedy implementation; evaluated on the planted support with intervals — **evidence only**); **(6) filters inside the pipeline** (fit the filter on the training fold only (Unit 1); the selected number `k` as a hyperparameter; - **L3:** **proofs, written in full:** (a) **XOR: for `x₁, x₂` i.i.d. fair bits and `y = x₁ ⊕ x₂`, `P(y = 1 | x₁) = ½` for each value of `x₁` so `I(x₁; y) = 0` (and the same for `x₂`) while `I((x₁, x₂); support-recovery and stability studies; estimator-setting sensitivity tables; spec-literal references; stable errors; no input mutation).

## Unit 3 — Recursive feature elimination and lasso selection

- **L1:** **two model-based ways to select features: *recursive feature elimination (RFE)* — fit a model, drop the weakest few features (by coefficient size or importance), refit, repeat until the desired number remain — and *the lasso* — a linear model with a penalty that pushes some coefficients exactly to zero, so selection happens during fitting**; **the lasso's dial `λ` (or `alpha`): larger `λ` → more coefficients zero; at a large enough `λ` all are zero; the *path* shows how coefficients appear as `λ` shrinks**; **a first worked example by hand: a two-feature standardised regression with an orthonormal design: the OLS coefficients, the soft-thresholded lasso coefficients at three `λ` values, and the `λ` at which each coefficient enters (computed exactly); then RFE on the six-row table**; **important cautions: standardise features before the lasso; the lasso's choice among correlated features is somewhat arbitrary; lasso coefficients are shrunken, so they are not unbiased effects; and selection by cross-validated `λ` tends to keep some noise features**; ≥ 3 worked examples.

## Unit 4 — Multicollinearity and unstable coefficients

- **L1:** **when two or more input columns carry nearly the same information (income and spending, a measurement in two units, one column derived from another) the model has a hard time deciding which one "deserves" the credit: predictions stay fine, but individual coefficients become unstable — large, of surprising sign, and different from sample to sample**; **a diagnostic: the *variance inflation factor* (VIF) of a feature measures how much its coefficient's variance is inflated because the feature can be predicted from the others**; **a first worked example by hand: two standardised features with correlation `ρ = 0.95`: the VIF (`1/(1 − ρ²) = 10.26`), the sample-to-sample correlation between the two coefficients (`−ρ`), and a tiny five-row regression where adding the second feature flips the first coefficient's sign**; **what is stable and what is not: the *sum* of two near-duplicate coefficients is well determined; their *difference* is not**; **remedies: drop or combine features, use ridge, use PCA components, or explain *groups* of features together — but remember the underlying question ("which one matters?") may have no data-supported answer**; ≥ 3 worked examples.
- **L2:** **collinearity in depth (derived/measured)**: **(1) the geometry and the symptoms** (near-linear dependence in the design matrix; condition number `κ(X)`; the symptoms: large standard errors, sign flips when a feature is added or removed, coefficients that change across bootstrap resamples, a good overall fit with insignificant individual coefficients; **prediction in-distribution is unaffected; extrapolation along the collinear direction and attribution are**); **(2) VIF and tolerance** (`VIF_j = 1/(1 − R_j²)` with `R_j²` from regressing feature `j` on the others; the variance formula `Var(β̂_j) = σ²/((1 − R_j²)Σ(x_{ij} − x̄_j)²)` (derived in L3); VIF cutoffs (5, 10) are *conventions* `JUDGEMENT` with measured behaviour on the generators, not laws); **(3) the correlation between estimated coefficients** (`Corr(β̂₁, β̂₂) = −ρ` for two standardised features: derived; the confidence ellipse as a table); **(4) estimable and non-estimable contrasts** (the variance of the sum versus the difference: `2σ²/(n(1 + ρ))` versus `2σ²/(n(1 − ρ))`: derived; a ratio of 39 at `ρ = 0.95`; how this determines what can be said about a group of correlated features); **(5) coefficient stability studies** (bootstrap the *whole* model; per-coefficient intervals, sign-agreement frequency, and rank stability; measured vs `ρ` and `n` on planted generators with a known true coefficient vector; the interval for a collinear coefficient can span both signs); **(6) remedies and their costs** (dropping a feature (omitted-variable bias if the dropped feature is truly relevant: measured); combining features (sums/ratios/domain composites); **ridge** (shrinks and stabilises: the variance reduction and bias trade-off: derived in L3 for the orthonormal-rotated case; coefficients are no longer unbiased effects); PCA regression/PLS (named; the PCA-discards-the-label caveat of 5B-05 Unit 1); elastic net (Unit 3); **grouped importance** (importance of the *group*, Unit 6); **(7) collinearity beyond linear models** (tree ensembles split credit among correlated features arbitrarily (random-forest importance dilution: measured); gradient boosting concentrates credit on whichever feature is split first; neural models (named); **the explanation methods of Units 6–8 behave differently under collinearity: permutation off-manifold evaluation, Shapley value-function choice, PDP extrapolation**: a preview table); **(8) exact collinearity and identifiability** (perfect dependence: infinitely many coefficient vectors give the same predictions; the minimum-norm solution of the pseudo-inverse and its arbitrariness; dummy-variable traps in encodings (5A-03 Unit 4)); **(9) multicollinearity and causal questions** (collinearity makes *effects* of individual features unidentifiable from observational data in the sense of Unit 4(4); a causal question about one of two near-duplicate variables cannot be answered by more modelling: it needs variation that separates them (an experiment or natural variation: `../10-…`)); **(10) reporting** (VIF/condition number tables, coefficient intervals across refits, the groups treated jointly, the remedy and its cost, and what cannot be concluded)**.
- **L3:** **proofs, written in full:** (a) **variance of an OLS coefficient: with `Var(ε) = σ²` and design `X` (with intercept), `Var(β̂) = σ²(XᵀX)^{-1}`; for coefficient `j`, `[(XᵀX)^{-1}]_{jj} = 1/(‖x̃_j‖²(1 − R_j²))` where `x̃_j` is the centred feature and `R_j²` the `R²` of regressing it on the other columns (Frisch–Waugh: the residual of `x_j` on the others has squared norm `‖x̃_j‖²(1 − R_j²)`, and `β̂_j` is the slope of `y` on that residual); hence `Var(β̂_j) = σ²/(‖x̃_j‖²(1 − R_j²))`, so the VIF `1/(1 − R_j²)` is the factor by which the variance exceeds the orthogonal-design value** — complete; (b) **two standardised features with correlation `ρ` and `XᵀX = n[[1, ρ], [ρ, 1]]`: `(XᵀX)^{-1} = (1/(n(1 − ρ²)))[[1, −ρ], [−ρ, 1]]`, so `Var(β̂_j) = σ²/(n(1 − ρ²))` (VIF `1/(1 − ρ²)`), `Corr(β̂₁, β̂₂) = −ρ`, `Var(β̂₁ + β̂₂) = 2σ²/(n(1 + ρ))`, `Var(β̂₁ − β̂₂) = 2σ²/(n(1 − ρ))`; at `ρ = 0.95` the VIF is `10.256` and the ratio of the two contrast variances is `39`** — complete (computed); (c) **ridge stabilises: in the eigenbasis of `XᵀX` with eigenvalues `d_i`, the OLS component has variance `σ²/d_i` and the ridge component `σ²d_i/(d_i + λ)²`, which is smaller for every `λ > 0` and tends to `0` as `d_i → 0` while the bias `−λβ_i/(d_i + λ)` grows; the MSE-optimal `λ` for a component is `σ²/β_i²` (derive)** — complete; (d) **exact collinearity: if `x₂ = x₁` then `XᵀX` is singular; the least-squares solutions form the affine set `{(β₁ + t, β₂ − t)}`; the pseudo-inverse returns the minimum-norm point `((β₁ + β₂)/2, (β₁ + β₂)/2)`** — complete; (e) **condition number and error amplification: relative perturbations in `y` of size `ε` can change `β̂` by up to `κ(X)·ε` in relative norm (the standard perturbation bound `CITED [VERIFY]`; a computed example)** — `CITED` with a numeric check; (f) **collinearity does not hurt in-distribution prediction: for a new row drawn from the same distribution as the training rows, the prediction variance `σ²x₀ᵀ(XᵀX)^{-1}x₀` is small because `x₀` lies in the span of the data's high-variance directions; along the low-variance direction the prediction variance is `σ²/d_min` times the squared component of `x₀` — large only for rows that violate the correlation** — complete (spectral argument); (g) **omitted-variable bias: if the true model is `y = β₁x₁ + β₂x₂ + ε` and `x₂` is dropped, the fitted slope of `x₁` converges to `β₁ + β₂·Cov(x₁, x₂)/Var(x₁)`** — complete; **counterexamples**: **a coefficient sign flip when a near-duplicate is added (seeded)**; **a bootstrap interval for one of two collinear coefficients spanning both signs while the sum's interval is tight (seeded; computed ratio 39)**; **a random forest splitting importance evenly between two copies (seeded)**; **a ridge coefficient shrunk to half its true value when stabilising (computed)**; **numerical analysis**: **spec-literal VIF (regression-based and from the inverse correlation matrix), condition numbers, coefficient-variance formulas, ridge variance, and bootstrap stability vs `statsmodels`-free formulas and scikit-learn (`LinearRegression`, `Ridge`) (agreement conditions: intercept, standardisation, `ddof`)**; **tool card** for `explainlab.collin` (VIF and tolerance via two routes; condition numbers and eigen-spectra; coefficient-correlation and contrast-variance calculators; bootstrap coefficient-stability studies (sign agreement, rank stability); ridge/PCA/grouping remedies with bias–variance reporting; planted collinear generators (controlled `ρ`, duplicates, near-duplicates, dummy traps); spec-literal references; stable errors; no input mutation).
- **L4:** **collinearity in production (an MLOps lens)**: **collinearity checks as data-contract gates on new features (a proposed feature with `VIF > threshold` triggers review: threshold documented as a convention); feature governance for derived/duplicate columns (lineage: link 5D `03`); stability reports for coefficient-based decisions (never ship a coefficient table without intervals across refits); drift in correlation structure as a monitor (a break in the correlation pattern changes the model's behaviour along the formerly-collinear direction: link 5D `12`); documentation of which features are interchangeable**; hostile inputs (perfect collinearity at serving; a feature that becomes constant; unit changes; target leakage via a derived column; dummy-variable traps; `p ≈ n`); **exhaustive verification** of the variance formula and the VIF identity **over all small designs by exact matrix inversion (`Fraction`)**, of the contrast-variance formulas **over a grid of `ρ`**, of ridge variance/bias formulas **over a grid of `(d_i, λ)`**, and of the omitted-variable bias **over small covariance matrices** (domains named and sized; `EVIDENCE ONLY`); mutation lab (VIF computed on unstandardised data incorrectly; `R_j²` from the wrong regression; coefficient intervals from a single fit; ridge penalty applied to the intercept; VIF cutoff treated as a law; correlation computed on the test set; a derived column left in the feature list) with no surviving mutants; case study: a pricing model whose coefficient table flipped signs between quarterly refits while its accuracy stayed constant, and a "driver ranking" for two near-duplicate inputs (original synthetic reproductions with grouped explanations, refit intervals, and a documented non-identifiability statement as fixes).

## Unit 5 — Model-specific versus model-agnostic explanations

- **L1:** **an *explanation* answers a question about a *fitted model*: "which features does the model rely on overall?" (global), "why did it score *this* case this way?" (local), "how does the output change as one feature changes?" (effect), "what would change the decision?" (counterfactual)**; **two ways to get one: *model-specific* methods use the model's internals (a linear model's coefficients; a tree's split paths and impurity decreases; a boosted model's gain), *model-agnostic* methods treat the model as a black box and probe it with inputs (permutation importance, Shapley/SHAP, partial dependence, surrogates)**; **a first worked example by hand: a small linear model `f(x) = 2x₁ − x₂ + 0.5x₃` and a three-row background: the coefficients as a global explanation, the local contributions `β_j(x_j − mean_j)` for one case (summing to `f(x) − mean f`), and a one-split tree's impurity-based importance for the same data**; **three things to keep in mind: an explanation describes *this model*, not the world; different explanation methods answer different questions and can disagree; and an explanation can be faithful but unstable, or stable but unfaithful**; ≥ 3 worked examples.
- **L2:** **explanation taxonomy in depth (derived/measured)**: **(1) the questions and the methods that answer them** (a table: global importance → permutation importance (Unit 6), mean `|SHAP|` (Unit 7), coefficients/gain (model-specific); **(2) intrinsic interpretability versus post-hoc explanation** (linear models, small trees, rule lists, additive models (GAMs; explainable boosting machines named): the model *is* the explanation; the interpretability–accuracy trade-off is problem-dependent and measured on the generators, not assumed; **(5) surrogate models** (a global surrogate (a shallow tree or sparse linear model fitted to `f̂`'s predictions): **fidelity** (`R²` or agreement with `f̂` on held-out rows) is the quantity to report; ## Unit 6 — Permutation importance

- **L1:** **permutation importance asks: *how much worse does the model get if I scramble this one feature?* — shuffle the column's values among the rows (breaking its link with the label), re-score the *already trained* model, and take the increase in error; a feature the model relies on causes a big increase; an ignored feature causes about none**; **a first worked example by hand: a five-row table and a fixed model: the baseline error; the error after two stated permutations of feature 1; the importance as the mean increase; the same for a noise feature (about zero, possibly slightly negative)**; **which data? score on **held-out** rows: scoring on training rows of an overfit model can show importance for features that carry no real signal**; **a caution to remember: if two features are correlated, scrambling one creates rows that never occur in real data, and importances become hard to read (one copy of a duplicated feature looks less important than the pair together)**; ≥ 3 worked examples.
- **L2:** **permutation importance in depth (derived/measured)**: **(1) the definition and the procedure** (`PI_j = L(f̂, X^{(π_j)}, y) − L(f̂, X, y)` for a loss `L` (or score decrease); repeats `R` with different permutations; mean and standard deviation (`permutation_importance` `n_repeats`, `scoring`, `max_samples`, `random_state` `[VERSION-SENSITIVE]`); cost `R·p` model evaluations on `n` rows: counted; the unit of independence (permute within groups/time blocks when rows are not exchangeable)); **(2) which data and which loss** (held-out validation/test rows (not training); the loss/score choice (accuracy, log loss, AUC, MAE): importances differ across metrics; **the model's *reliance* versus the feature's *predictive information*** (a feature can be informative but unused by this model, and used but redundant); **overfit models and training-set importance: measured on the null generator**); **(3) uncertainty** (two sources: *evaluation noise* (permutation randomness and finite test rows) and *model instability* (refits on resamples); both intervals reported and labelled; a test of `PI_j > 0` against a null built by permuting the *label* ("null importance") or by the paired difference per row; multiplicity across `p` features); **(4) correlated features** (the permuted rows are off-manifold: the model is queried where it has no data and may behave arbitrarily; **duplicate features split importance** in models that use both (computed in L3); **grouped permutation** (permute a group of correlated features jointly: the group's importance); conditional permutation (permute within bins of the correlated features) and the conditional-importance literature named `CITED [VERIFY]`; a measured study of importance of a true feature as its correlated twin's strength varies, with intervals); **(5) relation to the true effect and to model structure** (for a linear model with independent features and squared loss the importance equals `2β_j²Var(x_j)` (L3); for nonlinear/interacting models it mixes main effects and interactions; **importance is not an effect size and not a causal quantity** (Unit 9)); **(6) relation to other measures** (impurity importance (Unit 5: biased), drop-column/retrain importance (5A-12 Unit 7: a different question — "what is lost if the feature is *unavailable*" — since the model can compensate), Sobol indices (5B-01 Unit 5: variance-based, model-structure-based): a comparison table on the planted generators — **no ranking**); **(7) negative importances and small values** (noise features can have negative importance (the permuted score happens to be better): interpret with intervals; the practice of reporting only importances whose interval excludes zero); **(8) scaling and presentation** (absolute vs relative importance; normalising by the baseline loss; ranking stability across seeds: Kendall `τ` with intervals); **(9) computational shortcuts** (subsampling rows (`max_samples`); block permutations; the variance introduced; parallel evaluation with deterministic seeds); **(10) reporting** (data and background, loss, repeats, both intervals, group handling for correlated features, stability, and the limits)**.
- **L3:** **proofs, written in full:** (a) **linear model, independent features: let `y = f(x) + ε` with `f(x) = β₀ + Σβ_jx_j`, the model equal to `f`, squared loss, and `x_j′` an independent copy of `x_j`; - **L4:** **permutation importance in production (an MLOps lens)**: **importance reports as scheduled artifacts computed on a fixed held-out window with stored seeds; monitoring importance drift (a shift in which features the model relies on (with intervals) is a model-behaviour change: link 5D `12`); correlated-feature policies (groups defined in the feature registry); governance of "global importance" claims (always accompanied by intervals over refits); cost control (subsampling policy with a measured variance impact); avoiding misuse (importance is not a feature-removal recommendation: use retrain-based ablations: 5A-12 Unit 7)**; hostile inputs (constant features; categorical features with rare levels; time-ordered rows; duplicate rows; features that are deterministic functions of others; metrics undefined on a permuted sample (single-class folds); `NaN`); **exhaustive verification** of the linear closed form **by exact enumeration over all permutations of tiny tables**, of the duplicate-feature split **over a grid**, of the interpolating-model training-importance claim **over all tiny tables with a 1-NN model**, and of the grouped-permutation covariance formula **over small covariance matrices** (domains named and sized; `EVIDENCE ONLY`); mutation lab (importance on training rows; scoring direction reversed; one permutation reported; groups ignored for correlated features; refit instability omitted; permuted column not restored between features; metric changed between baseline and permuted evaluation) with no surviving mutants; case study: a "top feature" list from a single permutation on training data of an overfit model, and importances that halved when a duplicate column was added to the schema (original synthetic reproductions with held-out evaluation, grouped permutation, and refit intervals as fixes).

## Unit 7 — SHAP and feature attribution

- **L1:** **Shapley values come from game theory: share a "payout" (here, the difference between a model's prediction for a case and its average prediction) fairly among "players" (features) by averaging each feature's added contribution over all the orders in which features could be revealed**; **properties that make the sharing "fair": the shares add up to the total (*efficiency*), features that never change the output get zero (*dummy*), identical features get equal shares (*symmetry*)**; **SHAP applies this to model predictions: each feature gets a number for a specific case — positive pushes the prediction up from the average, negative pushes it down — and the numbers sum to `f(x) − E f`**; **a first worked example by hand: a three-feature model with a stated function and a two-row background: all `2³ = 8` coalition values `v(S)`, the six permutation orders, the three Shapley values for one case, and the efficiency check (computed exactly with `Fraction`)**; **three cautions to carry: SHAP explains the *model's* prediction relative to a *background*, not causes; the background matters; and with correlated features the "fair sharing" depends on how missing features are filled in**; ≥ 3 worked examples.
- **L2:** **Shapley attribution in depth (derived/measured)**: **(1) the definition** (`φ_j(x) = Σ_{S ⊆ N∖{j}}[|S|!(p − |S| − 1)!/p!]·[v(S ∪ {j}) − v(S)]`; equivalently the average of marginal contributions over all `p!` orderings; the four axioms (efficiency, symmetry, dummy, additivity) and the uniqueness theorem `CITED [VERIFY]`; recalled from 5A-12 Unit 7 where the same value attributes ablation gains: **here the "players" are features and the value function is a model output**); **(2) the value function — the decision that defines the explanation** (**interventional/marginal**: `v(S) = E_{X_{S̄} ∼ B}[f(x_S, X_{S̄})]` — missing features are filled by background draws *independently of* `x_S`; **conditional/observational**: `v(S) = E[f(X) | X_S = x_S]` — missing features are drawn conditional on the present ones; they coincide for independent features and differ under correlation: a computed two-feature Gaussian example; the interventional choice respects the model (a feature unused by the model gets zero) but queries off-manifold points; the conditional choice respects the data but can assign credit to features the model never uses: **state which is used in every report**; baseline value `v(∅) = E_B f`); **(3) exact computation** (enumerate `2^p` coalitions each needing `|B|` model calls for the interventional version: `2^p|B|` evaluations counted before running; exact for `p ≤ 14`; the learner's exact implementation is the oracle for all other estimators); **(4) estimation** (permutation-sampling estimators (sample orderings, average marginal contributions): unbiased with variance `σ²_φ/M` for `M` sampled orderings; antithetic/stratified variants named; **Kernel SHAP**: a weighted linear regression on coalition indicators with the Shapley kernel `π(z) = (p − 1)/(C(p, |z|)|z|(p − |z|))` `CITED [VERIFY]`, whose solution equals the Shapley values (the learner implements it for small `p` and checks equality with the exact values); **TreeSHAP**: polynomial-time exact computation for tree ensembles under the *path-dependent* (tree-conditional) value function and the interventional variant `CITED [VERIFY]`; the algorithm's idea described and a brute-force-equivalent check on tiny trees; **the value function it implements must be stated** `[VERSION-SENSITIVE]` for any library); **(5) closed forms and sanity checks** (linear model with the interventional value function and a background sample: `φ_j(x) = β_j(x_j − B̄_j)` exactly, **with or without correlation** (L3); additive model: `φ_j(x) = f_j(x_j) − E_B f_j(X_j)`; the dummy and symmetry checks as tests; the *explainer validation rule*: run the explainer on these known models first); **(6) global importance from local values** (mean `|φ_j|` over held-out rows; its relation to permutation importance and to variance shares (a comparison on the planted generators — **no ranking**); sums of absolute values hide sign structure; dependence plots as tables); **(7) interactions** (an XOR-style model: the pair's contribution is split equally between the two features by symmetry — the attribution says "both matter", not "jointly"; Shapley *interaction* indices (named `CITED [VERIFY]`; a simple pairwise implementation for small `p`)); **(8) output space and additivity** (log-odds vs probability vs regression units (Unit 5(9)); contributions sum to `f(x) − E f` in the chosen space; averaging across ensemble members is linear; probability-space attributions are not log-odds attributions passed through `σ`); **(9) the background distribution** (a sample of training rows; its size (the variance/bias trade-off: measured) and representativeness; **single-point baselines versus distribution backgrounds** (baseline-dependent contributions: `φ` changes when the baseline changes); k-means summaries of backgrounds named; the leak rule: the background comes from training rows only); **(10) limitations, stated plainly** (not causal (Unit 9); off-manifold queries under the interventional choice; instability across refits; sensitivity to the background; manipulability (adversarial models that detect explanation queries: named `CITED [VERIFY]`, awareness only); the `2^p` cost; the credit-splitting of duplicates); **(11) reporting** (value function, background (size, source, hash), output space, estimator and its error, exact-versus-estimated check on a subsample, refit stability, and the causal-limits statement)**.
- **L3:** **proofs, written in full:** (a) **efficiency: `Σ_jφ_j(x) = v(N) − v(∅) = f(x) − E_Bf` (the sum over a permutation of the marginal contributions telescopes to `v(N) − v(∅)`; averaging over orderings preserves it)** — complete (recalled from 5A-12 Unit 7(c); for `ρ = 0.9`, `x = (1, 1)`: `φ₂^{cond} = ½(0.9 − 0) + ½(1 − 1·1…)`-type: compute exactly via the two orderings (`φ₂ = ½[(v({2}) − v(∅)) + (v({1,2}) − v({1}))] = ½[0.9 + 0] = 0.45`)** — complete (computed); (h) **permutation-sampling estimator: for `M` independent uniform orderings, `φ̂_j = (1/M)Σ_mΔ_j^{(m)}` is unbiased with variance `Var(Δ_j)/M`; the number of orderings for a target standard error `ε` is `M ≥ Var(Δ_j)/ε²`** — complete; ## Unit 8 — Partial dependence and ICE

- **L1:** **partial dependence (PD) shows how the model's *average* prediction changes as one feature (or two) is varied across a range of values while the other features keep their real values from the data: for each grid value `z`, set the feature to `z` in *every* row, predict, and average**; **ICE (individual conditional expectation) curves show the same thing for each row separately — one line per case — so you can see whether cases respond differently**; **a first worked example by hand: a four-row table and the model `f(x) = x₁x₂`: the PD of feature 1 (the average of `z·x₂` over rows: flat if `x₂` averages zero) and the four ICE lines with slopes `x₂` — opposite slopes that cancel in the average**; **what PD can hide (interactions) and what it can invent (predictions at unrealistic combinations when features are correlated)**; **PD describes the *model*, not the world**; ≥ 3 worked examples.
- **L2:** **PDP, ICE, and ALE in depth (derived/measured)**: **(1) definitions and computation** (`PD_S(z) = E_{X_C}[f(z, X_C)]`, estimated by `(1/n)Σ_if̂(z, x_{iC})`; grid choice (quantile-based vs equal-width), resolution, and range (do not extend beyond the data's support); cost `grid × n` evaluations (counted; subsampling rows); `partial_dependence` `kind` (`'average'`, `'individual'`, `'both'`), `grid_resolution`, and `method` (`'brute'` vs `'recursion'` (tree-specific, with different background semantics) `[VERSION-SENSITIVE]`); classification PD in log-odds vs probability (Unit 5(9))); **(2) ICE and centred ICE** (one curve per row; **centring** curves at a reference value to compare shapes; heterogeneity: lines of different slope or crossing indicate interactions (a seeded demonstration with a planted interaction); derivative-ICE named; clustering ICE curves named; subsampling and the loss of tail rows); **(3) what PD means and what it hides** (PD equals the main effect plus the *average* of the interactions with the other features: for an additive model PD recovers `f_j` up to a constant (L3); for `f = x₁x₂` with mean-zero `x₂` the PD is flat while every ICE line has slope `±|x₂|`: the *absence* of an average effect is not the absence of an effect); **(4) the correlated-features problem** (PD averages over the *marginal* of the other features, evaluating the model at combinations that may not occur (e.g., height 2 m with weight 30 kg): the model's behaviour there is arbitrary; a measured example where PD shows a spurious dip; **accumulated local effects (ALE)** (Apley–Zhu) `CITED [VERIFY]`: average *local differences* of predictions within narrow bins of the feature using only *actual neighbouring* data, then accumulate and centre; the learner's from-scratch ALE for numeric features compared with PD on correlated generators: ALE recovers the additive component without off-manifold queries (L3); limits: ALE's interpretation near sparse bins; interactions via second-order ALE (named)); **(5) two-way PD and interaction strength** (2-D PD tables; **Friedman's `H`-statistic** (the share of the variance of the joint PD not explained by the sum of the one-way PDs) `CITED [VERIFY]` implemented for small cases; cost `grid²·n`; instability: measured); **(6) PD for diagnosing and testing models** (monotonicity checks against domain knowledge; detecting extrapolation artefacts; comparing PDs of two models; **a PD that looks sensible is not evidence the model is right**); **(7) uncertainty** (PD/ICE are functions of one fitted model: intervals across bootstrap *refits* (the PD band as a table) show model instability; the band across *rows* (ICE spread) shows heterogeneity: **distinguish the two**); **(8) categorical and mixed features** (PD by category; ordering; interactions with numeric features); **(9) relation to causal effects** (PD is the model's *predictive* dose–response; it equals a causal dose–response only under strong assumptions (no unobserved confounding, the model captures the structural equation): Unit 9 and `../10-…`); **(10) reporting** (feature, grid, background rows, evaluation space, ICE sample, refit bands, correlation caveats, ALE cross-check)**.
- **L3:** **proofs, written in full:** (a) **PD of an additive model: `f(x) = Σf_i(x_i)` gives `PD_j(z) = f_j(z) + Σ_{i≠j}E[f_i(X_i)]`, i.e., `f_j(z)` up to an additive constant** — complete; (b) **PD of a product: for `f(x) = x₁x₂`, `PD₁(z) = zE[X₂]` and `ICE_i(z) = z·x_{i2}`; if `E[X₂] = 0` the PD is identically zero while the ICE slopes are `x_{i2}`; the variance of ICE slopes across rows is `Var(X₂)`** — complete; (c) **PD under correlation evaluates off-manifold: for `X₁, X₂` with correlation `ρ → 1` and `f(x) = x₁ − x₂` (zero on the data manifold `x₁ ≈ x₂`), the PD of feature 1 is `z − E[X₂] = z − μ`, a line with slope 1 although along the data the model output is `≈ 0`; the interpretation "the model's output changes with `x₁`" is true for the *model* but describes inputs that do not occur** — complete (a computed example); (d) **ALE for an additive model with correlated features: the ALE of feature `j` is `∫E[∂f/∂x_j | X_j = t]dt` (centred); ## Unit 9 — Explanation stability and causal limitations

- **L1:** **two reasons to be careful with explanations: they can be *unstable* (rerun the training with another seed, another sample, or another correlated feature and the "top features" change) and they are *not causal* (a feature the model relies on need not cause the outcome, and changing it need not change the outcome)**; **stability in plain words: refit the model (or the whole pipeline) on resamples of the data and recompute the explanation; if the ranking of important features keeps changing, treat the ranking as unreliable**; **the causal caution in plain words: a model uses whatever predicts — including *proxies* and *effects* of the outcome; an explanation reports what the model uses, not what *produces* the outcome; "removing the feature from the model" and "changing the feature in the world" are different things**; **a first worked example by hand: a small world where `x₂ = x₁ + noise` and `y = x₁ + noise`: a model using `x₂` predicts well and its explanation says `x₂` is important; changing `x₂` in the world (intervening) does nothing to `y`; then five bootstrap refits and the importance ranks across them**; **why this matters: decisions based on explanations ("raise this feature to improve the outcome") can be wrong**; ≥ 3 worked examples.
- **L2:** **stability and causal limits in depth (derived/measured)**: **(1) sources of instability** (training randomness (seeds, subsampling); data sampling (bootstrap); hyperparameters; correlated features and the Rashomon effect (Unit 5(6)); the explanation method's own randomness (permutations, background samples, sampling estimators); small-sample noise); **(2) measuring stability** (**refit stability**: re-run the *whole* pipeline (including selection) on `B` bootstrap/subsample refits and recompute the explanation: per-feature interval and rank distribution; **rank agreement** (Kendall `τ`, Spearman: 5B-01 Unit 5 recalled) and **top-`k` Jaccard** between refits with intervals; sign agreement for signed attributions; **local stability** (the change in a case's attribution under small input perturbations: a Lipschitz-style ratio estimated by sampling; large ratios indicate fragile explanations); the **stability-versus-fidelity trade-off** (smoothing can stabilise but blur); a measured study on the planted generators of stability versus `n`, correlation, and model class with intervals — **evidence only**); **(3) reporting stability honestly** (report bands, not point rankings; flag features whose rank interval overlaps their neighbours'; refuse to publish an ordering whose rank intervals overlap beyond a stated margin (a pre-registered rule, `HEURISTIC`)); **(4) explanations are associational** (the what-is-being-explained convention: model + background + question; **importance ≠ effect of intervention**); **(5) planted structural causal models** (a library of small SCMs with known graphs: **proxy/effect features** (a feature caused by the outcome predicts it perfectly but cannot be intervened on to change it); **confounded predictors** (a common cause makes two features predictive of each other and of `y`); **mediators** (the feature's total causal effect passes through another feature: including both splits attribution); **colliders** (conditioning induces association: including a collider as a feature creates misleading importance); each shown with the *true* interventional effects, the model's importances/attributions, and their disagreement, over seeds with intervals); **(6) non-identifiability from observational data** (different causal structures can produce the same joint distribution (computed in L3: `x → y` versus `y → x` for a bivariate Gaussian), so no explanation of a model fitted on observational data can distinguish them; what would: interventions, experiments, natural experiments, or strong structural assumptions: `../10-…`); **(7) proxies and sensitive attributes** (removing a sensitive attribute from the inputs does not remove its influence if proxies remain: a planted proxy generator with known proxy strength; a **proxy audit** (predict the sensitive attribute from the remaining features on held-out rows: its AUC measures leakage); explanation methods applied to the sensitive attribute and to its proxies; why "the model does not use gender" is a claim about inputs, not about outcomes (awareness only; formal fairness criteria are out of scope; no legal claims)); **(8) explanations and model risk** (documented limits; misuse scenarios (using importances for causal policy; using recourse as promises; using explanations to certify fairness); adversarial manipulation of explanations (named `CITED [VERIFY]`); explanation drift monitoring); **(9) validating explanations against planted truth** (for models with known mechanisms: rank/sign/magnitude agreement with the *true* effects, the share of important-by-model features with zero true effect (the *spurious-importance rate*); both over ≥ 30 seeds with intervals; the null generator: any "important" feature is spurious); **(10) reporting** (stability bands, the causal-limits statement, proxy audit, spurious-importance rate on the bench, and the permitted uses of the explanation)**.
- **L3:** **proofs, written in full:** (a) **the proxy example: `x₁ ∼ N(0, 1)`, `x₂ = x₁ + 0.1ε₂`, `y = x₁ + ε_y` with independent unit-variance noise; a model fitted on `x₂` alone has `R² = Var(x₁)/(Var(x₁) + 0.01 + Var(ε_y)·…)` — compute: `Cov(x₂, y) = 1`, `Var(x₂) = 1.01`, `Var(y) = 2`, so `R² = 1/(1.01·2) = 0.495`; under the structural equations, `do(x₂ = a)` leaves `y`'s distribution unchanged (`y` does not depend on `x₂`), so the causal effect of `x₂` is `0` while its predictive importance is large** — complete (computed); (b) **non-identifiability: for the bivariate Gaussian `(X, Y)` with correlation `ρ`, the models `X → Y` (`Y = ρX + √(1 − ρ²)ε`) and `Y → X` (`X = ρY + √(1 − ρ²)ε′`) induce *exactly the same* joint distribution; the interventional effect of `X` on `Y` is `ρ` in the first and `0` in the second** — complete (check means, variances, and covariance); (c) **a collider induces association: `X, Z` independent, `C = X + Z + ε`; `Corr(X, Z) = 0` but `Corr(X, Z | C) ≠ 0` (`= −1/√(…)`: compute `Cov(X, Z | C) = −Var(X)Var(Z)/Var(C)`), so a model that includes `C` makes `X` predictive of `Z` and an explanation attributes importance to `X` for predicting `Z`** — complete (Gaussian conditioning); (d) **mediator splitting: with `X → M → Y`, `M = X + ε_M`, `Y = M + ε_Y`, a model with both `X` and `M` uses only `M` (since `Y` is independent of `X` given `M`); the explanation gives `X` zero importance though its total causal effect on `Y` is `1`** — complete (conditional independence); (e) **Kendall's `τ` between two refit rankings of `p` features: `τ = (C − D)/C(p, 2)` for no ties; under independent random rankings `E[τ] = 0` and `Var(τ) = 2(2p + 5)/(9p(p − 1))`; for `p = 10` the standard deviation is `0.236` (computed) — a baseline for judging observed stability** — complete for the mean; `CITED [VERIFY]` for the variance formula, checked by exact enumeration for `p ≤ 7`; (f) **top-`k` overlap baseline (recalled from 5B-05 Unit 5(f)): for independent random top-`k` sets from `p` features, `E|A ∩ B|/k = k/p`; stability above this baseline is the meaningful quantity** — complete (recalled); (g) **proxy leakage: if the sensitive attribute `s ∈ {0, 1}` is predictable from the remaining features with AUC `a`, then a model using those features can encode `s`: by the data-processing inequality, `I(ŷ; s) ≤ I(X_rest; s)`, and `I(X_rest; s) > 0` whenever `a > ½`; removing `s` from the inputs does not bound the dependence of predictions on `s`** — complete; **counterexamples**: **`R² = 0.495` explanation for a variable with zero causal effect (computed)**; **identical joint distributions with opposite interventional effects (computed)**; **a collider making `X` "important" for predicting `Z` (computed)**; **a mediator receiving zero importance with total effect 1 (computed)**; **a top-3 feature set changing across refits (seeded; Jaccard with interval)**; **a proxy audit AUC of 0.8 after removing the sensitive column (seeded)**; **numerical analysis**: **spec-literal refit-stability measures, Kendall `τ` with exact null distribution, local-Lipschitz estimators, SCM generators with exact interventional effects, spurious-importance rates, and proxy audits vs SciPy (`kendalltau`, `spearmanr`) and exact enumeration**; **tool card** for `explainlab.stability` (refit-stability harness over the whole pipeline with named-key resamples; rank/sign/top-`k` agreement with chance baselines; local-sensitivity estimators; planted SCM library (proxy, confounder, mediator, collider, non-identifiable pairs) with exact interventional effects; spurious-importance and attribution-error scorers; proxy-audit tools; explanation-risk register builder; spec-literal references; stable errors; no input mutation).
- **L4:** **explanation risk management (an MLOps lens)**: **a model-risk register entry for every deployed explanation (permitted uses, prohibited uses, stability evidence, proxy audit, review cadence: link 5D `14-Production-Reliability-Security-and-Governance`); stability gates in CI (a pre-registered minimum agreement versus the baseline for any published ranking); monitoring explanation drift (shifts in attribution distributions with intervals: link 5D `12`); change control (a new model version re-runs the explanation validation and the proxy audit); communication standards (language that separates "what the model uses" from "what causes"); incident handling when an explanation is misused**; hostile inputs (tiny `n` making all rankings unstable; degenerate rankings with ties; a sensitive attribute encoded in free text or IDs; features whose meaning changed; correlated groups with no stable leader; explanations requested for out-of-support inputs); **exhaustive verification** of the proxy/non-identifiability/collider/mediator computations **by exact Gaussian moment calculations (`sympy`)**, of the Kendall `τ` mean and variance **by enumeration over all pairs of rankings for `p ≤ 7`**, and of the top-`k` baseline **by exact hypergeometric enumeration** (domains named and sized; `EVIDENCE ONLY`); mutation lab (stability measured on one fit; explanation ranking published despite overlapping intervals; refits that skip the selection step; proxy audit run on training rows; causal language in the report; collider included as a feature without a flag; SCM truth leaked to the explainer) with no surviving mutants; case study: a "driver analysis" slide used to justify a policy intervention on a proxy variable, and a top-5 feature list that changed in four of five refits (original synthetic reproductions with stability bands, SCM-based validation, and a stated causal-limits section as fixes).

## Unit 10 — Counterfactual explanations and recourse

- **L1:** **a *counterfactual explanation* answers: "what is the smallest change to this case that would change the model's decision?" (e.g., "the loan would be approved if income were 8,000 higher and the number of open accounts were 1 lower")**; **an *actionable recourse* is a counterfactual the person can actually carry out: it must change only features they can change, in directions that are possible, at a cost they can bear**; **a first worked example by hand: a linear scoring model `f(x) = wᵀx + b` with `f(x) < 0` meaning "decline": the closest point on the decision boundary (the formula `x′ = x − f(x)w/‖w‖²`), its distance `|f(x)|/‖w‖`, and a *sparse* alternative that changes only the single feature with the largest `|w_j|`; then the same case with one feature marked immutable**; **what can go wrong: the nearest point may be unrealistic or impossible (negative age); the nearest *model* flip may not change the real outcome; the advice can be invalid after the model is retrained; and providing counterfactuals can reveal how the model works**; ≥ 3 worked examples.
- **L2:** **counterfactuals and recourse in depth (derived/measured)**: **(1) formulations** (find `x′` minimising `d(x, x′)` subject to `f̂(x′) ≥ τ` (target decision) and constraints `x′ ∈ 𝒞`; Wachter-style relaxation (penalise the prediction gap); distance choices: `L₁` (sparse changes), `L₂`, MAD-scaled `L₁` (feature-scale-aware), per-feature **costs** (some changes are harder): a table of how each distance changes the answer); **(2) constraints** (**immutable** features (e.g., birth year); **monotone** features (age can only increase); **bounds and valid values** (categorical levels, integer counts); **causal consistency** (changing income may change other features downstream: recourse that ignores causal effects can be infeasible or misleading `CITED [VERIFY]` (Karimi et al.); a planted SCM where naive counterfactuals are inconsistent with the causal structure); **plausibility** (stay near the data manifold: a density or nearest-neighbour penalty; the trade-off with proximity)); **(3) algorithms** (**closed forms**: linear models (L3); **exact for trees**: a tree partitions the space into axis-aligned boxes (leaves); the nearest point in a target-decision leaf is the projection onto the box (exact for any `L_p`); minimise over target leaves; ensembles: combinatorial (named) — the learner's exact tree algorithm and a gradient-free search (random restarts + local search, or a genetic/greedy single-feature search) for general models, evaluated against the exact answers on tiny trees and linear models; counts of model evaluations; **diversity** (several different counterfactuals: DiCE-style named `CITED [VERIFY]`)); **(4) metrics for counterfactual quality** (**validity** (the decision actually flips under `f̂`), **proximity** (distance), **sparsity** (number of features changed), **plausibility/feasibility** (constraint and manifold checks), **actionability** (only mutable features, within bounds), **stability** (similar inputs → similar counterfactuals), **cost** (the sum of per-feature costs): reported with intervals over test instances; **validity under the *true* mechanism** (planted SCMs: does the *real* outcome change when the person acts on the recourse? — often not): measured); **(5) recourse is model-dependent and time-dependent** (**retraining or model updates can invalidate previously issued recourse**: the share of issued recourses still valid after a refit (measured with intervals); robust recourse (margin beyond the boundary) named `CITED [VERIFY]` with the cost trade-off; communicating validity windows); **(6) strategic behaviour and gaming** (if people act on recourse, the data distribution shifts; features that are cheap to change but uninformative become exploitable (Goodhart-style effects): named, awareness only; the designer's responsibility to prefer causally meaningful recourse); **(7) fairness of recourse** (the *cost* of recourse by group (the distance/cost to cross the boundary): a measured disparity on a planted generator with a group whose features are costlier to change; reporting by group with small-cell suppression; awareness only; no legal claims); **(8) security and privacy** (counterfactuals reveal the decision boundary: **model extraction and membership-inference risks** with many queries (named `CITED [VERIFY]`; a measured demonstration of boundary recovery from `q` counterfactual queries on a linear model); rate limits and coarsening as mitigations with their costs); **(9) counterfactuals versus other explanations** (attributions say *why this score*; counterfactuals say *what would change it*; contrastive framing; when each is appropriate); **(10) reporting** (formulation, constraints, algorithm, validity/proximity/sparsity/actionability with intervals, validity under the true mechanism on the bench, post-retrain validity, group cost disparity, and the permitted use of the recourse)**.
- **L3:** **proofs, written in full:** (a) **nearest boundary point for a linear model in `L₂`: minimise `‖x′ − x‖²` subject to `wᵀx′ + b = 0`; the Lagrangian gives `x′ − x = −λw` with `λ = (wᵀx + b)/‖w‖²`, so `x′ = x − ((wᵀx + b)/‖w‖²)w` and `‖x′ − x‖₂ = |wᵀx + b|/‖w‖₂`; a strictly flipped point is obtained by moving a small margin past the boundary** — complete; (b) **nearest boundary point in `L₁` (sparse changes): `min‖δ‖₁` subject to `wᵀδ = −s` (`s = wᵀx + b`) has optimal value `|s|/‖w‖_∞`, attained by changing only the coordinate with the largest `|w_j|`: `δ_j = −s/w_j`; proof by Hölder: `|s| = |wᵀδ| ≤ ‖w‖_∞‖δ‖₁` with equality for the stated `δ`** — complete; (c) **with feature costs `c_j > 0` (weighted `L₁`: `Σc_j|δ_j|`), the optimal single-coordinate change picks `j* = argmax_j|w_j|/c_j` with cost `|s|·c_{j*}/|w_{j*}| = |s|/max_j(|w_j|/c_j)`** — complete (weighted Hölder/ratio argument); (d) **immutable features: restricting `δ_j = 0` for `j ∈ I` gives the same results with `w` replaced by its mutable coordinates; if all mutable `w_j = 0` the problem is infeasible — a decision that *cannot* be flipped by recourse (a computed example)** — complete; (e) **tree counterfactuals are exact: a tree defines leaves as boxes `B_ℓ = ∏_j[l_{ℓj}, u_{ℓj}]` with a predicted class; for a target-class leaf, the minimiser of `‖x′ − x‖_p` over `x′ ∈ B_ℓ` is the coordinate-wise projection `x′_j = clip(x_j, l_{ℓj}, u_{ℓj})` for every `p ≥ 1` (the box is a product of intervals and the norm is monotone in each coordinate's deviation); the optimal counterfactual is the best over target leaves (strict inequalities `x′_j > l`/`≤ u` handled by an `ε`-margin)** — complete; (f) **post-retrain validity: if the boundary is perturbed from `w` to `w + Δw` and a recourse lands at distance `m` (margin) from the original boundary along the unit normal, the recourse remains valid iff the perturbation moves the boundary by less than `m` at that point; for random Gaussian perturbations of the normal, the probability of validity is `Φ(m/σ_Δ)`-type (state for a one-dimensional boundary shift `N(0, σ²_Δ)`: `Φ(m/σ_Δ)`); a computed table** — complete for the one-dimensional shift model; (g) **boundary recovery from queries: a linear classifier `sign(wᵀx + b)` in `ℝ^p` is determined (up to positive scale) by `p + 1` boundary points in general position (the points satisfy `wᵀx_i + b = 0`, a homogeneous linear system in `(w, b)` of rank `p`); hence `p + 1` exact counterfactuals on the boundary reveal the model up to scale** — complete (linear algebra); **counterexamples**: **the nearest counterfactual changing an immutable attribute (computed)**; **a counterfactual valid under the model and invalid under the true mechanism (planted SCM; computed/seeded)**; **a recourse invalidated by a retrain (seeded; measured share still valid)**; **a group whose recourse cost is a multiple of another's (seeded)**; **boundary recovery from `p + 1` counterfactuals (computed)**; **numerical analysis**: **spec-literal linear closed forms (`L₁`, `L₂`, weighted), exact tree-box projection with margins, general-model local search, validity/proximity/sparsity metrics, and post-retrain validity estimators vs exact enumeration and `dice-ml` only if installed (agreement conditions: distance, constraints, margin)**; **tool card** for `explainlab.counterfactual` (counterfactual search for linear (closed form), tree (exact box projection), and general models (constrained local search); constraint sets (immutable, monotone, bounds, categorical levels); causal-consistency checks on planted SCMs; validity/proximity/sparsity/actionability/cost metrics with intervals; post-retrain validity and robust-margin studies; group cost-disparity reports with suppression; boundary-recovery demonstrators; planted-truth studies; spec-literal references; stable errors; no input mutation).
- **L4:** **recourse as a governed product feature (an MLOps lens)**: **recourse services as versioned components (model hash, constraint set, cost function, validity window; counterfactuals re-validated on every model release;
