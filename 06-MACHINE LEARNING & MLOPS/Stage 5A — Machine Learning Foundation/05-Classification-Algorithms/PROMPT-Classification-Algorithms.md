## Unit 2 — Logistic regression and decision boundaries

## Unit 7 — Support vector machines: margins and kernels

# 8. UNIT 12 — PROJECT 01: CLASSIFICATION ALGORITHM COMPARISON (REQUIREMENTS)

**Target file:** `Projects/01-classification-algorithm-comparison.md`. Apply the four levels and N.0–N.14. It builds **`clfbench`**: a reproducible benchmark and reporting harness that fits, tunes (inside the pipeline), thresholds, and compares the module's classifiers on original synthetic datasets with known structure, **with leak-safe pipelines, paired comparisons, cost-based decisions, calibration tables, cost counters, and a failure map** — and **never produces an algorithm ranking beyond the datasets it ran on**. It teaches **no new algorithm**; it teaches **benchmarking and reporting classifiers honestly**. It reuses `classlab` tools from the lessons and `prepkit`/`prepline`, `edalab`/`edareport`, `reglab`/`regbench`, and `mlsmoke`/`framebase` from earlier modules (**map, do not duplicate**).

**Required components:**
1. **Datasets (original, seeded, with ground-truth manifests).** **At least eight synthetic classification datasets**: **(a) two Gaussian classes with equal covariance (LDA and logistic are well specified); (b) Gaussian classes with unequal covariances (QDA is well specified); (c) nonlinear classes (moons- and ring-shaped from your own generators); (d) five near-duplicate informative features plus independent ones (Naive Bayes over-confidence); (e) `p > n` with a few informative features; (f) 1–3% positive rate with a cost matrix; (g) five-class with unequal priors and a confusable pair; (h) a small multilabel table with correlated labels**; each with a documented generator, true class-conditional structure, a data dictionary (5A-02 Unit 9), and a planted-issue manifest (scale disparity, duplicates, separation).
2. **Models.** **Baselines (majority/prior/stratified)**, **logistic regression (L2 and L1, `C` chosen inside the pipeline)**, **softmax and OvR/OvO builders**, **k-NN (`k`, metric, weights chosen inside the pipeline)**, **Gaussian/Bernoulli/Multinomial Naive Bayes**, **linear and RBF SVMs (`C`, `γ` chosen inside the pipeline)**, **LDA/QDA with shrinkage**, and **binary-relevance multilabel**; each implemented with the `classlab` spec-literal reference where one exists and compared with the scikit-learn estimator (the comparison is part of the verification).
3. **The benchmark protocol (the module's standard).** **One structure-aware split definition per dataset (stratified/group/time where relevant; hash-based; manifest stored); train/validation/test partitions; all learned statistics (including scalers, hyperparameters, and thresholds) from training and validation rows only; every model inside one pipeline artifact; ≥ 30 repeated splits (seeds listed) for any claim about differences; paired bootstrap or exact McNemar for model-vs-baseline and model-vs-model comparisons on the same held-out rows; metrics defined minimally: accuracy, per-class precision/recall, log loss, and the cost-weighted error of the stated cost matrix (each with `n` and an interval); thresholds selected on validation data by the cost rule; no best-seed or best-model selection on the test set; a lockbox test evaluation at the end.**
4. **Decision and calibration studies.** For each dataset with a cost matrix: **the cost-derived threshold vs 0.5 vs class weights, with expected cost and intervals; reliability tables (Wilson intervals) for every model that emits probabilities; abstention coverage–risk tables; the effect of a prevalence shift on the optimal threshold (the Unit 4 map vs measured)**.
5. **Cost and failure map.** **Operation counters and memory estimates for every model; scaling-exponent studies with bootstrap intervals (timings at the CLI edge with spread); the failure-mode gallery run on the planted manifests: which model breaks on which dataset, with the detection test that flagged it and the remedy lesson**; separate tuning and evaluation seed sets (stated).
6. **Verification.** `pytest` suites with **exhaustive small-domain tests** (the Unit domains: Bayes/cost decisions, Newton fixed points and separation, softmax identities, thresholds and prevalence map, k-NN and LOO, Naive Bayes exact posteriors, tiny SVM max-margin, LDA/QDA discriminants, operation counters), **seeded random tests with stated tolerances**, **adversarial inputs** (single class; class with one row; unseen labels; separable data; singular covariance; `n < p`; duplicate rows across splits; `NaN`; unscaled features; huge `n` for kernels (guard)), and **property tests** (the pipeline never mutates its input; the `classes_` contract holds; predictions are invariant to feature order when columns are selected by name; softmax outputs sum to 1; k-NN predictions are invariant to row order of the training set under the stated tie rule; repeating a run with the same seeds gives identical results across two processes).
7. **Mutation analysis.** A **mutation lab** (planted: scaler fitted on all rows; positive class swapped; `C` used as regularisation strength; threshold chosen on the test set; class weights read as calibrated; OvR scores treated as probabilities; unpaired interval for paired data; duplicates not removed before the split; baseline fitted on all rows; kernel matrix unguarded; Naive Bayes probabilities not log-space; cost matrix transposed) with **no surviving mutants**, and a **regression guard**.
8. **Reproducibility and packaging.** `clfbench verify` (supports `--quick`; disk cap; PASS/FAIL list); `pyproject.toml` (local editable install only); fresh-`venv` contract; no network after install; sizes capped; passes without optional libraries; a run manifest reusing the 5A-00 format (versions, seeds, config hash, dataset hashes).
9. **Documentation.** A package-layout mermaid diagram; an API reference; a **library card** (scope, tested domains, tolerances, versions, limits, "teaching benchmark — results hold for these synthetic datasets only; not a general ranking of classification algorithms"); a **report template** for the learner's own results with a blank template and a clearly labelled `[ILLUSTRATIVE]` synthetic example; **never fabricated results**; **every figure has a text description**; **a classifier card per fitted model**.

**Rubric (provide in full):** requirements traceability; correctness (spec-literal oracle agreement); leak-safety and protocol discipline (split structure, learned state, thresholds chosen on validation, test touched once); statistical honesty (paired comparisons, intervals, ≥ 30 seeds, no cherry-picking); decision quality (cost-derived thresholds; calibration tables; abstention); cost-and-failure analysis; honesty of claims (no general ranking); test and mutation strength; reproducibility; documentation and library card; honesty of the report; integrity statement.
