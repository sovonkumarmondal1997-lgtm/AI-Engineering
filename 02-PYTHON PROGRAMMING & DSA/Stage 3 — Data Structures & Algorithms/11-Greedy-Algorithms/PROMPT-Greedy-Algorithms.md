## Unit 1 — Greedy algorithm fundamentals
- **L1:** the **greedy idea**: build a solution **one irrevocable step at a time**, always taking the **locally best-looking** choice; no backtracking, no table of subproblems; why it is attractive (simple, fast — usually `O(n log n)` from a sort or heap) and why it is dangerous (**the locally best choice is not always globally best**); first examples by hand: **making change with coins `{25, 10, 5, 1}`** (works) and with **`{1, 3, 4}` for amount 6** (greedy gives 4 + 1 + 1 = 3 coins; the optimum is 3 + 3 = 2 coins — S3-09 Unit 1 link), **assign cookies** (smallest cookie that satisfies the least greedy child), **boats to save people** (pair the lightest with the heaviest — two pointers, S3-03 link), **fractional knapsack** (take items by value/weight ratio — optimal) versus **0/1 knapsack** (the same rule fails — counterexample drawn); the **greedy template**: *(1) define a sort key or priority, (2) process candidates in that order, (3) keep a candidate if it keeps the partial solution feasible, (4) never undo*; hand traces with the chosen/rejected list at each step.

## Unit 9 — Huffman coding and greedy construction

- **L3:** **proofs written in full**: (a) **Kraft's inequality** — **a binary prefix code with lengths `ℓ₁ … ℓ_n` satisfies `Σ 2^{−ℓ_i} ≤ 1`** (proof by counting leaves of the complete tree at the maximum depth) and **conversely lengths satisfying it are realizable by a prefix code** (constructive — canonical assignment; - **L4:** **engineering**: **robust codec design** (versioned container; checksums for **integrity only**, not authenticity; **explicit symbol-count/length fields**; **strict validation on decode**: code-length table must satisfy Kraft **with equality for a complete code** or be rejected; **bounded declared sizes**), **decompression-bomb and hostile-input defenses** (an input claiming a huge output length or a pathological code-length table must be rejected or capped **before** allocating; **maximum output size parameter**; tested with crafted malformed inputs **against the learner's own decoder only**), **memory/speed** (table-driven decoding with a **lookup table of `k` bits** vs bit-by-bit tree walk — **counted steps first**, time second — `[ILLUSTRATIVE]`; **streaming encode/decode** in chunks), **determinism and reproducibility** (same input ⇒ same bytes; canonical codes make the container independent of heap tie order), **testing**: **optimality oracle = enumerate all full binary trees over `n ≤ 7` leaves with all leaf-symbol assignments (Catalan × permutations, S3-06 Unit 1 link) and take the minimum weighted external path length** — **exhaustive on all small frequency vectors with entries in `{1 … 6}`**; round-trip on **all strings over a 3-letter alphabet up to length 8** and seeded random bytes; property tests (prefix-free; Kraft sum = 1 for the full tree; encoded length = `Σ f·ℓ`; canonical codes decode identically; `H ≤ L < H + 1` numerically; decoder rejects truncated/extended/corrupt headers without crashing or hanging); **mutation lab** (merging the two **largest** instead of smallest; wrong tie counter; off-by-one in canonical code increment; bit-order mix-up; padding mishandled; accepting an incomplete code table) with no surviving mutants; **regression guard** on counted heap operations; documentation of the format; coaching approach ("the two rarest symbols belong together at the bottom").
