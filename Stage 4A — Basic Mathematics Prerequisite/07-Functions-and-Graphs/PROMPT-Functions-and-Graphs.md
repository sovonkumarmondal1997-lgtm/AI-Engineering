- **L2:** **choosing a scale and a window** (the range of the data, equal vs unequal axis scales); **reading values between grid lines** (interpolation by eye and its error); **the distance and midpoint formulas** (**used, with the proofs in `../08-Geometry-and-Trigonometry/03-distance-midpoint-and-circles-in-the-plane.md`, which this module links to and does not re-derive; the midpoint formula is verified numerically here**); **symmetry of points** (reflections across the axes and the origin: `(x, y) → (x, −y)`, `(−x, y)`, `(−x, −y)`); **screen and image coordinates: the origin is at the top-left and `y` increases downward** — **the classic vertical-flip bug, shown with an exact transformation**; **mapping data coordinates to pixel coordinates** `px = (x − x_min)/(x_max − x_min) · W`, `py = H − (y − y_min)/(y_max − y_min) · H`; **ML-flavored use with stated numbers**: an image pixel `(row, column)` versus a plot `(x, y)` (a transposition trap); a scatter of two synthetic features.

## Unit 2 — What a function is, and function notation
- **L1:** **a function assigns to each input exactly one output**; **input, output, rule**; **representations**: a table, a mapping diagram, a formula, a graph, a verbal rule, **a Python function**; **function notation** `f(x)` (read "f of x"; **not** "f times x"); **evaluating** `f(3)`; **the vertical line test** (a graph is a function's graph iff no vertical line meets it twice); **functions vs relations** (`y² = x` is not a function of `x`; `|y| = x` is not); **a function in code is a *pure* mapping only if the same input always gives the same output** (a function that reads a clock or an unseeded RNG is not a mathematical function of its arguments).
- **L2:** **notation traps**: **`f(x + h) ≠ f(x) + f(h)` in general** (exact counterexample with `f(x) = x²`), **`f(2x) ≠ 2f(x)`**, **`f²(x)` can mean `(f(x))²` or `f(f(x))` — write it unambiguously**, `f(x)` vs `f` (the function vs a value); **equality of functions** (same domain and the same output at every input — **`x/x` and `1` are not the same function: M03 Unit 8 domain link**); **functions defined on finite sets** (a table is a complete definition); **counting functions between small finite sets** (`|B|^{|A|}`; M05 Unit 1 powers link); **ML-flavored functions with stated numbers**: **a model `ŷ = f(x; θ)`, a loss `L(θ)`, a preprocessing step `x ↦ (x − μ)/σ`**; **determinism and seeding** (a "random" augmentation is a function of the input *and* the seed).
- **L3:** **proofs, written in full:** (a) **the vertical line test is equivalent to the definition for relations given as sets of points** (state the relation as a set of ordered pairs and prove both directions); (b) **two functions with the same domain are equal iff they agree at every input** (the extensionality statement; a consequence for finite functions: a table decides equality); (c) **for `f(x) = kx` additivity holds, `f(x + y) = f(x) + f(y)`, and for `f(x) = x²` it fails** (so the notation trap is a property of the function, not of the notation); (d) **the number of functions from an `m`-element set to an `n`-element set is `nᵐ`** (a product of independent choices; link to `../11-Counting-and-Combinatorics/01-the-counting-principle.md`), **the number of injective ones is `n!/(n − m)!` for `m ≤ n` (stated; proved by the counting principle)**; **exhaustive verification**: **enumerate all functions `A → B` for `|A|, |B| ≤ 4` with `itertools.product` and verify the counts `nᵐ` and the injective counts** (state the domain size: at most `4⁴ = 256` functions); the vertical-line-test equivalence on all relations over a `3 × 3` pair set (`2⁹ = 512` relations).
- **L4:** **a finite-function type** `Func` (Tool card: an immutable mapping from a finite domain to values; **single-valuedness enforced at construction**; evaluation, equality, enumeration of all functions between two small sets, image and preimage; deterministic `repr`; caps on domain size); **purity checks in code are only evidence: a harness that calls a Python function repeatedly with seeded inputs can report "no violation found in `N` calls", never "pure"**; **a notation linter for a small grammar (`f(x+h)`, `f^2(x)`, `f(2x)`) listing ambiguous or commonly misapplied forms — rule-based, `HEURISTIC`, with stated false positives**; hostile inputs (a relation presented as a function; duplicate keys); **testing**: the exhaustive enumerations above; **mutation lab** (a relation accepted as a function; equality ignoring the domain; injective count off by one) with no surviving mutants.

## Unit 3 — Domain and range
- **L1:** **the domain is the set of allowed inputs; the range is the set of outputs actually produced**; **the codomain** (the declared target set) **vs the range**; **finding the natural domain of a formula** (no division by zero; no even root of a negative; no logarithm of a non-positive number — **M05 Unit 4, M06 Unit 1**); **writing domains and ranges in interval notation** (**M04 Unit 9 recall**); **domain from context** (a count is a natural number; a probability lies in `[0, 1]`); **reading domain and range from a graph**.
- **L2:** **ranges of the basic families by reasoning** (a linear function with non-zero slope: all reals; `|x|`: `[0, ∞)`; `x²`: `[0, ∞)`; a quadratic: bounded on one side at the vertex value, **M04 Unit 6**; `1/x`: all reals except `0`; `√x`: `[0, ∞)`; `eˣ`: `(0, ∞)`; `ln x`: all reals); **domains of sums, products, and quotients** (intersections of the domains, with the zeros of a denominator removed); **domain restrictions to make a function well-behaved** (restricting `x²` to `x ≥ 0`); **ML-flavored domains with stated numbers**: **the domain of a log-loss `−ln p` is `p ∈ (0, 1]`**, **the range of a sigmoid is `(0, 1)`** (**forward to Unit 14**), **valid ranges for a feature**; **domain errors in code** (`ValueError` vs `nan`; floats and `inf`).
- **L3:** **proofs, written in full:** (a) **the domain of `f + g`, `f·g` is `dom f ∩ dom g`, and of `f/g` is `dom f ∩ dom g ∩ {g ≠ 0}`**; (b) **the range of `ax² + bx + c` with `a > 0` is `[c − b²/(4a), ∞)`** (completing the square, **M04 Unit 6**), **and `(−∞, c − b²/(4a)]` for `a < 0`**; (c) **the range of `1/x` is `ℝ ∖ {0}`** (every non-zero `y` equals `1/(1/y)`); (d) **the range of a strictly increasing function on an interval is determined by its endpoint behavior** (stated with the endpoint cases; the existence of intermediate values is `CITED [VERIFY]` — intermediate value theorem, deferred to `../13-Limits-and-Rates-of-Change-Bridge/04-limit-laws-and-continuity-intuition.md`); **exhaustive verification**: for a stated family of rational functions with denominators of degree ≤ 2 (integer coefficients in `[−3, 3]`), **the exact excluded set (computed with `QuadSurd`/`Fraction` roots, M04) vs a brute-force evaluation over a rational grid that records which grid points raise `ZeroDivisionError`** (the grid sees only rational exclusions; the algebra supplies irrational ones — **state the blind spot**).
- **L4:** **a domain tool** `domain` (Tool card: strict parser for a small grammar of `+ − * / ^` with integer powers, `sqrt(...)`, `ln(...)`, and `abs(...)` over one variable; **natural domain as an exact `IntervalSet`** for constraint polynomials of degree ≤ 2 (exact `QuadSurd` roots), refusing higher degrees with a clear message; **range computed only for stated families (linear, quadratic, `|x|`, `1/x`, `√x`, `eˣ`, `ln x`, and their simple shifts/scales) with the three-status labels**, otherwise "range not established"; a grid cross-check labelled `EVIDENCE ONLY`); hostile inputs (nested roots/logs, huge degrees); **testing**: exact excluded sets vs the grid oracle; **mutation lab** (strict vs non-strict inequality for a square root; a zero of the denominator kept; a logarithm's argument allowed to be zero) with no surviving mutants.

## Unit 4 — Variables, parameters, and independent versus dependent
- **L1:** **independent and dependent variables** (the input and the output; which is which depends on the question); **parameters** (quantities held fixed within a problem that shape the function: `m` and `b` in `y = mx + b`); **constants**; **a family of functions** (changing a parameter changes the member); **tables and graphs of a family** (several values of one parameter, M03 Unit 1 recall); Python: default arguments and keyword parameters.
- **L2:** **the same symbol in two roles**: in `ŷ = wx + b`, **for prediction `x` varies and `(w, b)` are fixed; for training `(w, b)` vary and the data are fixed** — **the role reversal, shown with an exact loss as a function of one parameter**; **hyperparameters** (named: fixed choices that are not learned; **no claim about how they are tuned**); **units of parameters** (`w` has units of output per input — M01 Unit 8, M02 Unit 6); **partial application**: **freezing parameters in code with a closure or `functools.partial`**, and **the late-binding closure trap (`lambda` in a loop capturing the loop variable) demonstrated and fixed**; **sweeping a parameter** (a table of outputs for a grid of parameter values, exact with `Fraction`); **sensitivity**: how much the output changes when one parameter changes by a stated amount (exact algebra for linear and quadratic families).
- **L3:** **proofs and derivations, written in full:** (a) **a function of two arguments `f(a, x)` gives, for each fixed `a`, a one-argument function `f_a(x)`, and for each fixed `x`, a function `f^x(a)`** (the two "slices"); (b) **linearity in parameters vs in the input**: **`f(x; w, b) = wx + b` is linear in `x` for fixed `(w, b)` and linear in `(w, b)` for fixed `x`; `f(x; a, c) = a·e^{cx}` is linear in `a` but not in `c`; taking logarithms makes it linear in `(ln a, c)` for `a > 0, f > 0` (M06 Unit 7 recall)**; (c) **the closure/`partial` equivalence: freezing a parameter by closure, by `partial`, and by a default argument give the same function at every input — except for the late-binding case, whose failure is explained precisely**; **exhaustive verification**: slices commute (`f_a(x) = f^x(a) = f(a, x)`) on a stated grid; the late-binding bug reproduced and the three correct constructions agree over a stated loop range.
- **L4:** **a family tool** `Family` (Tool card: a parametric function from a fixed registry of named forms (`linear`, `quadratic`, `exponential`, `sigmoid-affine`), its parameter names and units, exact evaluation with `Fraction` where rational, parameter sweeps, partial application (a new `Family` with fewer free parameters), and a **late-binding self-check**; stable errors); **role-reversal helper**: given data and a model form, produce the loss as a function of the parameters (for finite synthetic data, exact); hostile inputs (unknown parameter names; duplicate parameters); **testing**: slice-commutation oracle; **mutation lab** (late binding; parameter order swapped; the wrong parameter frozen) with no surviving mutants.

## Unit 5 — Evaluating and piecewise functions
- **L1:** **evaluating a function at a value** (substitute carefully, brackets around negatives — **M03 Unit 6 recall**); **evaluating at an expression** (`f(a + 1)`); **piecewise functions** (different rules on different parts of the domain; the **conditions** decide the rule); **the absolute-value function as a piecewise function** (**M04 Unit 10 recall**); **step functions and floor/ceiling** (M01 Unit 4 link); **boundary points** (which piece owns the boundary?); Python `if/elif/else`.
- **L2:** **sketching piecewise functions** (graph each piece on its own interval, mark closed/open endpoints at the boundaries); **evaluating at the boundary**; **`max` and `min` as piecewise functions** (`max(a, b)`, `min(a, b)`); **`clip(x, lo, hi)`**; **ReLU `max(0, x)` as a piecewise function** (**forward to Unit 14**); **the sign function**; **synthetic tiered-rate functions** (an original tax-bracket-style cost function with stated tiers — **not a real schedule**); **continuity at a boundary as a question about values on both sides** (**intuition only; formal treatment in `../13-Limits-and-Rates-of-Change-Bridge/04-limit-laws-and-continuity-intuition.md`**); **vectorized evaluation awareness** (`numpy.where` — optional, never required).
- **L3:** **proofs, written in full:** (a) **a piecewise definition is a well-defined function iff the conditions' sets are pairwise disjoint and their union is the intended domain**; (b) **`max(a, b) = (a + b + |a − b|)/2` and `min(a, b) = (a + b − |a − b|)/2`**; (c) **`ReLU(x) = (x + |x|)/2`** (from (b) with `b = 0`); (d) **`clip(x, lo, hi) = min(max(x, lo), hi)` for `lo ≤ hi`, and the result lies in `[lo, hi]`**; (e) **`|x|` as a piecewise function equals `√(x²)`** (M05 Unit 4 link); **exhaustive verification**: for all integer `a, b ∈ [−10, 10]` the `max`/`min` identities exactly; for all integer `x ∈ [−12, 12]` and `lo ≤ hi ∈ [−6, 6]` the clip identity and range claim; **partition checks of random piecewise definitions over a rational grid including boundaries**.
- **L4:** **boundary-inclusion bugs** (`<` vs `≤`; overlapping or uncovered pieces; a boundary that belongs to two pieces — **detected exactly with `IntervalSet`s**); **a piecewise tool** `Piecewise` (Tool card: pieces as `(IntervalSet, expression)` with exact evaluation over `Fraction`s; **a partition check (disjoint, covering the declared domain)**; boundary report; comparison with a branchy Python implementation over an exhaustive grid; stable errors); hostile inputs (overlap, gaps, empty pieces, infinite pieces); **testing**: partition oracles; **mutation lab** (boundary assigned to both pieces; a gap left uncovered; `max` implemented with the wrong sign of `|a − b|`) with no surviving mutants.

## Unit 6 — Linear functions: slope, intercepts, and line equations
- **L1:** **a linear function `f(x) = mx + b`**; **slope `m` as rise over run** `(y₂ − y₁)/(x₂ − x₁)` for `x₁ ≠ x₂`; **the `y`-intercept `b` and the `x`-intercept `−b/m` (for `m ≠ 0`)**; **graphing from the slope and intercept**; **positive, negative, zero, and undefined slope** (**vertical lines are not functions**); **linear vs proportional** (`b = 0`; **M02 Unit 7 recall**); **rate of change constant** (**M02 Units 6–7**); Python linear functions with `Fraction`.
- **L2:** **the equation of a line through two points** (compute `m`, then `b`; **M04 Unit 11 recall**), **point-slope form** `y − y₁ = m(x − x₁)`, **slope-intercept form**, **standard form** `Ax + By = C`, and **conversions among them** (exactly); **parallel lines (equal slopes) and perpendicular lines (`m₁m₂ = −1`)**; **lines from a table or a story** (a fixed fee plus a rate; M04 Unit 4); **the meaning of slope with units** (output units per input unit); **ML-flavored use with stated numbers**: **the linear model `ŷ = wx + b`, its slope as "change in prediction per unit change in the feature", residuals `y − ŷ`**, **fitting a line exactly through two data points** (**the best-fit line for many points is Stage 4B-14, not taught here**); **linear change vs percent change** (M02 Unit 8, M05 Unit 6).
- **L3:** **proofs, written in full:** (a) **slope is well defined: for any two distinct points on the graph of `y = mx + b`, `(y₂ − y₁)/(x₂ − x₁) = m`**; (b) **uniqueness of the line through two points with distinct `x` values** (M04 Unit 11 (d) recalled and extended to all three forms); (c) **conversion formulas among the three forms and their validity conditions** (`B ≠ 0` for slope-intercept; vertical lines have no slope-intercept form); (d) **parallel lines have equal slopes and no common point unless equal; perpendicular lines satisfy `m₁m₂ = −1`** (the perpendicularity criterion uses the converse of the Pythagorean theorem, **`CITED [VERIFY]` from `../08-Geometry-and-Trigonometry/02-triangles-and-the-pythagorean-theorem.md`, or equivalently a zero dot product of direction vectors, `../09-Vectors-as-Arrows-and-Data-Points/04-direction-angle-and-perpendicularity-intuition.md`**); (e) **the composition of two linear functions is linear: `(m₁, b₁) ∘ (m₂, b₂) = (m₁m₂, m₁b₂ + b₁)`** (previewing Unit 11); **exhaustive verification**: the two-point line solver vs membership of both points for all integer point pairs in `[−4, 4]²` with distinct `x`; form conversions round-trip exactly; parallel/perpendicular classification vs a brute-force direction-vector computation over a stated grid.
- **L4:** **vertical and horizontal edge cases**; **float slopes from measured data** (an exact `Fraction` slope vs a float one; near-vertical lines amplify error — **named, conditioning deferred to Stage 4B**); **a line tool** `line` (Tool card: line through two points or from a point and slope; all three forms; intercepts; parallel/perpendicular tests; exact `Fraction` arithmetic; vertical-line handling; stable errors); hostile inputs (identical points; non-numeric input); **testing**: membership and round-trip oracles; **mutation lab** (rise and run swapped; the intercept computed from the wrong point; `m₁m₂ = +1` used for perpendicular) with no surviving mutants.

## Unit 7 — Intersection of lines and the geometry of linear systems

## Unit 8 — Quadratic functions and parabolas
- **L1:** **`f(x) = ax² + bx + c`, `a ≠ 0`**; **the parabola** (U-shaped); **opening up for `a > 0`, down for `a < 0`**; **the `y`-intercept `c`**; **the `x`-intercepts** (**factoring, completing the square, the quadratic formula — M04 Units 5–7 recall**); **the vertex and the axis of symmetry**; **the minimum or maximum value**; **graphing by plotting points** and **by vertex form** `a(x − h)² + k`.
