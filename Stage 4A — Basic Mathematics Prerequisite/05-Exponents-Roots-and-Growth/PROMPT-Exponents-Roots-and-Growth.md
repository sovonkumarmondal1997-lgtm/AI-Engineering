- **L3:** **proofs, written in full:** (a) **uniqueness of the non-negative `n`-th root**: if `b, c ≥ 0` and `bⁿ = cⁿ` then `b = c` (from the Unit 1 monotonicity); **existence is assumed from the completeness of ℝ and flagged as `CITED [VERIFY]` (deferred to analysis)**; (b) **`√(x²) = |x|`**; (c) **`√a · √b = √(ab)` for `a, b ≥ 0`** (square both sides and use uniqueness) **and the failure for negatives is explained by the domain (real roots do not exist) rather than by a "rule"**; (d) **`a^{m/n}` is well-defined**: it depends only on the rational number `m/n`, not on the chosen representation (use uniqueness of roots); (e) **the exponent laws hold for rational exponents and positive bases** (common-denominator argument); (f) **AM–GM for two numbers**: `√(ab) ≤ (a + b)/2` for `a, b ≥ 0`, with equality iff `a = b` (from `(√a − √b)² ≥ 0`), **and `GM² = AM · HM` for two positive numbers (M02 Unit 6's `2ab/(a + b)`)**, giving `HM ≤ GM ≤ AM`; (g) **`√n` is irrational unless `n` is a perfect square** (M01 Unit 1 link); **exhaustive verification**: an exact integer `k`-th root routine (**largest `r` with `rᵏ ≤ a`, by binary search — S3-03 link**) vs brute force for all `a ≤ 10⁵`, `k ∈ {2, 3, 4, 5}`; `r**k <= a < (r+1)**k` checked for every case; radical simplification vs prime-factorization oracle; AM–GM and HM ≤ GM over a stated grid (**evidence**; the proofs are the proofs).

## Unit 6 — Compound growth and decay: linear versus exponential
- **L1:** **linear change adds the same amount each period** (`y = y₀ + d·t`); **exponential change multiplies by the same factor each period** (`y = y₀ · rᵗ`); **a percent rate becomes a factor** (`+p%` → `r = 1 + p/100`; `−p%` → `r = 1 − p/100` — **M02 Unit 8 recall**); **growth (`r > 1`) and decay (`0 < r < 1`)**; **tables of both types** and how they differ; **doubling and halving**; Python simulations with `Fraction` and floats.
- **L2:** **compound interest as a formula** `A = P(1 + r/m)^{mt}` (a *formula*, with every rate an assumption — **no claim about real rates**); **repeated percent change** (M02 recall: `+x%` then `−x%` is not zero); **finding the first period at which a threshold is crossed**, by **search** (exact integers/`Fraction`s) — **solving `rᵗ = c` for `t` needs logarithms, deferred to `../06-Logarithms/05-solving-exponential-equations.md`**; **doubling time and half-life** by search; **ML-flavored schedules with stated numbers**: exponential learning-rate decay `ηₜ = η₀ · γᵗ` (with `t` counting epochs vs steps made explicit — **a unit-of-time error is the classic bug**); **geometric growth of a dataset**; **linear vs exponential cost models and where they cross** (M04 Unit 4 setups); **recognizing the type from a table** (constant differences → linear; constant ratios → exponential).
- **L3:** **proofs, written in full:** (a) **characterization**: a sequence is arithmetic iff consecutive differences are constant; geometric iff consecutive ratios are constant (non-zero terms) — and **an algorithm that classifies a finite table as linear / exponential / both (a constant sequence) / neither, with proof of correctness**; (b) **Bernoulli (Unit 1) gives `rᵗ ≥ 1 + (r − 1)t` for `r > 0` and natural `t`, hence an exponential with factor `r > 1` is never below the linear function with the same start and the same first-period increase**; (c) **in the strict case `r > 1` and `t ≥ 2` it is strictly above**; (d) **an exponential with `r > 1` eventually exceeds *any* given linear function** (for stated `y₀ > 0`, `d`; derive an explicit threshold from Bernoulli); (e) **repeated percent changes compose multiplicatively** (M02 recall) **and `(1 + x)(1 − x) = 1 − x² < 1`**; (f) **for a decay factor `0 < r < 1`, `rᵗ` drops below any given positive bound after finitely many periods** (derive an explicit period count from Bernoulli applied to `1/r`); **exhaustive verification**: the classifier vs a brute-force definition over **all integer sequences of length 4 with entries in `[0, 6]`** (`7⁴ = 2401` — state the domain); the Bernoulli-based inequality over a stated exact grid; threshold-crossing search vs the closed-form bound.
