# Module 0.2 — Operating System Fundamentals

## Lesson 01: Kernel and User Space

**Main objective:** Understand how an operating system manages computer hardware, how applications interact with it, and why this knowledge matters for Data Engineering and AI Engineering.

The lesson covers the following concepts.

---

## 1. Understanding the four fundamental terms

- **Operating System (OS):** Software that manages computer hardware and allows applications to run. Examples: Linux, Windows and macOS.
- **Kernel:** The most important, privileged component of an operating system. It manages CPU, memory, storage, network and hardware resources.
- **User Space:** The environment where ordinary applications execute, such as Python scripts, browsers, editors and AI services.
- **Kernel Space:** The privileged execution environment where the kernel and trusted kernel-level components operate.

**Remember:** The kernel is part of the operating system, not the entire operating system.

---

## 2. Why do we need a kernel?

Imagine multiple applications sharing one computer. Without restrictions, one application could damage another application's memory, access unauthorized files, monopolize the CPU or interfere with hardware.

The kernel prevents these problems through five responsibilities:

1. **Safety:** Prevents individual application failures from damaging the entire system.
2. **Isolation:** Keeps applications' memory and resources separated.
3. **Resource Management:** Allocates CPU, memory, storage and network resources.
4. **Controlled Access:** Controls access to sensitive hardware and operations.
5. **Reliability:** Allows multiple applications to operate safely together.

---

## 3. Why AI and Data Engineers need this knowledge

Your Python applications are user-space programs. Whether you develop a data pipeline, FastAPI service, ML training script or AI inference service, they depend on the kernel.

For example:

- Reading datasets requires filesystem access.
- Saving model files requires storage access.
- Processing large datasets requires memory and CPU.
- Receiving API requests requires networking.
- Running multiple workers requires process and CPU management.
- Production resource limits are enforced at the operating-system level.

---

## 4. CPU privilege and system-call interface

Modern CPUs support different privilege levels.

- **User Mode:** Restricted execution mode for ordinary applications.
- **Kernel Mode:** Privileged execution mode for the kernel.

The CPU hardware enforces this separation.

Applications cannot directly jump into kernel code. Instead, they use the **System-Call Interface**, which provides controlled entry points for requesting kernel services.

---

## 5. How does it work internally?

When a Python application needs an operating-system resource:

1. Python application executes in user space.
2. It requests something OS-managed, such as reading a file.
3. Python's runtime or library issues the appropriate system call.
4. The CPU transfers execution into kernel mode through a controlled mechanism called a **trap**.
5. The kernel performs the requested operation.
6. The kernel prepares the result.
7. Execution returns to user mode.
8. The Python application continues running.

**Important:** Basic arithmetic, string manipulation and operations on data already in memory do not necessarily involve the kernel.

---

## 6. Six real-world examples

The lesson explains kernel involvement in:

1. **Reading files** — retrieving datasets from storage.
2. **Writing files** — saving models and application logs.
3. **Creating processes** — launching data-processing workers.
4. **Memory allocation** — obtaining memory for arrays and tensors.
5. **Network communication** — sending and receiving API requests.
6. **Input/output** — reading terminal input and printing output.

## 7. Practical Linux commands

The lesson uses Ubuntu inside WSL2 to observe the Linux environment.

| Command | Purpose |
|---|---|
| `uname -a` | Displays kernel and system information |
| `whoami` | Displays current username |
| `id` | Displays user and group IDs |
| `ps` | Lists running processes |
| `cat /proc/version` | Displays kernel version information |
| `cat /proc/sys/kernel/ostype` | Displays OS type |
| `cat /proc/sys/kernel/osrelease` | Displays kernel release |
| `command -v ps` | Checks whether a command is available |

`/proc` is particularly important: it is a virtual filesystem whose information is generated by the kernel, not stored as ordinary files on disk.

---

## 8. Common misconceptions

The lesson corrects these misunderstandings:

- Kernel and operating system are not the same.
- User space does not mean the graphical user interface.
- Kernel space is not where users type commands.
- Applications cannot directly control hardware.
- Python does not require kernel involvement for every operation.
- Kernel and CPU are different.
- Kernel and shell are different.
- Kernel and process are different.
- The kernel manages much more than files.

---

## 9. Debugging and troubleshooting

Four practical scenarios are explained:

- **Permission error:** The kernel may reject file access because of permissions.
- **Program hanging:** The application might be waiting for network data or user input rather than executing an infinite loop.
- **AI service slowing down:** CPU contention or memory pressure may be responsible.
- **Unexpected termination:** The kernel may have refused a request or stopped a process because of resource constraints.

## The most important concept to remember

The kernel does not execute your AI model like PyTorch does. It manages the underlying CPU, memory, storage, networking and process resources that your Python application and AI frameworks need to operate.

**Your key learning outcome:** When a Python data pipeline or AI service fails, becomes slow or behaves unexpectedly, learn to distinguish between an application-level problem and an operating-system resource or permission problem.
