# Concept 10 — Signals

**Module:** Operating System Fundamentals
**Stage:** 0 — Module 0.2

**Main idea:** Signals allow the operating system or another authorized process to notify a running process about an event or request an action, such as stopping, pausing, or continuing.

---

## 1. What Are Signals?

A **signal** is a short, standardized notification delivered by the operating system to a process.

For example, when you press Ctrl+C, the terminal normally sends `SIGINT` to the foreground process group.

Signals are different from ordinary data:

- **Signals:** Control and event notifications.
- **stdin, stdout, stderr and pipes:** Channels for transferring data.

Signals prevent processes from constantly checking whether someone wants them to stop.

---

## 2. Why AI Engineers Need Signals

Signals are important for:

- Stopping Python services correctly.
- Managing background workers and batch jobs.
- Restarting services during deployments.
- Finishing active inference requests before shutdown.
- Closing database connections and files.
- Releasing resources safely.

---

## 3. Six Important Signals

| Signal | Meaning |
|---|---|
| `SIGINT` | Interrupt; commonly generated by Ctrl+C. |
| `SIGTERM` | Requests a process to terminate, allowing cleanup if implemented. |
| `SIGKILL` | Immediately terminates a process; cannot be caught or ignored. |
| `SIGHUP` | Traditionally indicates terminal disconnection; applications may reuse it for configuration reloads. |
| `SIGSTOP` | Pauses a process unconditionally; cannot be caught or ignored. |
| `SIGCONT` | Resumes a stopped process. |

Every signal has a default action. `SIGTERM`, `SIGINT`, and `SIGHUP` normally terminate; `SIGSTOP` pauses; `SIGCONT` resumes.

Signal names are preferable to numbers because numeric identifiers can vary across systems.

---

## 4. The `kill` Command

Despite its name, `kill` sends signals; it does not always terminate processes.

```bash
kill PID             # Sends SIGTERM by default
kill -TERM PID       # Requests termination
kill -INT PID        # Sends interrupt
kill -KILL PID       # Forces termination
kill -STOP PID       # Pauses
kill -CONT PID       # Resumes
kill -l              # Lists available signals
```

Always verify a PID with `ps` before sending a signal. Only experiment on processes you created yourself.

---

## 5. How Signals Work Internally

1. A signal is generated by a terminal, command, or OS event.
2. The OS identifies the target process.
3. The signal becomes pending or is delivered.
4. The process receives it.
5. The OS applies the default action or the application's registered handler.
6. The process continues, pauses, or terminates.

The OS also checks whether the sender has permission to signal the target process.

---

## 6. Python Signal Handlers and Graceful Shutdown

Python provides the `signal` module:

```python
import signal
import sys

def handler(signum, frame):
    print("Signal received")
    sys.exit(0)

signal.signal(signal.SIGTERM, handler)
```

The handler defines what the application does when it receives `SIGTERM`. Python handlers execute in the main thread of the main interpreter.

**Important:** `SIGKILL` and `SIGSTOP` cannot be handled by Python or any other application.

- **Abrupt termination:** The process stops without application-level cleanup.
- **Graceful shutdown:** The application handles a termination request, stops accepting new work, finishes or cancels active work, releases resources, closes connections, and exits.

Sending `SIGTERM` does not automatically guarantee graceful shutdown. Developers must implement the cleanup logic.

---

## 7. Production AI Example

When redeploying a model-serving service:

`SIGTERM` → stop accepting new requests → finish or safely cancel in-flight inference → close database connections and files → exit.

Use `SIGTERM` first. If the process genuinely fails to stop within a reasonable time, `SIGKILL` may be used as a last resort. Forced termination can leave incomplete work.
